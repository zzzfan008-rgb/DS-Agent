## 4. 退出码

| 码 | 含义 | 出现场景 |
|---|---|---|
| `0` | 成功 | 所有步骤 success（DryRun 恒 0） |
| `2` | 部分成功 | backup 有失败步骤但仍有成功步骤（如缺 `mc`） |
| `3` | 全部失败 | backup 所有目标步骤失败 |
| `1` | 拒绝或失败 | restore/drill 未确认、文件不存在、恢复/校验失败 |

## 5. 安全边界（已实现）

1. **不读取/打印密钥**：凭据分支只打印 age 占位命令；DSH 仅按文件名 `find` 计数并用 `tar --exclude` 排除，`excluded` 只报数量；报告/校验和只含路径、字节、sha256。
2. **DryRun 只读**：不写文件、不建卷、不改 `archive_command`、不删除任何内容。
3. **删除/覆盖默认拒绝**：restore 需 `-Force`；drill 需 `-Force`；backup 保留期清理需 `-Prune -Force`。无确认时直接退出 1 并提示。
4. **生产目标保护**：`PgDatabase=dssaas/postgres` 需 `-AllowProductionTarget`；默认目标是 `dssaas_restore`。
5. **演练口令**：drill 的临时口令在内存随机生成，不落盘、不进报告（DryRun 打印为 `<ephemeral>`）。
6. **卷边界**：Postgres 只经 `pg_dump` 读；DSH 以只读卷挂到一次性容器；不直接读 `pg-data` 宿主路径（docs/20 §3.1）。

## 8. 已知缺口（需 M9/生产侧补齐）

1. **MinIO 实链路未真跑**：本机未安装 `mc`；真实执行会标记 `failed` 并退出码 2。生产在备份容器内执行（`mc alias set` + 桶 versioning + `mc admin config export`），脚本已留参数与命令。
2. **WAL/PITR**：脚本只检查 `archive_mode` / `last_archived_time`（本次 dev 容器 `archive_mode=off`），不改 `postgresql.conf`；`pg_basebackup` + `archive_command` + 恢复演练属于生产配置与 M9 范围（docs/20 §5/§6.2）。
3. **凭据加密导出**：仅接口占位（age/KEK 未实现），默认不导出；docs/20 §4.3 的密钥管理不在脚本内。
4. **调度与异地**：cron/系统计划、异地转存、`audit_log(ops.backup)` 写入、失败告警未实现（docs/16 §7.3/§7.5）。
5. **DSH manifest/原子恢复**：当前 tar + SHA256SUMS；docs/20 §9 要求的 manifest/版本化/试恢复待 M9；restore 直接解包到 `/dsh`（有 sha256 校验与 `-Force` 保护），未做「解到临时目录再原子切换」。
6. **卷改名迁移**：compose 由 `pgdata/miniodata` 改为 `pg-data/minio-data`；本机未创建过旧卷，生产升级需先迁移数据（本任务未删除任何卷）。
7. **`-Target all` 的 restore**：要求同一类备份产物；实际按 target 分别执行（示例已分别给出 pg / dsh）。
