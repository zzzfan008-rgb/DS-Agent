## 0. 结论先行

1. **页面已可用**：新建、编辑、测试连接、归档四个动作全部走真实接口；凭据只存引用名，界面不回显、不保存密钥。
2. **测试连接诚实失败**：点「测试连接」→ `POST /api/platform-accounts/:id/test` → HTTP 200 + `ok:false` + `reason:"interfaces_unverified"`，界面渲染**黄色 ⚠ 警示条**（"无法发起真实请求：平台接口 method 尚未核验……这不是凭据错误，也不代表连通成功"），卡片连通性圆点**保持灰色"未测试"**，不做乐观更新。截图 `platforms-05-test-interfaces-unverified.png`。
3. **最近错误长期可见**：后端把 `last_test_error / last_tested_at / connectivity=unknown` 写回库；界面在卡内显示"最近错误（库里保留）· 上次测试 MM-DD HH:mm"，刷新后仍在（截图 05 / 08）。
4. **409 走真实冲突**：有人（此处用直连接口模拟"他人修改"）把 version 1→3 后，页面上仍持 v1 的抽屉点保存 → 409 → 红条"数据已被他人修改，请刷新" + 底部按钮变 `[刷新并关闭]`，**抽屉不关闭、用户输入保留**。截图 `platforms-06-edit-conflict-409.png`。
5. **不编造数据**：公告摘要 / 未自动化接口清单 / 同步状态三块后端无端点，一律渲染"数据源尚未接入"空态并写明计划字段；**没有**写"暂无公告"，**没有**假造 lag_seconds。
6. **权限**：写操作按 `provider.write` 门控（注释见 `page.tsx`），无权限时按钮不渲染；viewer 路径未能在浏览器实测（库里没有 viewer 账号，建号属权限变更，未越权），以代码审读 + 视觉稿 §5 交付。

### 4.1 交互流水（真实操作）

```text
1) 登录 admin@dssaas.local → 首页 → 点击侧栏「平台连接」
2) 初始态：已接入 4（t54 测试遗留）→ 截图 01
3) 为得到干净空态：对 4 条遗留账号调用 POST /archive（带 Idempotency-Key）→ 列表 items=[]
   刷新页面 → 截图 02（空态）
4) 点「新建平台账号」→ 填 shop_id=700123456 / shop_name=拼多多旗舰店 A /
   app_key=5f8c…8a45 / app_secret_ref=PDD_APP_SECRET / access_token_ref=PDD_ACCESS_TOKEN
   → 展开「我该填什么？看示例」→ 截图 03
5) 把 access_token_ref 改成 `FAKESECRETFORTESTONLYDONOTUSE0123456789` → 红字拦截 → 截图 03b
   （确认：此时无任何网络请求）
   > 注：此处刻意不用 `sk_live_` 前缀、也不用 32 位十六进制——GitHub secret scanning
   > 会把这类测试夹具误判为泄露密钥并拒绝推送（GH013）。同样满足「≥24 位连续长串」判定。
6) 改回 PDD_ACCESS_TOKEN → 点「创建账号」→ HTTP 201 → 卡片出现 + toast → 截图 04
7) 点「测试连接」→ HTTP 200 {ok:false, connectivity:"unknown", reason:"interfaces_unverified",
   message:"55 个平台接口尚未核验 method，无法发起真实请求", tested_at:…}
   → 黄色结果条（不绿、不带 ✓）→ 截图 05
8) 模拟"他人修改"：直连 API PATCH 该账号（If-Match 1 → 409 expected 1/actual 2；
   再 If-Match 2 → 200 version=3），页面仍持 version=1
9) 页面点「编辑」→ 改店铺名 → 点「保存」→ HTTP 409 → 红条"数据已被他人修改，请刷新"
   → 按钮变 [刷新并关闭] → 截图 06
10) 点「刷新并关闭」→ 列表刷新（版本显示 v3）→ 重新「编辑」→ 保存 → HTTP 200 version=4
    → 截图 08
```

## 5. 偏差与遗留

| # | 偏差 | 说明 / 处理 |
|---|---|---|
| D1 | **当前运行的 API 进程（:3010）是 t55 开工前的旧构建**，不含 t54 的 `/api/platform-accounts`（旧进程返回 404 not_found） | 未重启队长在用的 API 进程（重启属运维动作，且在 t54 验收流程中）。为完成本轮真实截图，**另起临时实例 `API_PORT=3011` + 独立 `next dev -p 3000`（`API_INTERNAL_URL=http://127.0.0.1:3011`）**；结束后已停止临时进程。**队长按计划重启 API 后，:3010 即具备该端点**，无需改本页 |
| D2 | 本地 `.env` 中 `API_PORT=3010`，而 `next.config.ts` 的 `API_INTERNAL_URL` 默认是 `:3001` | 若 `next dev` 未显式带 `API_INTERNAL_URL`，同源 `/api/*` 会打到 3001（非本项目 API）→ 页面报"接口不存在"。建议启动脚本统一从 `.env` 读 `API_PORT`（未在本任务修改配置，仅登记） |
| D3 | **viewer 只读路径未在浏览器实测** | 数据库只有 admin 账号；新建 viewer 属权限/身份变更（纪律②），未自行执行。已交付：`canWrite=false` 分支代码（按钮不渲染 + 只读说明）与 `guardPage` 门控；建议 QA 用测试库自建 viewer 账号复测 |
| D4 | 测试连通目前只有一种真实结果 | 后端 `interfacesVerified=false` 固定返回 `interfaces_unverified`；`ok / auth_invalid / unreachable` 三态的视觉已在 `describeTestResult` 中实现，待 t54-D1 探针落地后自然出现，UI 不用改 |
| D5 | 部署约束依赖 `extra` 的约定键 | 缺键显示"公网直连（默认假设）· IP 白名单 未核验 · 机房 未核验"，并标注"（默认假设，docs/03 未回填）"；`extra` 无 schema（docs/13c G7） |
| D6 | edge-proxy 状态未展示 | `platform_account` 无该字段（docs/13c G4）；不造数据，不渲染该行 |
| D7 | 截图过程中曾把一条 `shop_name` 写成乱码 | 原因：我用 `curl -d` 直连 API 造冲突时中文被 shell 转码（非界面缺陷，界面写入中文正常）。已通过界面重新保存修正（`platforms-08` 可见正确中文） |
| D8 | 「刷新并关闭」依赖整页刷新才能看到他人修改后的值 | 抽屉已触发列表刷新，但页面自身 RSC 数据未重取；用户点「刷新并关闭」后若店铺名仍为旧值，属浏览器缓存的旧 RSC。**建议后续把「刷新并关闭」改成 `location.reload()`**（本轮未改，登记为 UI 优化项） |
