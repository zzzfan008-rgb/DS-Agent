## 3. 用法与退出码

```bash
# 采集 + 快照 + delta（默认 pdd + 1688；1688 打印 TODO 跳过）
pnpm notices:watch -- --platform pdd

# 用 fixture 演练（--merge 保留已有快照，不删除旧条目）
pnpm notices:watch -- --platform pdd --merge --fixture data/notices/pdd.fixture.fake2.json

# 生成工单（默认读取 data/notices/<platform>.delta.json）
pnpm notices:ticket

# 按工单跑回归
pnpm adapter:regression -- --ticket "docs/变更工单/<ticket>.md"

# 扫描所有 open/blocked 工单（默认跳过 synthetic 演练工单）
pnpm adapter:regression
```

| 退出码 | 含义 | 触发 |
|---|---|---|
| 0 | 成功 | baseline、0 新增、1688 跳过、工单全部重复跳过、回归通过 |
| 2 | 网络/HTTP 失败 | 重试 2 次后仍失败（`--retries` 可调）；open-change-ticket 无 delta 也返回 2 |
| 3 | 解析器需更新 | 响应非 JSON、`success!=true`、缺 `result.announcementList`、`totalCount>0` 但列表为空、公告必要字段缺失 |
| 1 | 参数/IO/工单结构错误 | 非法参数、写盘失败、回归命令缺失 |

关键防静默规则：
- 解析失败 **不写快照、不生成空列表**，退出码 3 并打印「解析器需更新」；
- `totalCount>0` 但解析为 0 → exit 3；
- 同一条公告按 `link_hash = sha256(link)` 去重；工单幂等也按同一 `link_hash`；
- 同一天多条公告在 `delta.new_by_date` 聚合，控制台按日期分组打印。

## 6. 限制与风险

| # | 限制 | 说明 / 缓解 |
|---|---|---|
| 1 | 1688 公告需登录 | 未取得公开入口；脚本显式 TODO 跳过，不伪造数据。获得账号后补 `watch1688`，映射与回归已就绪。 |
| 2 | PDD 公告 API 非「官方文档化公开契约」 | 端点与请求参数来自页面公开 JS（SPA 与接口同源），不是开发者文档；平台改版会触发 exit 3。入口 URL 可用 `--list-url` 切换。 |
| 3 | 页面/响应结构变化 | JSON 结构/必要字段缺失 → exit 3 并提示更新解析器；不写空快照。HTML 选择器方案同样以 exit 3 处理。 |
| 4 | 时间无时区 | `publishedAt` 无 offset，按 `+08:00` 解释；若平台改为 UTC 或带 offset，需在 `toShanghaiIso` 更新并补 fixture。 |
| 5 | 内容不落正文 | 只存 `content_sha256`；若需公告正文 diff，应在合规评审后单独存储/脱敏。 |
