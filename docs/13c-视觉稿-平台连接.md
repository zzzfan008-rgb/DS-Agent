## 0. 结论先行

1. **本页从 PlaceholderPage 变成"可配置但不可撒谎"的页面**：用户能新建/编辑平台账号（只填引用名）、点"测试连接"、归档；但**测试连接永远显示失败态**，因为 55 个平台接口 method 未核验，后端固定返回 `ok:false / interfaces_unverified`。前端**不会**把它渲染成成功、也不会用"测试中…"糊弄过去。
2. **页面结构五段**（自上而下）：① 顶部状态条 → ② 两张平台卡（拼多多 / 1688）→ ③ 公告摘要 → ④ 未自动化接口清单 → ⑤ 同步状态。前两段接真实接口；后三段**当前无数据源**，一律渲染"数据源未接入"空态并标注里程碑，**不放假公告、不假造接口清单、不假造 lag_seconds**。
3. **凭据字段只有一个形状**：输入框里填的是**引用名**（环境变量名 / Vault 路径），不是密钥本身。输入框下方常驻说明文案；前端在失焦时做与后端 `assertCredentialRef` 同口径的预校验（≥24 位连续长串 → 本地红字，不发请求），服务端 400 的 `detail.hint` 原样回显。
4. **写操作只有 admin 可见**：以 `GET /me.permissions[]` 判断（新增 `platform.write` 权限键，或复用 admin 角色键，见 Q2），**无权限时按钮不渲染**（不是 disabled）；viewer 看到的是只读卡片。
5. **冲突处理统一**：PATCH 带 `If-Match: <version>`，409 时抽屉**不关闭**、顶部红条"数据已被他人修改，请刷新"，附"刷新并关闭"按钮；不做"自动合并"。
6. **视觉完全复刻 models 页 Provider 区**：`PanelCard` + 抽屉（560px）+ `Field`（label/hint/error 三段）+ `InlineAlert` + `Chip` + `Spinner` + `EmptyState`/`ErrorState`/`Skeleton`，不引入新技术栈。

### 3.2 字段 → 展示映射（以 `GET /api/platform-accounts` 实际响应对齐）

| 字段 | 来源 | 展示 | 缺失 / 空值 |
|---|---|---|---|
| 卡片标题 | `shop_name` → `shop_id` → `"未命名账号"` | 主标题，1 行省略 | `shop_name` null 时回落 `shop_id` |
| 授权状态徽标 | `status` | `active`→绿"启用"；`disabled`→灰"已停用"；`expired`→红"已过期" | 未知值原样显示 + 灰 |
| `contract_version` | 同名字段 | `契约 v2`；≠2 时加 tooltip"与当前系统契约（v2）不一致" | 恒有值（DB 默认 2） |
| `version` | 同名字段 | `v{version}` 小字（乐观锁版本，编辑抽屉用） | 恒有值 |
| 店铺 ID | `shop_id` | mono 文本 | null → `—` |
| app_key | `app_key_masked` | mono，`sk_****9f2`（后端已脱敏，前端**不再二次处理**） | 恒有值 |
| 连通性 | `connectivity` + `last_tested_at` | 圆点 + 文字，四态映射见 §4.2；未测过 → 灰点"未测试" | `last_tested_at` null → "最近测试 —" |
| 最近测试 | `last_tested_at` | 本地时区 `MM-DD HH:mm` | null → `—` |
| 最近错误 | `last_test_error` | 灰色折叠行（默认单行省略，点击展开）；**`interfaces_unverified` 前缀用黄底** | null → 不渲染该行 |
| 部署约束 | `extra`（jsonb） | 只认三个键：`network_mode`（`direct`/`direct_eip`/`edge`/`manual`/`unknown`）、`ip_whitelist`（`required`/`none`/`unknown`）、`datacenter`（字符串或 `unknown`）；缺键一律显示"未核验" | `extra={}` → "公网直连(默认) · IP 白名单 未核验 · 机房 未核验" ← **默认值必须标注"(默认)"**，因为这是 docs/01/02 的"未核实前按最严格假设"，不是已证实的结论 |
| edge-proxy 状态 | **无字段** | 不渲染该行（宁缺勿造）；原因与降级登记在 §7 G4 | — |
| 引用名 | `app_secret_ref` / `access_token_ref` / `refresh_token_ref` | 小字 mono，变量名可显示（它只是名字）；null → `—` | — |

> **为什么 `app_secret_ref` 能显示而 `app_key` 只能显示掩码**：引用名是变量名（`PDD_APP_SECRET`），本身不是秘密；`app_key` 是平台应用标识，后端按凭据口径脱敏。前端不做任何再加工。

## 4. 交互

### 4.1 新建 / 编辑抽屉

复用 M3 `Drawer`（560px）+ `Field`。字段顺序与说明文案：

```text
┌ 新建平台账号 ───────────────────────────────────── [×] ┐
│ 只填引用名，不要填密钥本身。实值配在环境变量或 Vault。     │
├───────────────────────────────────────────────────────┤
│ 平台 *          [拼多多 / 1688 ▾]   ← 编辑时 disabled   │
│ 店铺 ID         [________________] 平台后台的店铺/商户 ID │
│ 店铺名称         [________________]                       │
│ app_key *       [________________] 平台分配的应用标识      │
│ ── 凭据引用名（不是密钥）──────────────────────────────  │
│ app_secret_ref *[PDD_APP_SECRET__]                        │
│   ⓘ 这里填环境变量名（如 PDD_APP_SECRET），不要填密钥本身    │
│ access_token_ref [________________] 可选；token 轮换由外部完成 │
│ refresh_token_ref[________________] 可选                   │
│ token 过期时间   [________________] 可选（datetime-local）  │
│ ── 部署约束（extra）───────────────────────────────────  │
│ 网络模式         [公网直连 ▾]  取最严格：edge > 白名单 > 直连 │
│ IP 白名单        [未核验 ▾]                               │
│ 指定机房         [________________] 未核验可留空           │
├───────────────────────────────────────────────────────┤
│                              [取消]  [创建账号 / 保存]   │
└───────────────────────────────────────────────────────┘
```

规则：

| 规则 | 行为 |
|---|---|
| `platform` | 新建可选，**编辑不可改**（后端 PATCH 不接受 `platform`）→ disabled + hint"平台不可修改，如需更换请归档后重建" |
| `shop_id` | 新建可填；**编辑不可改**（同样不在 PATCH 白名单）→ disabled |
| `app_key` | 编辑时预填空值：placeholder"留空不修改"，与 M3 Provider 的 `credential_ref` 同策略（避免把掩码值回写到后端） |
| 引用名预校验 | 失焦/提交前本地跑：`^[A-Za-z_][A-Za-z0-9_:./@-]{0,127}$` 且不含 `[A-Za-z0-9+/=_-]{24,}`。不通过 → 字段下红字"这看起来像密钥本身；这里只填变量名，例如 PDD_APP_SECRET"，**不发请求** |
| 后端 400 | 原样显示服务端 `error.message`（"请传引用名，实值配在环境变量或 Vault"）+ `detail.expected` 作为第二行 |
| 提交中 | 按钮 `Spinner` + 全表单 disabled（防重复）；抽屉不可关闭（避免用户以为没提交） |
| 成功（201/200） | 抽屉关闭、列表刷新、页面右下 toast：`已创建 拼多多 · 旗舰店 A`；新建条目**高亮 2 秒**（`--brand-50` 底） |
| 409 创建冲突 | 红条"该平台该店铺已有未归档的账号；如需重新接入请先归档旧账号" |
| 409 编辑冲突 | 红条**"数据已被他人修改，请刷新"** + `[刷新并关闭]` 按钮；抽屉保留用户已输入内容（可复制后重开） |

### 4.2 测试连接 —— 四种结果的视觉表现（本任务最关键的一段）

按钮点击 → `POST /api/platform-accounts/:id/test` → 结果落在**账号卡内联结果条**（不弹 toast、不跳页），并立即用返回的 `connectivity/last_tested_at` 刷新卡片。

| 结果 | 触发来源 | 颜色/图标 | 卡片内文案 | 卡片连通性行 |
|---|---|---|---|---|
| `ok` | 后端返回 `ok:true`（**当前不可能发生**） | 绿 `--success` / ✓ | `连通正常 · {latency_ms}ms` | ● ok（绿） |
| `auth_invalid` | `connectivity==='auth_invalid'` | 红 `--danger` / ✕ | `鉴权失败：请检查 app_key 与凭据引用名指向的值是否匹配、token 是否过期` | ● 鉴权失败（红） |
| `interfaces_unverified` | `reason==='interfaces_unverified'`（**当前固定结果**） | **黄 `--warning` 底 `--warning-bg` / ⚠** | `无法发起真实请求：55 个平台接口 method 尚未核验（TODO-PDD-CONTRACT-VERIFY / TODO-1688-001…012）。这不是凭据错误，也不代表连通成功。` | ● 未测试（灰）——`connectivity` 仍是 `unknown` |
| `unreachable` | `connectivity==='unreachable'` | 红 `--danger` / ✕ | `无法连接：检查出口 IP / 网络模式（当前：公网直连）与平台白名单要求` | ● 不可达（红） |
| 请求失败（4xx/5xx/网络） | HTTP 层 | 红条 `--danger-bg` | `测试请求失败（{status} {code}）{request_id}` + `[重试]` | 不变 |

视觉细节（**防误读**）：

- `interfaces_unverified` **用黄色，绝不用绿色、绝不用 ✓ 图标**；结果条第一行永远是"无法发起真实请求"，不是"测试完成"。
- 结果条在 5 秒内不自动消失；用户可手动 `[×]` 关闭。卡片上的 `last_test_error` 长期保留该原因（后端已写回库），所以刷新页面后仍能看到"试过了、还是不通"。
- 测试中：按钮变 `测试中…` + spinner，同卡片其他按钮 disabled；**不做乐观更新**（不提前把圆点变绿）。
- `ok:false` 是**正常业务结果**，不弹 toast、不写"失败"红条 —— 只有 HTTP 层失败才是红条，两者不混。

### 4.3 归档

```text
[归档] → 行内二次确认条：
  "归档后该账号从列表消失，可重新接入同一店铺。审计会记录本次操作。"
  [取消] [确认归档]
```

- 成功后卡片移除 + toast `已归档 拼多多 · 旗舰店 A`。
- 归档不是删除；页面不提供"删除"。

### 4.4 刷新

- 顶部 `[刷新]`：重新 `GET /api/platform-accounts`。
- 不做 60s 自动轮询（本页无实时数据；轮询会让人误以为连通性在自动探测）。

## 5. 空态 / 加载 / 错误

| 场景 | 表现 |
|---|---|
| **全页空态**（0 个账号） | 状态条显示"尚未接入任何平台账号"；两张平台分组各显示分组空态，主 CTA `[接入拼多多账号]` / `[接入 1688 账号]`（admin）或"请联系管理员接入"（viewer）；下方三段照常显示"未接入" |
| 加载 | 骨架：状态条 1 行 + 2 张卡（各 2 个 120px 卡骨架）+ 3 个区块骨架；**≥300ms 才显示**，避免闪烁（13a §8.1） |
| 列表请求失败 | 顶部 `ErrorState`（code / request_id / next_action）+ `[重试]`；三段"未接入"区块不受影响（局部失败隔离）。401 → 跳登录 |
| 单平台分组请求失败 | 本设计列表是一次请求，故无分组级失败；若将来分请求，按区块局部失败处理 |
| 无权限（无 `platform.write`） | 所有写按钮**不渲染**；页面顶部 chip `只读`；viewer 仍可看账号、掩码、连通性 |
| 511 / 会话过期 | 跳 `/login?return_url=/platforms` |
