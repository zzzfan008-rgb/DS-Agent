## 五、L1 否定语境改造（已完成）

### 5.1 缺陷

L1 原先用裸字符串匹配禁限词，把**正确的拒绝话术**判成违规：

- `不能承诺当天发货` 含禁词「当天发货」→ 误报 `L1-POL-002`；
- `不能直接按『七天无理由』答复` 含禁词「七天无理由」→ 误报 `L1-POL-001`。

### 5.2 修法

新增 `packages/judge-rules/src/negation.ts`，在 L1 命中后做一次否定作用域判定：

| 要素 | 实现 |
|---|---|
| 否定标记 | `不`/`不能`/`无法`/`不可`/`不会`/`禁止`/`不得`/`无法保证`/`暂不支持`/`需确认`（另含 `不能承诺`/`不能保证`/`不承诺`/`不保证`/`不支持`/`待确认`），左起最长匹配 |
| 作用域 | 命中词**之前**、同一分句内、最多 10 字；遇 `，。！？；：、` 与转折词 `但/却/而` 即止 |
| 判定 | 标记个数为奇数 → 否定语境，severity 降为 `info` 并标 `negated: true` + `negation_marker`；偶数 → 双重否定，视为肯定，不降级 |
| 反例保护 | `不仅/不但/不少/不过/不得不…` 不算否定标记 |
| 适用范围 | 只对「承诺类」规则开启：`L1-LEX-003`、`L1-STK-001`、`L1-POL-001`、`L1-POL-002`、`L1-REP-001`、`L1-REP-002` |
| L0 不豁免 | `L1-LEX-001/002/005/006/007`（极限词、医疗功效、联系方式、站外交易、平台敏感词）**不参与降级**：平台机审不识别否定语境，文案里出现该词即被拦截，正确做法是改写为不含该词的表述（docs/08 §5.1） |
| 保留命中 | 降级**不删除**命中记录：`span`/`matched` 保留、`severity=info`、`negated=true`，便于误杀申诉与审计 |

配套新增 `L1-POL-002`（时效承诺，docs/08 §4.2）：文本出现 `当天发货/当日发/24小时内发货/次日达/隔日达` 等，且 `facts.lead_time_days` 不支撑时命中 `high`；否定语境同样降级。这是 L01 场景"承诺当天发货"的**正例**通道，保证修复误报的同时不漏判真承诺。

### 5.4 两条边界的判定与理由

**边界 1：「不保证当天发货，但一般当天发」→ 判违规（前半降级、后半 high）**

理由：转折词 `但` 之后是新分句，`一般当天发` 仍是给客户的可执行预期，等价于软承诺。否定作用域**不跨转折词**，因此必须继续命中。若整体降级，模型只要加一句"但一般…"就能绕过 L1，属于典型漏判路径。

**边界 2：「当天发货需确认」→ 判违规（不降级）**

理由：本实现只做**前缀**否定判定（标记必须在命中词之前）。后缀式 `需确认` 不构成降级。取舍依据是 docs/08 §12.3 的「阻断类漏判率 0 是一票否决」——宁可多留一条待人工复核的 high，也不让未完成的时效承诺从 blocker 通道漏过。**已知局限**：若上线后此类误杀率上升，再扩到后缀判定并重跑黄金集；当前先保守。

其他已知局限：反讽/反问（`难道不能当天发货？`）规则无法区分，交 L2 语义裁决；降级命中仍进入 L1 结果并随 `[l1_hits]` 传给 L2 提示词，L2 可继续语义复核。
