# 0009 · 凭据不进普通备份、单独加密导出与轮换

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 决策类型 | 安全（备份与密钥生命周期） |
| 关联 | `docs/00` §19.2；`docs/14` §5；`docs/20` §4 §5 §7 |

## 背景

1. **DSH 凭据未声明静态加密**（`docs/00` 附录 A 已核实）：`dsh-credentials` 只报「是否已配置/来源/能否写入」，绝不返回值；`dsh-credentials-local` 文件仅属主可读，**Windows 无 mode 检查**；agent 工具进程与 Host 同 OS 用户——文件权限无法对 agent 隐藏。
2. **凭据一旦进备份，爆炸半径等于所有备份介质**：备份会复制到离线盘、测试机、个人电脑。把明文 Key 放进 `dsh-data` 的 tar 包，等于把「卷内 0700」的保护一次性作废。
3. **凭据分三平面**（`docs/14` §5.1）：P1 模型供应商 Key（DSH 凭据）、P2 平台 appSecret（`credential_ref` 信封加密，DSH 永不接触）、P3 基础设施口令（容器 secret / KMS）。三者不能共用一把主密钥、不能共用一个存储。
4. **不可恢复 ≠ 必须备份**：模型 Key 可以在供应商控制台 5 分钟内重建；平台 appSecret 可重置（注意双 secret 窗口）。把「不可恢复」换成了「可重建」，比长期保管明文更安全。
5. **泄露预案要求 15 分钟内止血**（`docs/14` §5.5）：若平时没有导出与轮换路径，事故当天才现造流程必然超时。

## 决策

- **普通备份一律排除凭据**：
  - `dsh-data` 卷备份命令固定带 `--exclude='home/.credentials.yaml'`（路径见 `docs/20` §3.1）；备份报告校验清单断言该路径**不在**产物中，命中即视为备份失败。
  - `credential_ref` 的密文**随 Postgres 备份走**（它是密文，且恢复必须依赖它），但明文与 KEK 都不进备份。
  - 凭据值不进 Git、不进镜像、不进日志、不进 `model_call_log`、不进异常栈（`docs/14` §5.2）。
- **单独加密导出（唯一允许的凭据离开路径）**：`scripts/ops/credentials-export.sh` → **age** 加密到离线公钥（私钥只在离线介质/纸面保管），产物 `backup/creds/<yyyy>/<mm>/<dd>/dsh-credentials.age` + `.sha256` + `manifest.json`（字段：导出时间、DSH 版本、条目**名称**列表、加密算法、接收方公钥指纹、操作人、`request_id`）。**只导名称与值，不导明文清单到 stdout**。
- **导出频率与保留**：按变更触发（轮换后必导）+ 每周一次定期导出；保留最近 3 个版本 + 每季度 1 个归档；超过 365 天的归档直接销毁（密钥本身也应已轮换）。
- **首选恢复路径是「重建」而非「解密」**：恢复时先按 §轮换流程在供应商/平台侧新建 Key，再 `credentials set`；只有在「无法新建」时才用 age 导出件解密恢复。
- **轮换节奏**（与 `docs/14` §5.4 一致，此处只固定与备份的联动）：P1 模型 Key 90 天、P2 平台 appSecret 180 天、KEK 365 天、桥接令牌每次 Host 重启、备份加密密钥（age 接收方）365 天。轮换后**必须**生成一次新导出、销毁上一个导出件。
- **审计**：`audit_log(action='credential.export' / 'credential.rotate' / 'credential.revoke')`，含 `actor`、`purpose`、`fingerprint`（SHA-256 前 16 位，不复原明文）、`key_version`。

## 备选方案与放弃理由

| 方案 | 放弃理由 |
|---|---|
| 凭据随普通备份一起打包 | 介质泄露 = 凭据泄露；离线盘/测试机的安全等级远低于生产；违反 `docs/20` 不变量 I4 |
| 完全不导出，只靠重建 | 供应商控制台不可用、账号被锁、或有人离职时无法重建 → 恢复路径断；导出是「最后一把钥匙」 |
| 用同一 KEK 加密凭据与业务备份 | 爆炸半径合并：KEK 泄露同时暴露平台写权限与全部业务数据 |
| 把 P2 平台密钥也放进 DSH 凭据 | DSH 凭据无静态加密、agent 同用户可读；平台写权限泄漏 = 可被冒充改价/发消息（`docs/14` §5.3 明确禁止） |
| 用 Git 加密仓库（SOPS）+ 提交 | 历史不可彻底清除；密钥轮换后旧提交仍可解密；协作面扩大 |
| 用密码管理器人工保管 | 无审计、无版本、无自动化校验，多环境一致性差 |

## 影响

| 面向 | 内容 |
|---|---|
| 正面 | 备份介质泄露不再等于凭据泄露；恢复有两条路径（重建优先、导出兜底）且都被演练覆盖 |
| 正面 | 与三平面分离一致，P1/P2/P3 各自独立轮换，互不牵制 |
| 代价 | 恢复多一步人工（重建或解密），RTO 增加（凭据恢复演练目标 ≤ 30 分钟） |
| 代价 | 需维护 age 公私钥与离线介质，人员变动时有交接成本 |
| 缓解 | 导出脚本内置 `gitleaks` 自检与「不打印明文」断言；私钥双人保管 + 封存记录；演练每季度一次（`docs/20` §5.4） |
| 观测 | 指标：距上次轮换天数、导出件数量与年龄、备份清单断言通过率、凭据相关 401 计数 |

## 复审触发条件

- DSH 宣布凭据**静态加密**并给出密钥管理方式（此时可放宽「不进普通备份」，但仍需独立主密钥）。
- 引入 KMS/Vault/云密钥服务，age 导出可被托管密钥替代。
- 平台要求证书类凭据（`platform_cert`）且有效期 < 90 天，轮换节奏需改为自动化。
- 发生一次凭据泄露或备份介质外泄事件，须复盘本 ADR 的排除项是否失效。
- 人员变动导致 age 私钥保管链断裂，需重建信任根并重签所有导出件。
