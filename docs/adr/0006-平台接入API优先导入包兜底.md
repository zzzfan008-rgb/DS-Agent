# 0006 · 平台接入 API 优先、导入包兜底

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 决策类型 | 集成策略（受外部平台约束） |
| 关联 | `docs/00` §8 §9.2 §18；`docs/01`、`docs/02`、`docs/03`；`docs/11`；ADR-0005 |

## 背景

1. **平台权限不可控**：拼多多/1688 的开发者账号、应用审核、接口权限、类目资质都有周期与不确定性；1688 公开 API 文档在 M0 现场未能核实（`docs/00` 附录 A）。
2. **接口能力天然不齐**：上架、改价、库存、订单、消息、素材上传各有不同的审核状态与限流；部分接口可能要求指定机房或 IP 白名单（`docs/00` §8.3）。
3. **浏览器自动化是明确的禁区**：账号风控、封店风险、DOM 漂移导致的不确定性，收益远小于损失；本方案的非目标里已写死。
4. **但业务不能等**：`docs/00` §18 风险登记要求「导入包与人工路径同批交付，不阻塞其余模块」。
5. **客服消息是特例**：消息必须秒级进出，无法用「导入包 + 人工」承受，只能走 API 或人工工作台（`docs/18` §0.3 发送四级降级）。

## 决策

- **三条接入通道，按能力择优，不按偏好**：
  | 通道 | 适用 | 写入门 | 审计 |
  |---|---|---|---|
  | 官方开放平台 API | 接口已获批且满足字段需求 | 走写入门（幂等 + 快照 + 限流） | 全量 |
  | 上架包（CSV/Excel）+ 后台导入 | 接口未获批或字段不支持 | 由系统生成包 → 人工导入 → **回填登记** | 登记导入批次号与包哈希 |
  | 人工工作台 + 剪贴板助手 | 消息、询盘等无法 API 化的场景 | 复制/粘贴由人执行，系统只做去重占位与登记 | `handed_off` / `unconfirmed` 状态（`docs/18` §0.4） |
- **每种平台的 adapter 拆两层**：中心侧 `packages/adapters-pdd` / `adapters-1688`（业务逻辑、幂等、快照、审计）+（按需）`edge-proxy`（只在满足机房要求时做转发、签名、时间窗防重放、报文留档；不做业务判断）。
- **「未自动化接口清单」是一等交付物**：每个平台维护一张表（接口、原因、替代路径、回填方式、责任人、复核日期）。接口获批后从清单移出并跑 contract 回归。
- **导入包是产品化产出，不是临时脚本**：模板带版本号、字段级必填与校验、生成时记录 `payload_hash`；导入结果必须回填（批次、成功/失败条数、平台驳回原因），否则视为未完成。
- **禁止浏览器自动化**：不写 Playwright/DOM 注入/按键模拟；不做请求重放绕过签名。剪贴板助手只做「复制 + 记录」，不碰页面。

## 备选方案与放弃理由

| 方案 | 放弃理由 |
|---|---|
| 全量浏览器自动化（Playwright/RPA） | 违反平台规则与风控约束；DOM 变更即失效；无法审计「谁改了价格」；一旦封店，损失不可逆 |
| 只做导入包，不做 API | 客服消息无法批量导入 → 秒级不可达，直接放弃成功标准 2；库存/订单同步也做不到 |
| 只等 API 齐全再开工 | 权限周期不可控，整个项目被外部阻塞；与 `docs/00` §18 的缓解策略冲突 |
| 第三方聚合服务/中间商 | 账号凭据交给第三方 = 最高的不可控风险；数据出境与合规不可控；费率与 SLA 不可审 |
| 统一用「人工在平台后台操作」 | 放弃自动化收益，且人工操作无审计、无快照，不可逆动作更难追溯 |
| 自研 RPA 内核（无浏览器，直接构造请求） | 等于自研签名/风控规避，长期维护成本与封号风险都不可接受 |

## 影响

| 面向 | 内容 |
|---|---|
| 正面 | 外部依赖不全时仍能交付核心价值；每条通道都有审计与幂等，不存在「暗路径」 |
| 正面 | `未自动化接口清单` 把不确定性显性化，项目计划可据此排期与降级 |
| 代价 | 三条通道 = 三套校验与回填逻辑；导入包的模板版本需随平台改版维护 |
| 代价 | 人工通道的「是否真的发出」系统无法确认（`handed_off`/`unconfirmed`），必须靠回填与对账弥补 |
| 缓解 | 通道选择由 adapter 的能力矩阵决定，业务层只调用统一接口；导入包生成器与校验器复用同一 schema；`unconfirmed` 超 20 分钟进对账队列（`docs/18`） |
| 观测 | 指标：各通道占比、导入包成功率与驳回率、`unconfirmed` 数量、未自动化接口数变化、edge-proxy 调用延迟 |

## 复审触发条件

- 某平台接口大面积获批（未自动化清单缩短 > 50%），需重排通道优先级并退役对应导入包。
- 导入包模板被平台改版且无兼容窗口，需要重新评估该平台的可自动化边界。
- 平台新增能力（如官方消息撤回、批量导入 API）改变不可逆语义，需与 ADR-0005 联动复审。
- `edge-proxy` 的部署要求变化（如取消指定机房要求），可移除该组件以降低运维面。
- 平台明确禁止某类自动写（书面规则），必须立即收窄通道并更新清单。
