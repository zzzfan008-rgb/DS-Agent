# 0007 · DSH 版本锁与只用公共扩展点

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 决策类型 | 依赖治理（供应链与升级策略） |
| 关联 | `docs/00` §3.2 §19.4 附录 A；`docs/14` §5.3；`docs/17`；ADR-0004 |

## 背景

1. **内核在预发布通道且节奏极快**：当前 `0.2.1-rc.2`，2026-10-09 至 10-17 九天内 5 个 alpha/rc，累计 36 个版本（`docs/00` 附录 A）。语义与接口可能在小版本内变化。
2. **本方案重度依赖其扩展面**：`dsh-llm-pi-ai`（多供应商路由与热生效）、`dsh-credentials`（密钥按名引用）、`dsh-api-gateway`（流式 Remote + 取消）、`dsh-api-remote-access`（peer principal 授权）、`dsh-skill-filesystem`、`dsh-mcp-client`、`dsh-agent-preset`、`dsh-webhook`、`dsh-headless`。
3. **升级破坏的后果是工作台不可用**：agent 类功能是业务流程的一环（草稿、判断、内容生产），不是可选装饰。
4. **fork 内部包会锁死升级路径**：预发布期内部实现变动频繁，任何私有补丁在下一次升级时都要重新移植，且无法区分「我们的 bug」与「上游的 bug」。
5. **业务核心链路不能依赖 agent loop**：`docs/00` §19.4 要求停更兜底——核心链路必须能降级为「直调模型 + 自建 MCP」。

## 决策

- **版本锁定**：`package.json` 精确版本（不用 `^`/`~`）+ lockfile 提交 + `resolutions`/`overrides` 固定传递依赖；`dsh-headless` 二进制版本写入 `infra/dsh-version.txt`。CI 校验锁文件未漂移：
  ```bash
  git diff --exit-code -- pnpm-lock.yaml infra/dsh-version.txt
  pnpm ls --depth 0 --json | jq -r '.[] | select(.name|startswith("@deepseek-ai/")) | "\(.name)@\(.version)"' > /tmp/dsh-lock.txt
  diff -u infra/dsh-lock.txt /tmp/dsh-lock.txt
  ```
- **只用公共扩展点**（白名单，超出即评审阻断）：
  | 允许 | 形式 |
  |---|---|
  | MCP server | 独立进程，stdio/HTTP，工具与资源经协议 |
  | Skill | 目录 + `SKILL.md`，`dsh-skill-filesystem` 发现 |
  | Agent preset | Cordis bundle 声明，不改内核插件 |
  | Plugin bundle | 官方 bundle 机制安装/启用 |
  | Remote service | `@Remote({ mode:'stream' })` 的公开装饰器 |
  | 凭据 API | `dsh-credentials` 的「设置/查询状态/删除」，不读返回值 |
  | Headless CLI | `--json` 事件流、`--session-id` 续接 |
- **禁止**：fork 任何 `@deepseek-ai/*` 包；import 未在公开入口导出的内部路径（`@deepseek-ai/x/dist/*`、`/src/*`）；改 `node_modules` 打补丁；依赖未文档化的环境变量。
- **升级窗口与回归**：月度窗口（每月第一个周二），固定回归清单 7 项——preset 加载、skill 发现、MCP 工具可调用、Host 常驻与流式调用/取消、存储读写（凭据状态、会话落盘）、Typert 调用与 `AbortSignal`、`dsh-headless --json` 退出码与事件流。
- **降级兜底**：文本生成保留「直调供应商 HTTP」路径（`packages/registry` 内），MCP 工具自建（`packages/mcp-erp`、`packages/mcp-knowledge` 不依赖内核）。停更或内核故障时，核心业务仍可运行，只是失去 agent 的多步编排。

## 备选方案与放弃理由

| 方案 | 放弃理由 |
|---|---|
| 跟随 `latest`/`next`（不锁版本） | 预发布期每天可能有变化；工作台不可用的风险变成常态；无法定位回归 |
| Fork 内核并私有修改 | 每次升级都要重新移植补丁；与上游语义分叉后无法复用 bug 修复；包规模 311 个大，维护不可能 |
| 完全不用 DSH，自研 agent 内核 | 放弃多供应商路由、skill/MCP 编排、流式 RPC 的既有实现；工期与风险远超收益（ADR-0004 复审项） |
| 只锁 lockfile，不锁传递依赖 | `resolutions` 缺失时传递依赖仍会漂移，表现为「本地能跑、CI 挂」的隐性升级 |
| 仅在 CI 中打快照，无回归清单 | 通过 CI 不等于行为正确（agent 行为变化需要端到端回归） |

## 影响

| 面向 | 内容 |
|---|---|
| 正面 | 升级可控、可回滚（回退 lockfile + 镜像标签即可）；故障可归因到「我们 vs 上游」 |
| 正面 | 只用公共缝，意味着上游重构内部实现时我们不受影响 |
| 代价 | 安全补丁只能等月度窗口（预发布期尤其明显）；需保留例外通道 |
| 代价 | 内部能力不可用时只能绕（例如缺 embedding 包 → 自建 pgvector，ADR-0003） |
| 缓解 | CVE 例外通道：高危漏洞不等窗口，走「单包定点升级 + 全量回归」；升级失败即回退镜像并记录；`dsh-lock.txt` 入库可审计 |
| 观测 | 指标：当前版本、距上次升级天数、回归清单通过率、因上游变更导致的缺陷数 |

## 复审触发条件

- DSH 发布 **1.0 稳定版**并给出语义化版本承诺，可放宽到「minor 自动、major 手动」。
- 出现高危 CVE 且月度窗口无法覆盖，需重评例外通道的频次上限。
- 公共扩展点出现破坏性变更（如 `@Remote` 签名、skill 发现规则、凭据 API），必须在一个迭代内完成适配。
- 连续 2 次月度升级回归失败，需重新评估版本策略（考虑拉长窗口或临时冻结）。
- DSH 宣布停止预发布通道或改变许可/分发方式，触发整体依赖策略复审。
