# 0005 · 写操作 A/B/C 分级与禁止伪回滚

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 决策类型 | 业务规则（安全红线，不可由实现层绕过） |
| 关联 | `docs/00` §9.2 §9.3 §16 §18；`docs/06` §3.3 §3.4；`docs/11`；ADR-0002 |

## 背景

1. **平台线上状态不是幂等可逆的**：改价、换主图、改类目可能触发重新审核、搜索降权、活动中掉线；客服消息发出后平台没有撤回接口。
2. **「回滚按钮」是一个危险的隐喻**：用旧快照覆盖写回 ≠ 恢复原状。平台侧可能已经走了一次审核、权重已经掉了、活动已经退出——覆盖写只是再触发一次写操作，把不可逆变成「两次不可逆」。
3. **验收口径是 0 容忍**：不可逆误操作率 0、越权/未审批写 0（`docs/00` §16）；一旦用「伪回滚」掩盖事故，审计就失去了唯一可信的叙述。
4. **两类业务线敏感点不同**：拼多多对价格与主图最敏感，1688 对报价与起批条件最敏感（`docs/00` §2.2），分级必须允许按平台/动作细化，但级别语义不能改。

## 决策

- **分级落在数据上**：`approval.operation_level ∈ {A,B,C}`（`docs/06` §2 `ck_operation_level`），action 白名单 `ck_approval_action`。分级判定由 `packages/core` 的规则表给出，**不由调用方传参决定**；调用方声明与规则表冲突时以规则表为准并记审计。
- **A 可逆**（库存微调、未发布内容、内部标签）：常规审批；回滚 = 用 `published_snapshot` 覆盖写回，且必须写 `audit_log(action='listing.rollback', irreversible=false)`。
- **B 不可逆·低危**（新增 SKU、发送客服消息、替换非主图素材）：审批界面强制展示「提交/发出后不可撤回」；不提供回滚入口；事故处理只能走**止损**——紧急下架、补偿话术、`compensating_ticket`。
- **C 高危·不可逆**（在售改价、换主图、改类目/关键属性、触碰活动字段）：红色警告 + 二次确认（`confirm_token` 落库）+ 影响面提示 + 建议执行窗口；强制双人（审批人 ≠ 发起人）；执行前查活动状态，命中活动期转「预约低峰窗口」或「先下架再改」，并记录决策依据。
- **禁止伪回滚（硬规则）**：不得用旧快照覆盖写回并对外宣称「已恢复」。B/C 类必须登记不可逆动作（`irreversible=true`）并生成 `compensating_ticket`；工作台与对外口径统一使用「止损」一词。代码层面：`POST /listings/rollback` 只接受 `operation_level=A` 的目标，否则返回 `422 irreversible`。
- **kill switch 联动**：`block_writes` / `block_replies` 一旦命中，写入门在硬校验阶段拒绝，不进入 adapter。

## 备选方案与放弃理由

| 方案 | 放弃理由 |
|---|---|
| 全量快照 + 自动回滚（对所有动作） | 平台没有事务；覆盖写会再触发审核/权重变化，等于制造第二次事故；且给运营「可以随便改」的错误安全感 |
| 一律禁止写平台，全部人工在后台操作 | 放弃自动化的核心收益（`docs/00` §1.2 成功标准），且人工操作同样不可逆却没审计 |
| 按金额阈值自动分级（如 >500 元算 C） | 金额不是唯一风险维度：换主图 0 元但可能掉权重；改类目影响全店搜索权重。风险维度必须多因子 |
| 只用「二次确认弹窗」不分级 | 弹窗会被肌肉记忆点掉；分级提供的是**流程差异**（双人、窗口、影响面、登记），不是一次点击 |
| 用消息撤回/重新编辑补偿 B 类 | 平台不提供消息撤回接口；重新发送会造成重复触达（`docs/18` 出站重复 0 容忍） |

## 影响

| 面向 | 内容 |
|---|---|
| 正面 | 不可逆动作可枚举、可登记、可复盘；审计能区分「回滚」与「止损」，事故叙述不再自欺 |
| 正面 | C 级双人与窗口机制把最高风险的操作压到低峰、可回退的路径上（先下架再改） |
| 代价 | C 级操作变慢（双人 + 窗口），高峰期改价体验下降 |
| 代价 | 需要维护「动作 → 级别」的规则表与插件（新平台/新动作上线必须补表，否则默认按 C 处理） |
| 缓解 | 预约执行（`scheduled`）承接高峰期需求；批量操作按最大级别取整（一批里有一条 C 则整批 C）；规则表带版本号与单测 |
| 观测 | 指标：C 级占比、二次确认缺失次数（须恒为 0）、`422 irreversible` 命中数、不可逆登记覆盖率、止损时效 |

## 复审触发条件

- 平台明确提供可回滚/版本化发布能力（需 `docs/01`/`docs/02` 现场核验书面证据），A 级边界可扩大。
- 出现规则表无法判定级别的新动作类型（上线前必须补表，此项同时是阻断条件）。
- 不可逆登记覆盖率连续两月 < 100%，说明分级被绕过，需收紧为硬编码白名单。
- 业务侧提出「批量改价」常态化（周频次 > 3），需要专门的窗口调度与批量审批策略。
- 平台处罚/风控事件被归因为某次写操作，需回看分级是否低估。
