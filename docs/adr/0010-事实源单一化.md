# 0010 · 事实源单一化（模型不得生成价格/成分/尺码/政策）

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 决策类型 | 业务规则（合规红线，实现层不可绕过） |
| 关联 | `docs/00` §10 §11 §16 §18 §19.1；`docs/06` §2 `ck_source_kind`；`docs/08`；`docs/20` §8；ADR-0008、ADR-0003 |

## 背景

1. **价格与政策是 0 容忍字段**：`docs/00` §16 把价格与政策的错误率定义为 0 容忍；一次错价可能带来批量亏损与投诉，一次错政策可能构成虚假宣传。
2. **LLM 会「顺手编」**：只要提示词里没有事实，模型就会从训练分布里补一个合理的数字。这不是提示词工程能根治的问题，而是**数据来源**问题。
3. **渠道多、写法多**：同一份成分别在详情页、客服话术、平台属性、尺码表图、报价单里出现；任何一个渠道手写，就会出现「五个版本」。
4. **平台与法律要求可追溯**：写入平台的每个字段都应能反查到来源记录（`docs/00` §18 事实源单一化硬规则）；AIGC 与实拍的边界、功效词、绝对化用语都要在判断层拦。
5. **模型的价值是改写而非发明**：语气、场景、结构的优化肉眼可见；数值与承诺的「优化」只会制造风险。

## 决策

- **唯一事实源**：价格/库存来自 `product_sku`（导入/ERP/平台同步）；成分来自 `fabric_composition`；尺码来自 `size_chart`；退换政策/资质来自 `kb_document`（带 `version_no` + `effective_from` + 来源）。模型只能**取用与改写措辞**，不得产生或推断这些字段。
- **物理层禁止**：`ck_source_kind` 枚举刻意不含 `model`/`ai` 取值（`docs/06` §2）——「模型产生事实」在数据库层不可表示。
- **生成前装配事实快照**：`content_draft.facts` 必须绑定来源（表 + 行 id + 版本/哈希）；无快照不允许进入 `generating`（守卫拒绝，`422 invalid_fact`）。
- **判断层三段闸门**：L1 规则校验数值一致性与字段完整性（价格与主数据逐字段比对、成分合计 100、尺码区间合法、政策引用存在且未过期）；L2 只判语义（夸大、场景匹配、越界承诺）且输出必带 `evidence_refs`，无引用直接升级 L3；L3 = 一切平台写操作（`docs/08`）。
- **可追溯**：写入平台的 payload 带 `facts_hash`；`listing.published_snapshot` 记录「这个字段当时来自哪一行/哪一版」；抽检可以机械复算。
- **变更联动**：任何触碰价格/库存/成分/尺码/政策的变更 → `product.fact_version + 1` → 相关 `pending` 审批 `invalidated`，`approved` 未执行的重新校验（`docs/06` §3.1）。
- **静态与运行时防线**：提示词模板中禁止出现数值型占位符（只能引用 `facts.*`）；生成后对「数字、百分比、日期、政策关键词」做正则抽取并与快照比对，不一致即 `needs_revision`。这条同时是 `docs/20` §8 静态规则的一部分。

## 备选方案与放弃理由

| 方案 | 放弃理由 |
|---|---|
| 让模型生成后人工审核兜底 | 0 容忍指标下不可行：抽检漏检即事故；且人工复核成本高于收益，长期必然流于形式 |
| 用 RAG「尽量给对的事实」 | 检索是概率性的，缺片/过期切片会直接变成编造；RAG 只能作为**取数**手段，取值必须结构化绑定 |
| 提示词里写死「不要编造」 | 提示词不是约束，是建议；模型在长上下文中会漂移，且无法审计是否遵守 |
| 把事实做成可编辑的自由文本字段 | 编辑即失真，且无法追溯来源；与 ADR-0008 冲突 |
| 全人工撰写（不用模型） | 放弃成功标准 1（人工只需校对与审批），且人工写同样会写错且无校验 |

## 影响

| 面向 | 内容 |
|---|---|
| 正面 | 事实错误率可测、可追、可复算；平台驳回与合规风险显著下降；文案生成可以放心交给多模型路由 |
| 正面 | 「事实 → 判断 → 审批 → 写入」链路每一环都有硬校验，模型能力升级不会降低安全性 |
| 代价 | 生成前必须装配事实快照（多次查询），挤占 5s 草稿预算 → 必须并行取数 + 缓存（`docs/18` §1.4） |
| 代价 | 提示词自由度受限：模板化程度提高，创意类文案需要走「无事实字段」的独立通道并明确标注 |
| 代价 | 主数据质量成为瓶颈：脏数据会让生成大面积 `needs_revision`，导入校验必须先到位 |
| 缓解 | 快照做 60s 进程内缓存（按 `fact_version` 失效）；`facts_missing` 直接走模板降级而非硬失败；提示词分型（事实型/创意型）并在 UI 标注 |
| 观测 | 指标：抽检事实错误率（价格/政策 0）、`422 invalid_fact` 命中数、L2 无引用升级率、快照装配时延 P95 |

## 复审触发条件

- 平台政策/类目要求变化，出现必须「推断」才能填写的字段（如适用季节、风格标签）——此时仍须人工标注为事实，不可由模型产出。
- 抽检事实错误率连续两月 > 0（任一），需收紧为「禁止模型接触该类字段」并复核提示词。
- 引入新的内容渠道（如直播口播稿、站外投放）且携带价格/政策，需把渠道加入 L1 校验覆盖。
- 主数据源切换（ERP/平台同步优先级变化），需复核 `ck_source_kind` 与来源标记。
- 判断层 L2 改为本地小模型或规则化，需重新确认「无引用不进入判断」的守卫仍成立。
