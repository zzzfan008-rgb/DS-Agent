## 0. 结论先行

1. 七层测试：单测 / 集成 / 契约 / 端到端 / 安全 / 压测 / 演练。每层有明确的触发时机、时间预算与阻断级别（第 1 节）。
2. 平台契约用**录制回放 + 夜间沙箱**双轨：PR 跑回放（秒级、无外网），夜间跑沙箱（真实调用、可失败告警）。
3. 故障注入不是「测异常」，而是**验证每一种失败都有确定的错误码、重试分类与用户可见下一步**（第 5 节矩阵 14 行）。
4. 黄金集是**回归基线**，不是演示数据：≥50 个真实 SKU × 2 平台 × 3 类产出，硬事实 100% 精确匹配。
5. 安全与专项测试各有独立清单，且与 `docs/14` 的 SEC-01~40 一一对应（第 6、7 节）。
6. CI 门禁分层：PR 必过 9 项、夜间 6 项、发布前 5 项；任何一项红即禁止合并/发布（第 8 节）。
7. 静态规则用 ESLint + dependency-cruiser + 边界脚本三重保证：业务代码不碰 `.jsonl`、不碰 DSH 存储根、不直接 import Prisma（第 9 节）。
8. 测试产出必须可审计：JUnit、trace、压测报告、SARIF、恢复演练日志统一落 `artifacts/<run_id>/`，保留 90 天。

## 1. 测试分层

| 层 | 范围 | 工具 | 触发 | 时间预算 | 阻断级别 | 覆盖目标 |
|---|---|---|---|---|---|---|
| L1 单测 | 纯函数、规则集、状态机转移、哈希/幂等键、金额与尺码计算 | Vitest | 每次保存/PR | ≤90s | 阻断 | 行覆盖 ≥80%，`packages/core` ≥90% |
| L2 集成 | API 路由 + Postgres/Redis/MinIO 真实依赖、迁移、事务、队列 | Vitest + Testcontainers | PR | ≤8min | 阻断 | 所有写路由至少 1 条成功 + 1 条失败 |
| L3 契约 | 平台 adapter 请求/响应、错误码映射、字段漂移 | undici MockAgent 录制回放 + JSON Schema | PR（回放）/ 夜间（沙箱） | ≤3min / ≤10min | 阻断 / 告警 | 每个平台接口 ≥1 组录制，错误码全覆盖 |
| L4 端到端 | 12 个页面的 P0 用户旅程、SSE 流式、审批闭环 | Playwright | PR 冒烟 / 夜间全量 | ≤5min / ≤25min | 阻断 / 阻断 | P0 旅程 8 条，P1 旅程 12 条 |
| L5 安全 | 越权、注入、SSRF、密钥、沙箱、MCP | Vitest + Playwright + semgrep/gitleaks + 自定义探针 | PR（必跑子集）/ 夜间 | ≤4min | 阻断 | `docs/14` SEC-01~40 |
| L6 压测 | 会话列表、审批队列、批量发布、Agent 并发 | k6 | 每周 / 发布前 | ≤30min | 告警 / 阻断（发布前） | 达到容量基线（第 6.4 节） |
| L7 演练 | 备份恢复、止损、kill switch、DSH 升级回滚、账实对账 | 脚本 + 人工 | 每月/每季度 | 2–4h | 阻断（M9 验收） | 每次有记录、有结论、有整改项 |

执行顺序（PR）：L1 → 静态检查 → L2 → L3 回放 → L5 必跑子集 → L4 冒烟。前一层红则后续层不启动（fail fast）。

## 2. L1 单测

### 2.1 必测清单

| 模块 | 必测点 | 反例（必须存在） |
|---|---|---|
| `packages/core/domain` | 价格模型（拼多多售价/促销价 vs 1688 起批/阶梯）、库存扣减、SKU 组合唯一性 | 阶梯价区间重叠、起批量 > 库存 |
| `packages/core/facts` | 成分合计 100、尺码字段完整、身高体重区间不交叉 | 成分 99%、尺码缺胸围 |
| `packages/core/write-gate` | 幂等键生成、payload 哈希、审批绑定、七道校验顺序 | 同 payload 不同顺序字段应得同哈希 |
| `packages/judge-rules` | L1 规则命中/不命中、禁限词、品牌语气 | 空文本、超长文本、全角/半角混排 |
| `packages/core/reconcile` | 账实差异分类（少单/多单/金额差/状态差） | 平台有本地无、金额差 0.01 |
| `packages/core/cost` | 按 token/张/秒计费、四舍五入规则 | 0 token、超长上下文 |
| `packages/db` 迁移 | 每个迁移可重复执行（幂等 DDL） | 重复 `CREATE INDEX` 不报错 |

### 2.2 约定

- 时间必须注入 `clock`（禁止 `Date.now()` 直用），否则跨时区/过期用例不稳定；
- 随机必须注入 `rng`（seed 固定），失败可复现；
- 金额一律整数分，禁止浮点比较；
- 单测禁止访问网络、文件系统、真实时钟；违反即失败（Vitest `setupFiles` 里装探针）。

## 4. L3 契约测试：录制回放 + 沙箱

### 4.1 双轨模型

| 轨道 | 何时 | 网络 | 目的 | 失败处理 |
|---|---|---|---|---|
| 回放（Replay） | 每次 PR | 无 | 防回归：请求构造、签名、解析、错误码映射 | 阻断合并 |
| 沙箱（Sandbox） | 每晚 02:00 + 平台公告后手动 | 真实平台沙箱/测试店 | 防漂移：真实字段、限流、权限 | 告警 + 24h 内出工单 |
| 生产影子（Shadow） | 每周一次只读接口 | 真实生产（只读） | 校验真实返回结构 | 告警 |

### 4.2 录制

```bash
# 在沙箱环境录制（需要平台测试店凭据）
RECORD=1 PLATFORM=pdd pnpm test:contract -- --grep "item.add"
# 产物
tests/contract/fixtures/pdd/item.add/2026-10-20T10-00-00.json
```

录制规则：
1. **只录沙箱/测试店**，绝不在生产录制；生产只做只读影子校验；
2. 录制器在 `undici` 层拦截，保存 `request`（method、path、query、headers 白名单、body）与 `response`（status、headers 白名单、body）；
3. 脱敏：`app_key`、`sign`、`access_token`、`timestamp`、`nonce`、手机号、收货地址、买家昵称、店铺名 → 固定占位符；脱敏后仍须通过 JSON Schema 校验；
4. 时间与随机固定：`timestamp` 用 `2026-10-20T02:00:00Z`，`nonce` 用序号；
5. 每个 fixture 带 `meta.json`：平台、接口、录制时间、平台文档版本/公告号、录制人；
6. fixture 进 Git；单文件 ≤2 MB，超出裁剪到必要字段并注明。

### 4.3 回放

```ts
// tests/contract/replay.ts（示意）
const agent = new MockAgent();
agent.disableNetConnect();                       // 回放期禁止真实网络
for (const fx of loadFixtures(platform, endpoint)) {
  agent.get(baseUrl).intercept({ path: fx.request.path, method: fx.request.method })
    .reply(fx.response.status, fx.response.body, { headers: fx.response.headers });
}
```

断言四件事：
1. **请求**：签名可复算（用固定密钥 + 固定时间）、必填字段齐全、金额/库存为整数分；
2. **响应解析**：字段白名单解析，未知字段忽略但不报错；
3. **错误映射**：平台错误码 → 内部错误码（`platform_reject / quota / invalid_fact / upstream_5xx / conflict`）逐条断言；
4. **Schema 快照**：响应体对 `tests/contract/schemas/<platform>/<endpoint>.schema.json` 做校验；Schema 变化必须单独 PR 并说明。

### 4.4 字段漂移检测

| 漂移类型 | 检测 | 处理 |
|---|---|---|
| 新增字段 | 沙箱录制与上次 fixture 的 key 集合 diff | 允许，记录；若影响判断则更新解析 |
| 删除/改名必填字段 | Schema 校验失败 | 告警 → 阻断该接口发布 → 24h 修复 |
| 类型变化（string→number） | 运行时类型断言失败 | 同上 |
| 枚举新增值 | 枚举白名单断言失败 | 告警，人工确认后更新 |
| 限流阈值变化 | 压测/沙箱 429 比例 | 更新 adapter 限速配置 |

漂移报告落 `artifacts/<run_id>/contract-drift.json`，并自动开 `compensating_ticket`（类型 `contract_drift`）。

### 4.5 沙箱策略

- 沙箱测试店独立 appKey，与生产隔离；凭据走 P2 平面；
- 只跑**只读 + 可安全写的测试商品**；写测试用专门 `SIT-` 前缀商品，跑完清理；
- 沙箱不可用时：夜间任务标记 `skipped`，连续 3 天不可用升级告警，但不阻断 PR（回放仍跑）；
- 每次沙箱运行记录：接口数、成功/失败、429 次数、平均耗时，与上周对比。

## 5. L4 端到端与故障注入

### 5.1 P0 旅程（必须绿）

| ID | 旅程 | 关键断言 |
|---|---|---|
| E2E-01 | 登录（口令 + TOTP）→ 首页 | 无 TOTP 不得进入；审计有记录 |
| E2E-02 | 商品导入 → 尺码/成分校验 → 保存 | 非法数据被拒；合法数据可查 |
| E2E-03 | 文案生成 → 判断 → 提交审批 → 批准 → 发布 | 无审批不能发布；发布后 `listing` 状态正确 |
| E2E-04 | 客服消息到达 → 5 秒内草稿或模板 → 发送 | 重复点击只发一次；超时降级提示 |
| E2E-05 | C 级改价 → 红色警告 → 二次确认 → 执行/预约 | 无二次确认不得执行；活动期提示先下架 |
| E2E-06 | 批量发布 → 部分成功 → 失败项修复 → 重试 | 成功项不重复写；失败项有下一步 |
| E2E-07 | kill switch 开启 → 写入被拒 → 解除 | 解除需双人；全程审计 |
| E2E-08 | Agent 流式对话 → 中途取消 | 取消后上游停止；页面显示已取消 |
| E2E-09 | 素材生成 → 轮询 → 入库 → 关联 SKU | 成本记录；AIGC 标识存在 |
| E2E-10 | 审计检索 → 按 `request_id` 还原一次写操作 | 能串起 api→平台→审计 |

### 5.2 故障注入矩阵（14 行，必须逐行有用例）

| # | 注入 | 模拟方式 | 期望行为 | 错误码/状态 | 断言 |
|---|---|---|---|---|---|
| FI-01 | 连接超时 | mock 延迟 35s | 15s 断开、可重试、不重复写 | `upstream_timeout` | 队列重试 1 次后进死信 |
| FI-02 | 读超时（已发出） | 响应头后卡住 | 标记「结果未知」，不自动重试 | `upstream_unknown` | 不产生第二次写；人工核对 |
| FI-03 | 5xx | 500/502/503 | 指数退避重试 3 次 | `upstream_5xx` | 第 3 次失败进死信 + 告警 |
| FI-04 | 429 限流 | `Retry-After: 30` | 遵守 Retry-After，暂停该平台队列 | `quota` | 期间其它平台不受影响 |
| FI-05 | 401 token 过期 | 首次 401 | 刷新 token 后重试 1 次 | `auth_expired` | 刷新失败则停该平台并告警 |
| FI-06 | 部分成功 | 批量 10 条，3 条失败 | 成功落库、失败可单独重试 | `partial_success` | 重试只跑失败 3 条 |
| FI-07 | 重复回调 | 同 `event_id` 投递 3 次 | 只处理 1 次 | 幂等命中 | 无重复消息/订单 |
| FI-08 | 回调乱序 | 先到「已发货」后到「已付款」 | 按状态机拒绝回退或落补偿 | `conflict` | 状态不倒退 |
| FI-09 | 平台新增字段 | 响应多一个字段 | 忽略并记录 | — | 解析不失败 |
| FI-10 | 平台删/改必填字段 | 缺 `sku_id` | 契约校验失败 | `contract_drift` | 告警 + 阻断该接口 |
| FI-11 | 类型变化 | `price: "12.00"` | 严格解析失败，不猜 | `contract_drift` | 不产生错误金额 |
| FI-12 | 空响应/HTML 错误页 | 200 + `<html>` | 解析失败，分类为上游异常 | `upstream_invalid` | 不进死信前先告警 |
| FI-13 | 签名失败/时间戳过期 | 篡改 `sign` | 拒绝并审计 | `signature_invalid` | 不重试 |
| FI-14 | 大响应/慢流 | 20 MB、1 KB/s | 20 MB 上限、超时断开 | `response_too_large` | 内存不暴涨 |

每个注入用例必须同时断言：**错误码、队列状态、审计记录、用户可见提示**四件事，缺一不算通过。

### 5.3 端到端稳定性

- Playwright 禁用真实第三方（全部走 mock 或测试店）；
- 每个用例独立数据（`tests/e2e/fixtures/seed-<case>.sql`），串行执行；
- 失败自动留 trace + video + 截图，落 `artifacts/`；
- flaky 用例标记 `@quarantine`，24h 内修复或删除，不允许长期挂起。

### 6.4 压测

| 场景 | 脚本 | 负载 | 通过标准 |
|---|---|---|---|
| 会话列表 | `tests/load/conversations.js` | 50 VU × 5min | P95 < 300ms，错误率 <0.1% |

```js
export const options = {
  thresholds: {
    http_req_failed: ['rate<0.001'],
    http_req_duration: ['p(95)<300'],
    checks: ['rate>0.999'],
  },
};
```

压测环境必须与生产同规格（至少同 CPU/内存档），否则结论只作参考并注明。

## 7. 黄金集

### 7.1 定义

**黄金集 = 真实商品数据 + 固定预期 + 可重复评分。** 不是 demo 数据。

| 维度 | 数量 | 来源 | 说明 |
|---|---|---|---|
| 真实 SKU | ≥50 | M0 `data/sample-products.csv` + 生产主数据脱敏 | 覆盖：上装/下装/连衣裙/外套/针织；含尺码 2XS–4XL、特殊体型 |
| 平台 | 2 | 拼多多 + 1688 | 每个 SKU 两平台各一套预期 |
| 产出类型 | 3 | 文案 / 图片 / 尺码表 | 图片含主图规范、场景图、尺码表渲染图 |
| 用例总数 | ≥300 | 50 × 2 × 3 | 另加 20 条「应被拦截」的负例 |

目录：

```text
tests/golden/
├─ skus/                    # 50 个 SKU 的输入（主数据 + 实拍图引用）
├─ expected/
│  ├─ pdd/<sku>/copy.json   # 期望要点、禁词、事实字段
│  ├─ pdd/<sku>/image.json  # 尺寸/比例/水印/AIGC 标识/EXIF
│  ├─ pdd/<sku>/size.json   # 尺码表数值与渲染文本
│  └─ 1688/...
├─ negative/                # 应被拦截的样本（成分 99%、缺尺码、禁词）
└─ golden.lock.json         # 版本锁：数据集哈希 + 规则版本 + 提示词版本
```

### 7.2 评分规则

| 产出 | 硬断言（必须 100%） | 软指标（阈值） |
|---|---|---|
| 文案 | 价格/库存/成分/尺码/政策字段与主数据**逐字一致**；无禁词；无平台违禁承诺 | L1 规则通过率 100%；L2 与人工标注一致率 ≥90%；标题长度在平台区间 |
| 图片 | 格式/尺寸/比例/大小符合平台规范；AIGC 标识存在；EXIF 清理；数量正确 | 抽检合格率 ≥90%；单张成本 ≤预算；生成失败率 <2% |
| 尺码表 | 每个尺码的测量值与 `size_chart` 一致；渲染文本与数据同版本 | 图文一致性 100%（哈希绑定）；可读性抽检 ≥95% |
| 负例 | 必须被拦截，错误码正确 | 误拦率 <2% |

「软指标」不因单次波动失败，但连续两次低于阈值即阻断发布。

### 7.3 维护

- 数据集版本 `golden-v1`、`golden-v2`…；变更需 PR + 至少一名业务评审；
- `golden.lock.json` 记录：数据集 SHA-256、规则集版本、提示词版本、模型路由快照；任一变化必须重跑全量并更新基线；
- 每季度复核一次：替换 10% SKU（避免过拟合），保留旧版用于对比；
- 真实商品数据脱敏：去掉供应商名、成本价、内部备注；图片去掉人脸（未授权模特）。

### 7.4 执行

```bash
pnpm test:golden -- --platform pdd --kind copy     # PR 只跑变更相关子集
pnpm test:golden -- --all                          # 发布前全量
pnpm test:golden -- --update-baseline              # 仅 admin 可执行，需审批
```

报告：`artifacts/<run_id>/golden/report.html` + `report.json`（每条用例的输入哈希、输出、断言结果、模型与成本）。

## 8. 专项测试

### 8.1 不可逆动作：二次确认与登记

| 步骤 | 断言 |
|---|---|
| 发起 C 级操作 | 返回 `irreversible` 警告 + 影响面 + 建议窗口；不产生写 |
| 未二次确认直接执行 | 409 `confirm_required` |
| 二次确认 token 过期/复用 | 401/409；审计记录 |
| 确认人 = 审批人 | 409（C 级要求第三人） |
| 执行成功 | `audit_log.irreversible=true`；自动创建 `compensating_ticket`；工作台显示「已登记」 |
| 执行失败 | 不生成补偿工单；错误可重试且不重复写 |

用例：`tests/special/irreversible.spec.ts`；E2E 覆盖 E2E-05。

### 8.2 消息去重与并发

| 场景 | 断言 |
|---|---|
| 双击发送 | 只产生 1 条平台消息；第二次返回首次结果 |
| 两个 worker 同时处理同一回调 | 只有一个获得锁；另一个幂等命中 |
| 重复回调（3 次） | `message` 只有 1 条；`conversation.last_message_at` 不重复推进 |
| 「发送中」占位 | 占位期间再次发送被拒（409 `sending`） |
| 发送失败后重试 | 允许；但若平台实际已成功，必须能通过「结果未知」核对避免二次发送 |
| 并发 50 条不同会话 | 全部成功；无串会话 |

用例：`tests/special/dedup.spec.ts`、`tests/load/message-concurrency.js`。

### 8.3 剪贴板助手不越界

| 检查 | 通过标准 |
|---|---|
| 实现方式 | 只调用 `navigator.clipboard.writeText` 或等价 API，写入纯文本 |
| 无 DOM 注入 | 不向平台页面注入脚本/样式；无 `content_scripts` |
| 无按键模拟 | 无 `keydown`/`keypress` 合成、无 `Input.dispatchKeyEvent`、无 `sendInput` |
| 无浏览器自动化 | 依赖中无 Playwright/Puppeteer/Selenium；CI 检查 `package.json` |
| 内容安全 | 复制内容经转义，不含平台禁止的外链/联系方式（按规则） |
| 审计 | 每次复制记录 `clipboard.push`（内容哈希、长度、用途），不存全文 |

用例：SEC-38 + `tests/special/clipboard.spec.ts`（静态扫描 + E2E 点击）。

### 8.4 幂等与止损演练

| 演练 | 步骤 | 通过标准 |
|---|---|---|
| 幂等 | 同一 `Idempotency-Key` 连发 5 次发布请求 | 平台只收到 1 次；5 次响应一致 |
| 断点续跑 | 批量 20 条，执行到第 7 条时杀 worker | 重启后从第 8 条继续；前 7 条不重复 |
| 止损 | 模拟 C 级改价后平台驳回/客诉 | 一键下架生效；补偿工单生成；30 分钟内完成 |
| kill switch | 开启后所有写被拒 | 0 笔写成功；解除需双人 |
| 伪回滚拦截 | 对 B/C 级操作调用 `/listings/rollback` | 返回 `irreversible`，不执行覆盖写 |

演练记录模板：`docs/drills/<date>-<scenario>.md`（时间线、命令、结果、问题、整改）。

### 8.5 账实对账

| 检查 | 断言 |
|---|---|
| 订单对账 | 平台订单数/金额 vs 本地，差异逐条可解释 |
| 库存对账 | 平台可售库存 vs 本地，差异分类（同步延迟/超卖/手工改） |
| 商品状态对账 | 平台在线/下架 vs 本地 `listing.status` |
| 差异处理 | 只报告不自动改；人工确认后走写入门修正 |
| 演练 | 人为制造 3 类差异，对账任务必须全部发现并分类正确 |

用例：`tests/special/reconcile.spec.ts` + 每日生产对账报告。

## 10. 静态规则（业务代码禁碰 DSH 存储）

### 10.1 规则清单

| # | 规则 | 实现 | 失败信息 |
|---|---|---|---|
| S1 | 业务代码禁止引用 `.jsonl` | ESLint `no-restricted-syntax` 匹配字符串字面量 `/.jsonl$/` | 指向 `docs/00 §19.1` |
| S2 | 业务代码禁止访问 DSH 存储根 | 匹配 `dsh-data`、`DSH_HOME`、`.credentials.yaml`、`dsh-storage` | 同上 |
| S3 | 禁止 import `@deepseek-ai/dsh-storage-json` | `no-restricted-imports` | 「业务状态只进 Postgres」 |
| S4 | 只有 `packages/db` 能 import `@prisma/client` | dependency-cruiser `forbidden` 规则 | 「业务读路径必须经 repository」 |
| S5 | 只有 `packages/db` 包含 SQL/迁移 | dependency-cruiser + glob 检查 | 同上 |
| S6 | 禁止浏览器自动化依赖 | `package.json` 扫描 + `check:boundaries` | 「不碰 Playwright/Puppeteer/Selenium」 |
| S7 | 禁止把密钥写入源码/配置模板 | gitleaks + 自定义正则（`sk-`、`AKID`、`app_secret=`） | 「凭据只进 credential_ref/DSH」 |

### 10.2 ESLint 片段

```js
// eslint.config.js（节选，实际放 packages/eslint-config）
export default [{
  files: ['apps/**/*.{ts,tsx}', 'packages/{core,registry,adapters-pdd,adapters-1688,judge-rules}/**/*.ts'],
  ignores: ['packages/db/**', '**/*.test.ts', 'tests/**'],
  rules: {
    'no-restricted-syntax': ['error',
      { selector: "Literal[value=/\\.jsonl$/]", message: '业务代码禁止引用 .jsonl（docs/00 §19.1）' },
      { selector: "Literal[value=/dsh-data|DSH_HOME|\\.credentials\\.yaml/]", message: '禁止访问 DSH 存储根或凭据文件' },
      { selector: "Literal[value=/dsh-storage/]", message: 'DSH 原生存储不承载业务数据' },
    ],
    'no-restricted-imports': ['error', {
      paths: [{ name: '@deepseek-ai/dsh-storage-json', message: '业务状态只进 Postgres' }],
      patterns: [{ group: ['**/dsh-data/**'], message: '禁止业务代码读 DSH 目录' }],
    }],
  },
}];
```

### 10.3 边界脚本

```bash
# scripts/check-boundaries.mjs（CI 调用）
# 1) 扫描 apps/** 与 packages/{core,registry,adapters-*,judge-rules}/**
# 2) 命中以下任一即退出 1：
#    - 字符串包含 ".jsonl" / "dsh-data" / "DSH_HOME" / ".credentials.yaml"
#    - 出现 "dsh-storage-json" import
#    - 出现 "playwright|puppeteer|selenium" 依赖
# 3) 允许列表（显式）：tests/**、scripts/debug/**、packages/db/**
pnpm check:boundaries
```

### 10.4 运行时探针（防绕过）

- 生产构建注入 `__BOUNDARY_PROBE__`：在 `fs.readFile/open` 包装层记录对 `dsh-data` 的访问，启动 10 分钟后自检并上报；
- 若业务请求触发 DSH 目录读取，告警 `boundary.violation`（这属于事故，不是警告）；
- 每周抽样核对：业务读路径 100% 来自 Postgres（对应总纲验收指标「双写漂移」）。
