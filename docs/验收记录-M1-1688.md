1. **领域模型已可执行、可复用**：`PriceTiersV1` 的 6 条 x-rules（档位连续、不重叠、不留空档、`min_qty` 严格递增、`price_cents` 单调不增、首档 = 起批量、末档开放）全部落成代码与错误码，区间价由档位推导（`computePriceRange`），按量取价（`resolveTierPrice`）不会在低于起批量时"悄悄按首档算"。

## 5. 领域规则与错误码（可执行口径）

### 5.1 阶梯价 / 起批价 / 区间价

| 规则（docs/06 §6.4 x-rules + docs/02 H2） | 错误码 | 反例测试 |
|---|---|---|
| 1–5 档，不允许空 | `PRICE_TIER_COUNT` | 空数组、6 档 |
| `min_qty` 严格递增、不重复 | `PRICE_TIER_ORDER` | 10 → 10 |
| `price_cents` 单调不增（可持平） | `PRICE_TIER_MONOTONIC` | 15000 → 15800 |
| 区间不重叠 | `PRICE_TIER_OVERLAP` | 2–49 / 40–∞ |
| 区间不留空档 | `PRICE_TIER_GAP` | 2–49 / 60–∞ |
| 非末档必须闭合、末档必须开放 | `PRICE_TIER_OPEN_END` / `PRICE_TIER_CLOSED_LAST` | 首档 null；末档 99 |
| 首档 `min_qty == min_order_qty` | `PRICE_TIER_FIRST_MOQ` | 起批 5 / 首档 2 |
| 金额与数量为整数 | `PRICE_TIER_PRICE` / `PRICE_TIER_MIN_QTY` / `PRICE_TIER_MAX_QTY` | 12.5 分、`"50"`、max<min |
| 低于起批量不按首档计价 | `PRICE_TIER_BELOW_MOQ` | 起批 2，下单 1 |

区间价：`min=末档价`、`max=首档价`；持平只显示单价。指纹 `priceTiersDigest()` 用于幂等键与包哈希。

## 6. 客户端骨架：安全默认值与管线

```
plan(op)    → 缺口列表（field → TODO id）+ 参数摘要；不触网
execute(op) → 注册表校验 → 令牌桶 acquire → [重试循环: 签名 → transport → 留档 → 解析/错误分类]
```

| 能力 | 实现 | 证据 |
|---|---|---|
| 注册表桩 | 27 个操作；`method/httpMethod/path/paramsIn/bodyFormat/signatureRequired = null`；级别来自 docs/11 §6.2（`listing.create` B、`listing.update_price` C、`inquiry.quote` C…） | `test/client.test.ts` 第 1 条 |

| 签名端口 | `RequestSigner { id, verified, sign() }`；默认 `UNVERIFIED_SIGNER`；未核验签名器被客户端二次拒绝 | 第 15 条 |

## 10. 对下游的接口承诺

- `buildListingPackage(input)`：纯函数、无 I/O，永不抛错（问题在 `checks`）；输出含 `packageHash`，可直接进 `listing_snapshot`/审批 `target_hash`；
- `validatePriceTiers()` / `resolveTierPrice()` / `computePriceRange()`：写入门与报价单（`POST /inquiries/:id/quote` 的 `price_tiers`）可复用，错误结构为 docs/19 §10 的 `{code, field, expected, actual, hint}`；
- `plan()`：给前端"为什么不能发"的稳定数据（缺口 → TODO id → 文档章节）；
- `execute()`：唯一出口；契约未核验时抛 `CONTRACT_NOT_VERIFIED`，写入门应把它映射为 `409 conflict`/`blocked` 并展示 TODO 列表，而不是 `500`。
