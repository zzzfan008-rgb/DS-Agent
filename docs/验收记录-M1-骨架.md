### 5.2 Prisma 6.19.3 能力边界（必须在文档中留痕的实现差异）

| # | docs/06 要求 | 本实现 | 原因 / 补偿 |
|---|---|---|---|
| B1 | `users.email citext` | `text` + 唯一索引 `uq_users_email (org_id, lower(email)) WHERE archived_at IS NULL` | Prisma 不支持 `@db.Citext`（实测 validate 报错）；语义等价：大小写不敏感唯一 |
| B2 | `audit_log.ip inet` | `text` + `ck_audit_ip_format` 正则 | Prisma 不支持 `@db.Inet`；格式校验弱于 inet 类型，写入门/接口层再校验 |
| B3 | 表间关系 | Prisma schema **不声明 relation**；全部外键在 SQL（`fk_<表>_<列>`） | 06 的唯一性/索引大量是部分唯一索引，Prisma 无法表达；声明 relation 会额外生成非部分唯一/命名不符的约束 |
| B4 | 枚举 `text + CHECK` | Prisma 侧全用 `String`；CHECK 在迁移 | Prisma enum 会生成原生 ENUM，与 §0.5 决策冲突 |
| B5 | 触发器 / HNSW / GIN / 部分唯一索引 | 全部手工 SQL（migration.sql 后半段） | Prisma schema 无法表达 |
| B6 | 迁移可回滚（up.sql + down.sql） | 提供 `down.sql`，但 Prisma 只执行 `migration.sql` | Prisma 无 down 机制；回滚按 `docs/20 §6` 备份/恢复执行 |

### 5.4 迁移漂移说明（重要）

`prisma migrate diff --from-migrations … --to-schema-datamodel … --exit-code` 当前固定返回 2，输出约 200 行「Removed index/foreign key」。这**不是**数据库漂移：移除项全部是本迁移手工创建的 CHECK/部分唯一索引/外键/触发器（Prisma 不感知）。CI 的漂移检查必须按 `docs/06 §0.9` 做白名单过滤，或只对「Prisma 生成的表列」做 diff。

## 6. 已知限制与后续

1. **api/worker 镜像**：compose 已声明 `--profile app` 与 `dsh-data` 卷；镜像与 Dockerfile 由后续任务构建后接上。
2. **备份脚本**：卷矩阵、备份矩阵已定（`docs/20`），`scripts/` 下备份/恢复脚本在后续任务落地；M1 只保证 `dsh-data` 在卷内。
3. **Prisma Client relation**：当前无 `include` 能力；t2 起如需关系查询，建议用显式 join 或只读视图，避免改动 FK 命名。
4. **枚举词表双写**：DB CHECK 是兜底，应用层（zod / `packages/core` JSON Schema）仍是第一道校验；t2 应从 `docs/06 §2` 生成一份共享词表，避免两套。
5. **`prisma migrate dev` 禁用**：共享库一律 `migrate deploy`；本地需要 `dev` 时先备份并接受它生成「删除手工索引」的迁移（不允许提交）。
6. **测试库**：本验收使用一次性 `pgvector/pgvector:pg16` 容器（端口 55433），验证后已删除；开发库仍按 `.env.example` 的 5432。
