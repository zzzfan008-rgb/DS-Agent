## 8. t11 默认值修补（2026-10-20）

### 8.1 缺陷

QA 静态门禁发现：`workflow_run.state` 的 DEFAULT 写成了 `'queued'`，而 `docs/21` §2 的 7 态词表是
`pending | running | waiting_human | succeeded | failed_retryable | failed_permanent | cancelled`，
迁移里的 `ck_workflow_state` 只允许这 7 个值。后果：任何省略 `state` 的 INSERT 必然违反 CHECK（t2 一插入就炸）。

根因：t1 第一版 schema 沿用 `docs/06` §3.5 的旧状态机默认值（`queued`），按 `docs/21` 改 `state` 词表时只改了 CHECK，漏改 DEFAULT。

### 8.2 修改点

| 文件 | 行 | 修改前 | 修改后 |
|---|---|---|---|
| `packages/db/prisma/schema.prisma` | 776 | `state String @default("queued")` | `state String @default("pending")` |
| `packages/db/prisma/migrations/20261020142000_init/migration.sql` | 721 | `"state" TEXT NOT NULL DEFAULT 'queued'` | `"state" TEXT NOT NULL DEFAULT 'pending'` |

**为什么直接改原迁移而不新增 ALTER**：该迁移只在 t1 验收时的一次性 `pgvector/pgvector:pg16` 容器上执行过（容器已删除）；
本机 `localhost:5432` 的 Postgres 认证失败、并非本项目库；没有共享/开发库执行过本迁移。
因此直接改原文件，避免「迁移历史 + schema」两处不一致；若后续任一环境已执行过该迁移，应改为新增 `ALTER TABLE ... ALTER COLUMN ... SET DEFAULT`。
