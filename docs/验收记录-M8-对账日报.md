## 2. 同步游标（`sync_cursor`）

### 2.1 使用的列（docs/06 §4.5.2 / Prisma `SyncCursor`）

| 列 | 用途 |
|---|---|
| `platform` / `shop_id` / `resource` | 唯一键 `(org_id, platform, shop_id, resource)`；resource ∈ `products/orders/messages/after_sale/stock` |
| `cursor` | 平台游标（录制样本为 `ck-orders-1/2`，仅验证机制） |
| `watermark_at` | 已消费水位 |
| `last_run_at` / `last_success_at` | 运行/成功时间；`GET /sync/status` 的 `lag_seconds` 依据 |
| `consecutive_failures` / `status` / `error_code` | 连续失败 ≥5 → `status='error'`（docs/06 要求） |
| `lease_owner` / `lease_until` | 单实例消费（抢占式租约，防并发重复跑） |
| `stats` | `{pulled, created, updated, skipped}`；本轮只填 `pulled`（不写业务表） |
| `page_size` | 每页条数（默认 100） |

### 2.2 行为

- **断点续跑**：每读完一页立即 `checkpoint(cursor, watermark_at, stats)`；进程中断后下一次从 `cursor` 继续。
- **并发**：`tryAcquire` 用 `UPDATE ... WHERE lease_until IS NULL OR lease_until < now()` 抢占；拿不到租约返回 `409 conflict`（docs/12 §3.9）。
- **失败**：记录 `error_code`、`consecutive_failures+1`、释放租约；保留最后成功游标。
- **只读**：reader 返回 `{items, nextCursor, hasMore, watermarkAt}`，服务**不写**任何业务表（orders/after_sale 表由 t37 补建）。
- **真实 reader 硬拒绝**：`RECONCILE_READER/SYNC_READER=adapter` 时抛 `publish_blocked`（409），detail 带 `reason=adapter_contract_unverified` 与 TODO 列表（1688：`TODO-1688-*`；PDD：`TODO-PDD-CONTRACT-VERIFY`）。

### 2.3 验证输出（测试节选）

`apps/api/test/reconcile.test.ts` 中断言：
- 第一轮 `pages=1, pulled=2, cursor=ck-orders-1`；
- 第二轮 `resumed_from=ck-orders-1, pulled=1, cursor=ck-orders-2`；
- 第三轮 `pulled=0`（已到末尾，不重复拉取）；
- 并发跑第二次 → `ApiError('conflict')`；
- adapter reader 连续失败 5 次 → `consecutive_failures=5, status='error', errorCode='publish_blocked'`；
- 端点：`POST /api/sync/1688 {resource:"orders"}` → `202`，`pages=2, pulled=3, cursor=ck-orders-2`；`GET /api/sync/status?platform=1688` → `store:"postgres"`、`orders` 状态 `idle`、`cursor=ck-orders-2`。

## 4. 存储：`drift_log` 缺失与 `drift_key` 规则（t37 交接）

### 4.1 现状

- docs/18 §4、docs/20 §7 要求"对账漂移写 `drift_log`"，但 `docs/06` 未定义该表、t1 迁移未建（实测 `select to_regclass('public.drift_log')` 返回 `t`=缺失，即 NULL）；
- 任务约束"不改 schema"，故实现 `DriftStore` 端口：
  - `PgDriftStore`：真实 SQL（`INSERT ... ON CONFLICT (org_id, day, platform, drift_key) DO UPDATE` + `xmax=0` 区分插入/更新 + `to_regclass` 探测）；
  - `FileDriftStore`：`<RECONCILE_DIR>/<day>/<platform>.json`，原子写（tmp+rename），同 key 合并；
  - `auto`：探测 `drift_log`，有则 PG，无则文件，并在响应 `store_note` 说明原因。

### 4.2 建议 DDL（未执行；t37 可原样采用）

```sql
CREATE TABLE drift_log (
  id uuid PRIMARY KEY,                       -- 应用侧 uuid v7（不依赖 DB 扩展）
  org_id bigint NOT NULL DEFAULT 1,
  platform text NOT NULL CHECK (platform IN ('pdd','1688')),
  day date NOT NULL,                         -- Asia/Shanghai 业务日
  drift_key text NOT NULL CHECK (char_length(drift_key) = 35),
  kind text NOT NULL CHECK (kind IN (
    'platform_only_listing','local_published_missing_platform',
    'local_published_platform_offline','price_mismatch','stock_mismatch','state_mismatch')),
  severity text NOT NULL CHECK (severity IN ('low','medium','high')),
  subject jsonb NOT NULL DEFAULT '{}',       -- {type,listing_id,platform_item_id,sku_id,platform_sku_id}
  local_value jsonb,                          -- 本地侧取值（价格/库存/状态等）
  platform_value jsonb,                       -- 平台侧取值
  detail text NOT NULL,
  suggestion jsonb NOT NULL DEFAULT '{}',     -- {summary,actions[],doc_refs[],auto_fixable:false}
  status text NOT NULL DEFAULT 'open' CHECK (status IN ('open','fixed','ignored')),
  first_detected_at timestamptz NOT NULL,
  last_detected_at timestamptz NOT NULL,
  seen_count integer NOT NULL DEFAULT 1 CHECK (seen_count >= 1),
  detected_at timestamptz NOT NULL,
  fixed_at timestamptz,                       -- docs/18 §4 的 fixed_at（本轮不写）
  resolution text,                            -- 人工处置说明（后续）
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),

CREATE INDEX ix_drift_day_platform ON drift_log (day, platform, kind);
```

### 4.3 我的代码实际依赖的字段

| 字段 | 读/写 | 说明 |
|---|---|---|
| `id, org_id, platform, day, drift_key, kind, severity, subject, local_value, platform_value, detail, suggestion, status, first_detected_at, last_detected_at, seen_count, detected_at, updated_at` | 写 | INSERT 必填（`status` 恒 `open`；`updated_at` 由 DB/更新语句维护） |
| `org_id, day, platform, drift_key, kind` | 读 | `list/count/countByKind` 过滤；`countByKind` 按 `kind` 分组 |
| `first_detected_at, last_detected_at, seen_count` | 读 | 验收"重复对账不新增"的判据 |
| `fixed_at, resolution` | 未用 | 建议保留，供后续关闭差异/复盘 |

### 4.4 `drift_key` 构造规则（**t37 及后续模块必须遵守**）

```
drift_key = 'dk_' + hex( sha256( platform + '|' + kind + '|' + listing_id + '|' + platform_item_id + '|' + platform_sku_id ) ).slice(0, 32)
```

- **参与字段（5 个，顺序固定）**：`platform`、`kind`、`listing_id`、`platform_item_id`、`platform_sku_id`；
- **空值处理**：`null` / `undefined` 以**空串**参与，不做占位符；
- **不参与**：`day`（存储维度，唯一键里单列）、`org_id`（唯一键里单列）、`severity`、`detail`、价格/库存取值；
  → 因此"价格从 14900 变 14950"仍是同一条差异（更新而非新增），这是刻意设计（差异是"某对象某类不一致"，不是"某次取值"）；
- **唯一作用域**：`(org_id, day, platform, drift_key)`；同一对象同一类差异每天最多一行；
- **稳定性**：`kind` 或参与字段口径变更 = 键规则变更，必须升版本并在文档登记（否则历史去重语义断裂）；
- 当前长度固定 35（`dk_` + 32 hex），DDL 里有 `CHECK (char_length(drift_key)=35)`。

口径（全部 `Asia/Shanghai` 业务日）：
- `listed`：当日 `listing.published_at` 落点数；
- `rejected`：当日 `updated_at` 且 `status='rejected'`；
- `approvals_pending`：**当前** `status='pending'`（积压是"现在"）；`approvals_oldest_minutes` 为最老待审批等待分钟数；
- `messages`：当日新建 message；
- `media_cost_cents`：当日 `cost_ledger`（`kind='media'`, `ref_type='media_job'`）合计，**无平台列 → `media_cost_scope=global`**；
- `drift_total` / `drift_by_kind`：对账存储（文件或 `drift_log`）。

### 5.2 阈值配置（不写死数字）

`DAILY_ALERT_THRESHOLDS`（JSON，zod strict）：

```json
{ "drift_total": 5, "drift_by_kind": { "price_mismatch": 1 }, "approvals_pending": 20,
  "rejected_listings": 3, "messages": 500, "media_cost_cents": 50000 }
```

- 未配置 / 空串 → `thresholds_configured=false`，`alerts=[]`（只报事实）；
- 非法 JSON、未知键（如 `drfit_total`）、负数 → 启动即 `ConfigError`（fail fast）；
- 触发条件 `value > threshold`（等于阈值不告警）；
- 级别：`drift_total / drift_by_kind.* / approvals_pending / rejected_listings` → P2；`messages / media_cost_cents` → P3。
