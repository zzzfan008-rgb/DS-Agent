## 2. 端点（docs/12 §3.10 对齐）

| 端点 | 角色 | 行为 |
|---|---|---|
| `POST /api/kb/documents` | operator+ | multipart（`file` + `title` + `domain` + 可选 `effective_at/source_ref/source_type/doc_type`）或 JSON（`content`/`content_base64` 兜底）；解析→切片→embedding→写 kb_document/kb_chunk；同 `source_ref + checksum` 幂等返回既有文档（200）；内容变化新建版本（201） |

| `GET /api/kb/search` | viewer+ | `q*, k?=10, domain?, source_type?, platform?, as_of?, filters?`；混合召回 + RRF；每条 hit 带 citation，响应带 `evidence_refs/degraded/degrade_reason/mode/took_ms` |

## 3. 入库管线（实现口径）

| 阶段 | 实现 |
|---|---|
| 解析 | Markdown 按 `#` 标题树、段落、列表、表格；txt 按空行分段；PDF 用 `node:zlib` + PDF 文本操作符（`Tj/TJ/'/"`）抽取文本层，扫描件/无 ToUnicode 字体报 `pdf_no_text_layer`（见 L6） |
| 清洗 | CRLF→LF、去页码行、行尾空白、3+ 空行压缩；不改写/纠正/摘要（docs/09 §4.3） |
| checksum | `sha256(normalizedText)`；同 `source_ref` 且 checksum 相同 → 幂等；不同 → `version_no+1`，旧版本 `superseded`（不删） |
| 切片 | 目标 450 字、硬上限 800、软下限 80、重叠 15%≤120 字（句子边界）；表格/列表按行、不重叠；FAQ `Q:/A:` 识别为 `qa`；表格 `table`、列表 `list`、其余 `text`；`section_path` 取标题层级（≤6）；同内容去重 |
| 元数据 | `metadata={source_type,domain,source_ref,section_path,effective_from,effective_to,lang,parser_version,advisory}`；`content_hash`、`content_tokens`（1.6 字/token 估算）；`advisory` 仅 copy 域 |
| 嵌入 | `gateway.invoke({purpose:'embed', params:{inputs:[header+content],dim:1024}, estimate:{tokensIn}})`；校验数量/维度=1024、L2 归一化、拒零向量；批量入库；失败不阻塞文档（`index_status='stale'`，chunks 无 embedding） |
| 引用文本 | 每个 chunk 的 embedding input = `[《title》 v{version} · section_path]` + content；引用 quote 用原始 content（docs/09 §5.5 分离） |

### schema 映射（关键偏差）

`kb_document` **没有** `source_ref` 列（schema 只有 `source_id uuid` / `uri text` / `checksum`）：

- `source_ref` → `uri`（原样保存，便于检索/审计）；
- `source_id = uuidv5("kb:" + source_type + ":" + source_ref)`（稳定 UUID，复用 `uq_kb_doc_active` 做版本/幂等）；
- 内容指纹 `checksum = sha256(normalizedText)`。
  → 未改 schema；若后续增列 `source_ref`，迁移只需回填 `uri`，应用层可平滑切换。

## 4. 检索（混合召回 + 引用 + 降级）

### 4.1 两路召回

| 路 | 实现 | 候选 |
|---|---|---|
| 向量 | `gateway.invoke(purpose='embed')` 得查询向量；`ORDER BY c.embedding <=> $q::vector`；`SET LOCAL hnsw.ef_search=100`；过滤 `status='active' / archived_at IS NULL / effective_from<=as_of / acl_roles && role` | 40 |
| 关键词 | 应用侧中文分词（单字+bigram）→ `to_tsvector('simple', tokens)` 的 `tsv` GIN；查询 `to_tsquery('simple', token1|token2…)` + `ts_rank_cd`；辅以 `content ILIKE`（raw/词）召回 | 40 |

BM25 说明：Postgres 无内置 BM25，本实现用 **`ts_rank_cd` 覆盖密度近似**（docs/09 §8.1 默认档），
未启用应用侧真 BM25（L5）。

### 4.2 融合（RRF，参数写死并可复算）

```text
score(d) = w_vec/(60 + rank_vec(d)) + w_kw/(60 + rank_kw(d))
w_vec = 1.0, w_kw = 0.8, k = 60
```

- 同 chunk 在两路出现则相加；按 `content_hash` 去重（保留最高分）；
- 取 top-k（默认 10，最大 50）；
- 任一路不可用只影响召回质量，不影响引用完整性。

### 4.3 引用（CitationV1）

每条 hit 必带：

```json
{
  "doc_id": "…", "chunk_id": "…", "doc_version": 1,
  "quote": "content 的连续子串（≤200 字，句边界对齐）",
  "effective_from": "2026-10-20T…Z",
  "title": "…", "source_type": "policy", "section_path": ["…"], "score": 0.0293, "uri": "policy://…"
}
```

- `quote` 由服务端从 `kb_chunk.content` 截取并校验 `content.includes(quote)`；测试逐条断言；
- `evidence_refs` 排除 `advisory=true`（copy/manual 不作为事实证据，docs/09 §8.4）；
- 无命中也返回 `degraded:true, degrade_reason:'no_citation'`，不返回无引用内容。

### 4.4 降级（docs/09 §11）

| 场景 | 行为 |
|---|---|
| embed 路由不可用/调用失败 | 跳过向量路，纯关键词，`degraded=true, degrade_reason='embed_unavailable'` |
| 向量列全空 / 查询向量为零 | 纯关键词，`degraded=true, degrade_reason='no_vector'` |
| 无命中 | `degraded=true, degrade_reason='no_citation'` |
| 数据库不可用 | 查询直接失败（5xx），不返回猜测内容 |

检索落 `kb_query_log`（purpose/mode/hit_count/hits/citations/degraded/degrade_reason/latency），
失败仅记 warning，不影响响应。

## 6. 偏差与已知限制（需评审知悉）

**D1（schema 缺字段，未改 schema）`kb_document` 无 `source_ref` 列。**
按任务“不改 schema（缺字段报我）”要求，未新增列；`source_ref` 存 `uri`，并派生稳定
`source_id = uuidv5(...)` 复用现有唯一索引。若后续允许加列，可回填并切换。

**D2（schema 枚举限制）`model_call_log.subject_type` 不含 `kb_document`。**
现有 CHECK 只允许 `content_draft/judgment/media_job/workflow_run/kb_query/conversation/other`；
embedding 入库调用暂用 `subject_type='other'`，`subject_id` 仍可空/文档 id。建议后续迁移增加
`kb_document`（不改本次 schema）。

**D3 嵌入调用使用 admin 系统主体。**
registry 策略规定 operator 不能使用 embed（docs/07；t7 测试已锁定），但知识入库路由对
operator 开放；KnowledgeEmbedder 以 admin 角色调用网关、`actorType=system`，业务上传权限仍由
路由 `minRole=operator` 控制。审计里同时保留真实上传者（`kb.document_ingest.actorId`）。

**D4 mock embedding 不是语义模型。**
`provider.extra.mock=true` 时返回确定性 1024 维向量（概念词典 + 中文 bigram + sha256 投影），
用于管线与同义召回的**可重复**验证；生产必须在模型管理页配置真实 `embedding` provider/model
（`embed_dim=1024`），并用 docs/09 §14 测试集验收。真实 adapter 仍待 M6（当前 registry 对
非 text provider 默认 mock）。

**D5 BM25 为近似。**
关键词路用 `ts_rank_cd`（覆盖密度）而不是真 BM25；docs/09 §8.1 允许的默认档。真 BM25（k1=1.2,
b=0.75, avgdl）未启用，候选窗 ≤200 的可选优化留待后续。

**D6 PDF 抽取限于文本层。**
自实现 `node:zlib` + PDF 文本操作符抽取，不引入 pdfjs；扫描件、加密 PDF、无 ToUnicode 的
CJK 字体可能得到空文本/乱码，按 `pdf_no_text_layer`/`pdf_encrypted` 拒绝并提示 OCR。
生产 PDF 若无文本层，应走 OCR（M6 媒体管线）。

**D7 切片为工程近似。**
未使用 tiktoken（docs/09 §5.3 提过）；按 1.6 字/token 估算，目标 450/上限 800/重叠 15%。
表格/列表按行切、不重叠；跨 section 不合并。真实 token 计费以 embed provider 返回为准。

**D8 无 rerank。**
docs/09 §9 的可选 rerank 未实现；RRF 已满足 M7 验收。rerank 失败降级（D5）留待 M7+。

**D9 `POST /kb/reindex` 未实现。**
docs/12 §3.10 列了该端点，但本任务范围只要求入库/列表/删除/检索；重嵌入/重建索引留待后续
（当前可通过重新上传生成新版本或直接更新 embedding 实现离线重建）。

**D10 全 workspace typecheck 的 Prisma EPERM。**
并发任务占用 Prisma engine DLL 导致 `@dssaas/db` 的 `prisma generate` 失败；`@dssaas/api` 与
本次改动类型检查通过，属于环境瞬时问题。

**D11 advisory 过滤与证据域。**
search 端点默认返回 copy/manual 的 advisory 命中（附引用与 `advisory:true`），但
`evidence_refs` 与 `resolveEvidence` 一律排除；copy 域的 acl 仅 operator/admin。

**D12 检索日志 best-effort。**
`kb_query_log` 写失败只记日志、不影响检索；`query` 截断 500 字符（DB CHECK）。监控告警待 M9。

**D13 PDF/JSON 兜底上传。**
multipart 为主（docs/12）；JSON `content`/`content_base64` 是测试/客户端便利路径，同样受
5MB 限制与校验。
