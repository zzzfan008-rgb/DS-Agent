## 0. 目标与四条不变量

知识库只做一件事：**让判断层与客服在回答时能拿到「可追溯、有版本、有生效期」的原文片段**。它不是搜索引擎，也不是"让模型自由发挥"的上下文池。

| # | 不变量 | 违反后果 |
|---|---|---|
| K1 | 检索结果必须带引用（`doc_id + chunk_id + doc_version + effective_from`）；无引用即视为无证据 | 判断层直接升级人工（`08` §8 E1） |
| K2 | 写入知识库的内容**不得由模型改写**；解析器只做结构与空白整理，正文逐字保留 | 事实漂移，无法溯源 |
| K3 | 尺码表与面料成分是**同源同版本**：`kb_document.version_no == size_chart.version_no`，`checksum` 一致 | 客服口径与平台数据不一致（`00` §11 明确要求） |
| K4 | 过期（`effective_to < now()`）或非 `active` 的文档切片**永不出现在结果里**，且过期命中率必须为 0 | 用旧政策答复，客诉与赔付 |

## 1. 术语

| 术语 | 含义 |
|---|---|
| 文档（document） | 一个知识条目（商品规格、尺码表、政策条款…），带 `version_no` 与生效期 |
| 切片（chunk） | 文档内可独立引用的最小单元；一行 = 一个切片 |
| 证据（evidence） | 被判断层/客服引用并逐字摘录的切片 |
| 权威级 A/B/C | A=主数据派生；B=政策/平台规则；C=文案样例（仅风格参考） |
| 分域（domain） | `product`/`size`/`fabric`/`policy`/`platform`/`copy`/`service`，决定权限与可用性 |
| 降级 | 向量不可用或超时时退化为纯关键词，并显式标记低置信 |

## 3. 文档源清单与责任人

责任人均需落到具体人（`kb_document.owner_user_id`），角色字段用于兜底与交接。

| # | `source_type` | `domain` | 权威级 | 内容示例 | 责任人（角色） | 更新触发 | 复核周期 |
|---|---|---|---|---|---|---|---|
| 1 | `product` | `product` | A | 商品规格、卖点口径、属性值、适用场景 | 商品运营 `operator` | `product.fact_version` 变更 | 90 天 |
| 2 | `size_chart` | `size` | A | 尺码表（每码一行）、建议身高体重、版型说明 | 版师/商品开发 `operator` | `size_chart` 新 effective 版本 | 随版本 |
| 3 | `fabric` | `fabric` | A | 面料成分、克重、工艺、洗护要点 | 商品开发 `operator` | `fabric_composition` 新版本 | 180 天 |
| 4 | `policy` | `policy` | B | 退换货、运费、售后时效、保修 | 客服主管 `operator`（变更需 `admin` 审） | 政策调整/平台规则变更 | 90 天（硬到期） |
| 5 | `platform_rule` | `platform` | B | 类目规则摘要、标题/图片规范、违禁词说明（人工摘录 + 原文链接） | 平台运营 `admin` | 平台公告 | 30 天 |
| 6 | `faq` | `service` | B | 常见问答（客服口径）、尺码/洗护/物流答复模板 | 客服主管 `operator` | 客诉复盘、政策变更 | 90 天 |
| 7 | `copy_sample` | `copy` | C | 历史优质文案、爆款标题、场景描述 | 内容运营 `operator` | 上新与复盘 | 180 天 |
| 8 | `care` | `fabric` | A | 洗护说明（水洗/漂白/熨烫/干洗/干燥代码 + 话术） | 商品开发 `operator` | 供应商资料更新 | 180 天 |
| 9 | `manual` | `service` | C | 内部 SOP、培训材料、话术库 | 运营负责人 `admin` | 流程变更 | 180 天 |

规则：

1. **每个源必须指定责任人**（`owner_user_id`），未指定不得发布（`status='draft'` 且不可检索）。
2. **权威级 C 的文档不得作为事实证据**（§8.4）：`copy`/`manual` 域的切片可以被召回给"文案风格参考"，但**不能进入 `judgment.evidence_refs`**；编号 4/5（政策与平台规则）必须带原文链接或公告编号。
3. 平台规则只能是**人工摘录**，禁止让模型总结平台文档后直接入库（摘要可另存为 `manual` 且标 C 级）。
4. 涉及客户隐私的会话内容须脱敏后才能进 `faq`（不得出现买家昵称、订单号、手机号）。

## 4. 解析规则

### 4.1 输入类型与解析器

| 类型 | 解析器 | 输出 | 备注 |
|---|---|---|---|
| Markdown / txt | `unified`（remark） | 标题树 + 段落 + 表格 + 列表 | 首选格式，结构最完整 |
| docx | `mammoth` → HTML → 统一中间态 | 同上 | 保留标题层级；批注丢弃 |
| pdf（文本层） | `pdfjs-dist` | 标题启发式 + 段落 | 扫描件先判定有无文本层 |
| pdf（扫描件） | OCR（`tesseract` + 中文包） | 段落 | 结果标 `parser=ocr@x` 且 `metadata.ocr=true`，权威级降一档（A→B），需人工抽检 |
| csv / xlsx | `SheetJS` | 表格块（每 sheet 一组） | 首行作表头；空列丢弃 |
| 结构化主数据 | 直接渲染（`size_chart`→Markdown 表；`fabric_composition`→列表） | 文本 + 表格 | **唯一允许程序生成的正文**（非模型改写） |
| 网页摘录 | 人工粘贴 + 来源 URL | 段落 | 必须登记 `uri` 与抓取日期 |

### 4.2 解析产物（中间态）

```ts
interface ParsedDoc {
  title: string;
  blocks: Array<
    | { kind: 'heading'; level: 1 | 2 | 3 | 4; text: string }
    | { kind: 'paragraph'; text: string }
    | { kind: 'list'; ordered: boolean; items: string[] }
    | { kind: 'table'; header: string[]; rows: string[][]; caption?: string }
  >;
  links: string[];
  checksum: string;      // sha256(原始文件) 或 sha256(渲染文本)
  parserVersion: string;
}
```

### 4.3 清洗规则（只做结构，不改语义）

| 动作 | 规则 |
|---|---|
| 去页眉页脚 | 连续出现在 ≥80% 页面的短行（≤30 字）判为页眉页脚 |
| 去页码 | `^\s*[-—]?\s*\d+\s*[-—]?\s*$` |
| 去水印文字 | 与正文重叠度高的重复短句（同文档出现 ≥3 次且 <10 字） |
| 空白规范化 | 连续空白→单空格；中文之间不加空格；保留段落边界 |
| 编码 | 统一 UTF-8；乱码率 >2% 直接失败（`index_status='failed'`） |
| 禁止 | 不改写措辞、不纠正错别字、不补全缺失数字、不摘要（摘要属新文档，须标 C 级） |

### 4.4 版本与幂等

- `kb_document.checksum = sha256(parsedNormalizedText)`；相同 checksum 重复上传 → 直接返回既有版本，不新建（幂等）。
- checksum 变化 → **新建 `version_no = max+1`**，旧版本 `status='superseded'`（不删，保留引用可追溯）。
- `parser_version` 变化不自动重建；需人工触发 `POST /kb/reindex`（解析器升级可能改变切片边界，属评审项）。

## 5. 切片规则

### 5.1 三条原则

1. **可独立引用**：一个切片拿出去必须能读懂，不依赖上一条（避免"该尺码适合 165-172cm"丢了"2XL"）。
2. **不切断语义单元**：数字+单位、成分列表、尺码行、政策条款编号、否定句（"不"不得落在上一片）绝不跨片断开。
3. **元数据可过滤**：SKU、尺码、平台、生效期必须进 `metadata`，让过滤发生在检索前而不是靠语义相似。

### 5.2 按源的切片策略

| `source_type` | 切片单位 | 目标大小 | 重叠 | 特殊规则 |
|---|---|---|---|---|
| `size_chart` | **一个尺码一行一片**（`2XL` 一片） | 80–200 字 | 0（行间独立） | 片头带商品与版本；同片含该码全部部位；`metadata.size_code` 必填 |
| `product` | 小节（标题层级 2） | 350–550 字 | 15% | 属性表按"表头 + ≤12 行/片" |
| `fabric` | 一个面料（`fabric_code`）一片 | 150–400 字 | 10% | 成分列表不拆开；百分比与材料名必须同片 |
| `care` | 一套洗护说明一片 | 120–300 字 | 0 | 代码（水洗 30℃ 等）与解释同片 |
| `policy` | **一条条款一片**（按 1./2./(1) 编号） | 200–500 字 | 0 | 条款编号进 `metadata.clause`；跨条款不合并 |
| `platform_rule` | 一条规则一片 | 200–500 字 | 0 | 必带 `metadata.source_url`、`announcement_date` |
| `faq` | 一问一答一片 | 100–350 字 | 0 | `content` 形如 `Q: …\nA: …`；`chunk_type='qa'` |
| `copy_sample` | 一个完整文案段（标题组/卖点组/详情模块） | 150–400 字 | 0 | 标 `metadata.advisory=true`（不得作事实证据） |
| `manual` | 一个小节 | 300–600 字 | 10% | 标 `metadata.advisory=true` |

### 5.3 大小、重叠与边界参数（配置常量）

```ts
export const CHUNK = {
  targetTokens: [500, 800],   // 中文约 350–550 字
  hardMaxTokens: 1000,        // 约 700 字，超了必须再切
  hardMinTokens: 120,         // 约 80 字，短于此合并到相邻片（政策条款除外）
  overlapRatio: 0.15,         // 相邻重叠，按句边界对齐
  overlapMaxTokens: 120,
  tableRowsPerChunk: 12,      // 表格片最大行数（含表头重复）
  splitOn: ['\\n\\n', '。', '；', '！', '？', '\\n'],  // 优先级从高到低
  forbidSplitInside: ['数字+单位', '尺码码值', '百分比列表', '条款编号', '否定短语'],
} as const;
```

分词与 token 估算：`tiktoken`（cl100k 近似）仅用于**大小控制**，不用于计费；实际计费以 `purpose=embed` 的供应商用量为准。

  "source_type": "size_chart",
  "source_id": "uuid-of-size-chart-row-set",

  "sku_code": "SPU-2026-001-KH-2XL",

`advisory=true` 的切片（`copy`/`manual` 域）在检索结果中照常返回，但**不允许进入 `evidence_refs`**（§8.4）。

### 5.5 嵌入文本与引用文本分离

| 用途 | 内容 | 说明 |
|---|---|---|
| 嵌入输入 | `header + "\n" + content` | `header` 形如 `[商品 SPU-2026-001 · 尺码表 v3 · 2XL]`，让向量带上下文，提升召回 |
| `kb_chunk.content` | **纯正文**（不含 header） | 引用、展示、`quote` 校验只用它 |
| 引用展示 | `header + content + 来源/版本/生效期` | 前端拼装，不落库重复 |

这样避免"为了召回加的头"污染逐字引用（`08` §7.3 要求 `quote` 是 `content` 的连续子串）。

### 5.6 切片示例（尺码表）

`size_chart` v3（2XL 行）→ 1 个切片：

```text
content: 尺码 2XL：衣长 68cm，胸围 104cm，肩宽 46cm，袖长 61cm，腰围 84cm，臀围 98cm，下摆 92cm。建议身高 165–172cm，建议体重 65–72kg。版型：常规。
metadata: { source_type: "size_chart", size_code: "2XL", section_path: ["尺码表","2XL"], effective_from: "2026-09-01T00:00:00Z", ... }
header:   [商品 SPU-2026-001 卡其 2XL · 尺码表 v3 · 生效 2026-09-01]
```

## 6. 嵌入（`purpose=embed`）

### 6.1 模型选择标准

| 标准 | 要求 | 说明 |
|---|---|---|
| 中文语义 | 中文检索评测明显优于通用英文模型 | 用 §14 测试集实测，不靠榜单 |
| 维度 | 固定 1024（与 `kb_chunk.embedding vector(1024)` 一致） | 部署期锁定；换维度走 §7.5 |
| 批量 | 支持 batch ≥ 32 | 影响重建耗时 |
| 上下文 | ≥ 512 token | 切片上限 1000 token，超长切片需截断策略 |
| 成本 | `model.price.embed.input_per_1k` 可接受 | 全量重建成本可估算（§7.5） |
| 稳定性 | 同一 `external_model_id` 输出稳定（无静默换版） | 否则索引不可复现 |
| 可用性 | 支持 `purpose=embed` 的路由且**不降级**（`07` §5.1） | 跨模型向量不可比 |

选型流程：在 `model` 表建 2–3 个候选（`capability='embedding'`、`status='testing'`）→ 用 §14 测试集跑 Recall@8 / nDCG@10 → 取最优且成本可接受者 `publish` → 锁定 `embed_dim`。

### 6.2 索引期流程

```ts
async function embedDocument(docId: string) {
  const doc = await kb.getDocument(docId);              // status='draft'|'active'
  const chunks = await kb.listChunks(docId, doc.versionNo);
  const model = await registry.resolve({ purpose: 'embed' }); // 只接受 capability=embedding

  for (const batch of chunk(chunks, 32)) {
    const inputs = batch.map((c) => `${c.header}\n${c.content}`);
    const res = await gateway.embed({ model, inputs });  // 幂等：content_hash+model 相同则跳过
    for (const [i, c] of batch.entries()) {
      const vec = l2Normalize(res.vectors[i]);           // 归一化后存，cosine 等价点积
      await kb.saveEmbedding(c.id, vec, model.id, res.dim, res.usageTokens);
    }
  }
  await kb.markIndexed(docId, { embedModelId: model.id, chunkCount: chunks.length });
}
```

### 6.3 嵌入侧硬规则

| # | 规则 | 原因 |
|---|---|---|
| E1 | 只走 `purpose=embed`，且该路由**不配置降级** | 混用模型会污染向量空间 |
| E2 | 向量先 L2 归一化再入库；查询向量同样归一化 | cosine 与内积结果一致，减少一次计算 |
| E3 | `embedding_dim` 必须等于 1024，否则拒绝写入 | 维度守卫（`06` §4.9.2） |
| E4 | 每片记录 `embedding_model_id`；同一文档内不允许混模型 | 重建可复现、可逐步迁移 |
| E5 | 幂等键 `(content_hash, embedding_model_id)`；已存在则跳过 | 重跑不重复计费 |
| E6 | 嵌入失败（重试 3 次指数退避）→ `embedding=NULL`、`kb_document.index_status='stale'`、告警；**不写零向量** | 零向量会造成假命中 |
| E7 | 入库前 PII 检测（身份证/银行卡/手机号/地址）；命中则拒绝入库并告警 | 隐私与合规 |
| E8 | 空白/纯符号切片不嵌入（`content_tokens < 20` 直接 `status='disabled'`） | 省成本、减噪声 |

### 6.4 成本

`cost = ceil(totalTokens / 1000 × price.embed.input_per_1k)`（`07` §7.3）；记录到 `model_call_log`（`subject_type='kb_query'` 仅用于查询；索引期为 `other` + `subject_id=doc_id`）。

全量重建估算：`总片数 × 平均片 token ÷ 1000 × 单价`。示例：8 000 片 × 450 token ≈ 3.6M token；若单价 100 micro/1k → 约 3.6×10⁸ micro ≈ 360 元。**重建前必须出估算并由 admin 确认**。

## 7. pgvector 表结构与索引参数

### 7.1 表与向量列（DDL 全文）

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE kb_chunk (
  id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id              bigint NOT NULL DEFAULT 1 CHECK (org_id > 0),
  document_id         uuid NOT NULL REFERENCES kb_document(id) ON DELETE CASCADE,
  version_no          integer NOT NULL CHECK (version_no >= 1),
  seq                 integer NOT NULL CHECK (seq >= 0),
  section_path        text[] NOT NULL DEFAULT '{}',
  chunk_type          text NOT NULL DEFAULT 'text'
                      CHECK (chunk_type IN ('text','table','list','qa','snippet')),
  content             text NOT NULL CHECK (char_length(content) BETWEEN 1 AND 4000),
  content_hash        text NOT NULL CHECK (char_length(content_hash) = 64),
  content_tokens      integer NOT NULL DEFAULT 0 CHECK (content_tokens >= 0),
  embedding           vector(1024),
  embedding_model_id  uuid REFERENCES model(id),
  embedding_dim       smallint CHECK (embedding_dim IS NULL OR embedding_dim = 1024),
  tsv                 tsvector,
  metadata            jsonb NOT NULL DEFAULT '{}'
                      CHECK (jsonb_typeof(metadata) = 'object'),
  acl_roles           text[] NOT NULL,
  effective_from      timestamptz NOT NULL,
  effective_to        timestamptz,
  status              text NOT NULL DEFAULT 'active'
                      CHECK (status IN ('active','superseded','disabled')),
  superseded_by       uuid REFERENCES kb_chunk(id),
  created_at          timestamptz NOT NULL DEFAULT now(),
  archived_at         timestamptz,
  CONSTRAINT uq_chunk UNIQUE (document_id, version_no, seq),
  CONSTRAINT ck_chunk_emb CHECK (
    (embedding IS NULL AND embedding_dim IS NULL)
    OR (embedding IS NOT NULL AND embedding_dim = 1024)
  )
);

CREATE INDEX ix_chunk_doc       ON kb_chunk (document_id, version_no, seq);
CREATE INDEX ix_chunk_active    ON kb_chunk (org_id, status) WHERE status = 'active' AND archived_at IS NULL;
CREATE INDEX ix_chunk_meta      ON kb_chunk USING gin (metadata jsonb_path_ops);
CREATE INDEX ix_chunk_tsv       ON kb_chunk USING gin (tsv);
CREATE INDEX ix_chunk_embedding ON kb_chunk USING hnsw (embedding vector_cosine_ops)
       WITH (m = 16, ef_construction = 64);
```

维度常量 `EMBED_DIM = 1024` 只出现在两处：迁移脚本与 `packages/knowledge/src/config.ts`；两者由 CI 校验一致。

### 7.2 索引参数与理由

| 参数 | 值 | 理由 | 调整触发 |
|---|---|---|---|
| 索引类型 | **HNSW**（`00` §11 指定） | 无需训练、召回高、增量插入友好 | — |
| `distance` | `vector_cosine_ops` | 文本嵌入方向相似度，与归一化配套 | — |
| `m` | 16 | 每层最大连接；16 在百万级以内召回/内存平衡好 | 召回不足且内存充足 → 24/32 |
| `ef_construction` | 64 | 构建期搜索宽度；越大越准越慢 | 构建可等待更久 → 96 |
| `hnsw.ef_search` | 40（默认）/ 80（重排时） | 查询期宽度；召回随时延线性上升 | 见 §7.4 实测 |
| 构建方式 | `CREATE INDEX CONCURRENTLY` | 不锁表；索引期仍可检索 | — |
| 维护 | 每周 `VACUUM (ANALYZE)`；更新率 >20% 时 `REINDEX CONCURRENTLY` | HNSW 对删除不友好，需重建去墓碑 | 索引膨胀 >1.5× |

`ivfflat` 不采用：需要预先训练聚类且对增量数据不友好，而知识库是持续增量写入。

### 7.3 查询与过滤（先过滤 vs 后过滤）

HNSW 的 `WHERE` 过滤会**降低召回**（图遍历被过滤掉）。三种策略，按域选择：

| 场景 | 策略 | 实现 |
|---|---|---|
| 过滤后基数小（`domain='policy'`，通常 < 500 片） | **先过滤后检索**：分区式部分索引 | 额外建 `ix_chunk_policy_hnsw ON kb_chunk USING hnsw (embedding vector_cosine_ops) WHERE metadata->>'advisory' = 'false' AND status='active'`（按需） |
| 过滤条件为高频等值（`status='active'`） | 允许 HNSW + 过滤，放大 `ef_search` | `SET LOCAL hnsw.ef_search = 100` |
| 强过滤（单 SKU/单平台）且命中量不可控 | **两阶段**：关键词/元数据先出候选 ≤ 500，再对候选算向量距离 | CTE + `ORDER BY embedding <=> $1`（候选集小，顺序扫描可接受） |

pgvector ≥ 0.8 可用 `hnsw.iterative_scan`：`SET LOCAL hnsw.iterative_scan = relaxed_order; SET LOCAL hnsw.max_scan_tuples = 20000;`——在过滤强时先开它，仍不足再走两阶段。

统一封装：`packages/knowledge/src/search.ts` 暴露 `search({query, filters, mode})`，调用方不得手写 SQL。

### 7.4 调参与监控

| 指标 | 采集 | 目标 | 动作 |
|---|---|---|---|
| 召回率（测试集 Recall@8） | 每日离线 | ≥ 0.90 | 降则查切片/模型/`ef_search` |
| 检索 P95 | `kb_query_log.latency_ms` | ≤ 600ms（无重排） | 超则查索引是否命中、候选窗是否过大 |
| 索引命中率 | `EXPLAIN (ANALYZE)` 抽样 | 100% 走向量索引 | 未命中则查过滤写法 |
| 平均候选数 | 查询计划 | 40–200 | 过大则加过滤 |
| 降级率 | `degraded=true` 占比 | ≤ 2% | 超则查 embed 可用性/超时 |
| 过期命中 | 结果中含 `effective_to < now()` | **0** | 立即阻断并修 SQL |

调参记录格式（写入 `docs/adr/`）：日期、改动（`ef_search` 40→80）、测试集指标前后、P95 变化、决策人。**禁止无记录调参**。

### 7.5 维度变更与全量重建（`embed_dim` 迁移）

维度变更 = 一次正式迁移，不是配置修改（`07` §11 明确不可热改）。流程：

| 步 | 动作 | 回滚点 |
|---|---|---|
| 1 | 新建 `model`（`capability='embedding'`，新 `embed_dim`）并 `publish` | 删除该 model |
| 2 | 迁移脚本：加新列 `embedding_v2 vector(<new_dim>)` + 新 HNSW 索引（`CONCURRENTLY`） | 删列 |
| 3 | 后台任务回填：按 `content_hash` 批量嵌入写 `embedding_v2`，进度可断点续跑 | 停任务即可 |
| 4 | 双读验证：同一查询分别走向量 v1/v2，比较 top-8 重合率与 Recall（测试集） | — |
| 5 | 切换：`search()` 读新列（配置开关 `EMBED_VERSION=v2`）；旧列保留 7 天 | 切回 v1 |
| 6 | 清理：删旧列/旧索引/旧 `embedding_dim` CHECK，更新常量与 `kb_document.embed_model_id` | 迁移 down 脚本 |
| 7 | 记录 ADR + 成本结算 | — |

窗口：选低峰（22:00–06:00）；期间检索**不中断**（读旧列）；成本必须提前估算并经 admin 确认。

## 8. 混合召回（向量 + 关键词）

### 8.1 两路召回

| 路 | 输入 | 取数 | 输出 |
|---|---|---|---|
| 向量路 | 查询向量（同一 `embed` 模型、同维度、已归一化） | `ORDER BY embedding <=> $q LIMIT 40`（加过滤） | `(chunk_id, distance, rank)` |
| 关键词路 | 查询分词后的 `tsquery` | `ORDER BY ts_rank_cd(tsv, q) DESC LIMIT 40` | `(chunk_id, rank_score, rank)` |

中文分词：Postgres 无内置中文分词。决策为**应用侧分词**（`nodejieba`，词典版本化 `jieba-dict@x.y`），把 token 用空格拼接后 `to_tsvector('simple', tokenized)` 写入 `tsv`；查询侧用同一词典切词后构造 `to_tsquery('simple', 'token1 & token2')`。理由：不引入 `zhparser`/`pg_jieba` 扩展（部署与词典升级不可控），且分词结果在应用侧可测试、可缓存。

BM25：Postgres **没有**内置 BM25。两档实现：

| 档 | 排序函数 | 说明 |
|---|---|---|
| 默认（够用） | `ts_rank_cd(tsv, query, 32)` | 覆盖密度近似，零额外成本 |
| 可选（更准） | 应用侧真 BM25，仅对候选窗 ≤200 计算 | `k1=1.2, b=0.75, avgdl` 来自 `kb_chunk` 统计（每小时刷新） |

真 BM25 公式：

```text
score(q, d) = Σ_{t ∈ q} IDF(t) · [ f(t,d) · (k1 + 1) ] / [ f(t,d) + k1 · (1 − b + b · |d| / avgdl) ]
IDF(t) = ln( 1 + (N − n(t) + 0.5) / (n(t) + 0.5) )
```

### 8.2 融合公式（默认 RRF）

采用 **Reciprocal Rank Fusion**（秩融合，无需跨模型分数校准）：

```text
score(d) = w_vec / (k + rank_vec(d)) + w_kw / (k + rank_kw(d))

默认：w_vec = 1.0，w_kw = 0.8，k = 60
rank_*(d) ∈ [1, 40]（未出现在该路结果中则该项为 0）
```

选择 RRF 而非加权分数：向量 cosine 与 `ts_rank_cd` 量纲不同，min-max 归一化会被单条极值带偏；RRF 只用名次，稳健且可解释。

可选的分数加权（仅当两路都做了 z-score 归一化时启用）：

```text
z_i(d) = (score_i(d) − μ_i) / σ_i
score(d) = 0.6 · z_vec(d) + 0.4 · z_kw(d)
```

默认关闭；开启需在测试集上证明优于 RRF（nDCG@10 提升 ≥ 2 个百分点），并写 ADR。

### 8.3 融合伪代码

```ts
export async function hybridSearch(req: SearchRequest): Promise<SearchHit[]> {
  const filters = buildFilters(req);            // domain/acl/effective/sku/platform/advisory
  const qvec = await embedQuery(req.query);     // 失败 → 降级 keyword（§11）
  const [vecHits, kwHits] = await Promise.all([
    qvec ? vectorSearch(qvec, filters, 40) : [],
    keywordSearch(req.query, filters, 40),
  ]);

  const fused = new Map<string, { hit: SearchHit; score: number }>();
  const add = (h: SearchHit, rank: number, weight: number) => {
    const prev = fused.get(h.chunkId);
    const inc = weight / (60 + rank);
    if (prev) { prev.score += inc; prev.hit.vectorRank ??= h.vectorRank; prev.hit.keywordRank ??= h.keywordRank; }
    else fused.set(h.chunkId, { hit: { ...h }, score: inc });
  };
  vecHits.forEach((h, i) => add(h, i + 1, 1.0));
  kwHits.forEach((h, i) => add(h, i + 1, 0.8));

  return [...fused.values()]
    .sort((a, b) => b.score - a.score)
    .slice(0, req.topK ?? 8)
    .map(({ hit, score }) => ({ ...hit, score }));
}
```

### 8.4 过滤与去重

| 过滤 | 条件 | 强制点 |
|---|---|---|
| 状态 | `status='active' AND archived_at IS NULL` | SQL |
| 生效期 | `effective_from <= as_of AND (effective_to IS NULL OR as_of < effective_to)` | SQL（`as_of` 由调用方传，默认 now） |
| 权限 | `acl_roles && ARRAY[$role]` | SQL（§12） |
| 域 | `metadata->>'domain' = ANY($domains)` | SQL；判断层证据只允许 `{product,size,fabric,policy,platform}`，禁止 `copy`/`manual` |
| 平台/SKU | `metadata->>'platform'`、`metadata->>'sku_code'` | SQL（可选） |
| 去重 | 同 `content_hash` 只留 score 最高一条 | 应用层 |
| 相邻合并 | 同文档 `seq` 相邻且合计 ≤ 1200 token 时合并展示（引用仍指向首片） | 展示层，不改变 chunk 行 |

`advisory=true` 的切片（`copy`/`manual`）可以进检索结果供"风格参考"，但调用方在组装证据时必须过滤（`08` §7.3 白名单校验会兜底拒绝）。

## 9. 重排（可选）

| 项 | 规则 |
|---|---|
| 触发条件 | ① 候选 ≥ 8；② 用途 ∈ {`judge_evidence`, `reply_draft`}；③ `config.rerank_enabled=true`；④ 预算充足。任一不满足即跳过 |
| 模型 | `purpose='rerank'`（`capability='rerank'`），或经批准的 `text` 模型 listwise 打分；**不得**用 `embed` 模型做重排 |
| 输入 | 查询 + top 12 候选（每片截断 300 token，保留 `chunk_id`），总 in ≤ 3000 token |
| 输出 | 每个 `chunk_id` 一个 0–1 分 + 可选理由；解析失败 → 视为未重排（不报错） |
| 融合 | `final = 0.4 × normalize(rrf_score) + 0.6 × rerank_score`；阈值 `final ≥ 0.25` 才进入结果 |
| 超时 | 3s；超时即跳过重排，用 RRF 结果（不阻塞主链路） |
| 成本 | 单次 ≤ `config.rerank_max_cost_micro_cny = 10000`；超限跳过 |
| 降级 | 重排失败不影响检索可用性；`kb_query_log.rerank_used=false` |
| 禁止 | 重排不得改变"是否过期/是否有权限"的判定（过滤永远在前） |

## 10. 引用结构（`CitationV1`）

与 `08` §7.1 的 `$defs.evidence` **完全对齐**（`doc_id`/`chunk_id`/`doc_version`/`quote`/`effective_from`），另加展示用可选字段。

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://dssaas.local/schema/citation/v1.json",
  "title": "CitationV1",
  "type": "object",
  "additionalProperties": false,
  "required": ["doc_id", "chunk_id", "doc_version", "quote"],
  "properties": {
    "doc_id": { "type": "string", "format": "uuid" },
    "chunk_id": { "type": "string", "format": "uuid" },
    "doc_version": { "type": "integer", "minimum": 1 },
    "quote": { "type": "string", "minLength": 4, "maxLength": 200 },
    "effective_from": { "type": ["string", "null"], "format": "date-time" },
    "title": { "type": "string", "maxLength": 200 },
    "source_type": {
      "enum": ["product", "size_chart", "fabric", "policy", "faq", "platform_rule", "copy_sample", "care", "manual"]
    },
    "section_path": { "type": "array", "items": { "type": "string", "maxLength": 40 }, "maxItems": 6 },
    "score": { "type": "number", "minimum": 0, "maximum": 1 },
    "uri": { "type": ["string", "null"], "maxLength": 500 }
  }
}
```

规则：

| # | 规则 |
|---|---|
| C1 | `quote` 必须是 `kb_chunk.content` 的**连续子串**（去空白后比较）；服务端校验，失败即作废该引用（`08` §8 E4） |
| C2 | `doc_version` 必须等于检索时的有效版本；旧版引用无效 |
| C3 | 引用必须能反查到 `kb_document.source_type` 与 `effective_from`，便于展示"依据：退换货政策 v3（2026-09-01 生效）" |
| C4 | 前端展示格式固定为：`《标题》v{版本} · {生效日期} · 「摘录…」`，可点击跳转原文 |
| C5 | `advisory=true` 的切片不得出现在 `evidence_refs`（调用方白名单兜底） |
| C6 | 一次回答最多 8 条引用（与 `08` `maxItems: 8` 一致）；不足则说明"未找到依据" |

引用组装（`packages/knowledge/src/citation.ts`）：

```ts
export function toCitation(hit: SearchHit): Citation {
  return {
    doc_id: hit.documentId, chunk_id: hit.chunkId, doc_version: hit.docVersion,
    quote: pickQuote(hit.content, hit.matchedSnippet),  // 取命中窗口，≤200 字，句边界对齐
    effective_from: hit.effectiveFrom?.toISOString() ?? null,
    title: hit.title, source_type: hit.sourceType,
    section_path: hit.sectionPath, score: round3(hit.score), uri: hit.uri,
  };
}
```

## 11. 降级（两类，行为必须显式）

### 11.1 决策表

| # | 故障 | 检测 | 行为 | 返回标记 | 上层动作 |
|---|---|---|---|---|---|
| D1 | **无引用**：检索 0 条，或全部被权限/生效期过滤 | `hits.length === 0` | 返回空引用；**不编造** | `degraded=true, degrade_reason='no_citation'` | 判断层 `escalate`（`08` §8 E1）；客服话术只说"我帮您确认" |
| D2 | **向量不可用**：embed 服务故障 / 查询向量化失败 / `embedding IS NULL` 占比高 | 查询前 ping + 嵌入异常 | 转 **纯关键词**召回（`mode='keyword'`） | `degraded=true, degrade_reason='no_vector'` | 结果标注"低置信，仅供参考"；判断层可用于线索，但**不得**单独作为 pass 依据（`08` §2 severity 至少 medium→needs_revision） |
| D3 | **检索超时**（向量路 > 1.5s） | `Promise.race` | 取消向量路，用关键词结果 | `degrade_reason='timeout'` | 同 D2 |
| D4 | **索引缺失/陈旧**（`index_status='stale'` 或索引不存在） | 文档状态检查 | 该文档不参与召回；其他文档照常 | `degraded=true, degrade_reason='no_vector'`（若全库无索引则同 D2） | 触发重建任务 + 告警 |
| D5 | **重排失败** | 超时/解析失败 | 跳过重排，用 RRF 结果 | `rerank_used=false` | 无（不影响） |
| D6 | **数据库不可用** | 连接失败 | **直接失败**（5xx），绝不返回猜测内容 | 错误码 `upstream_5xx` | 前端提示稍后重试 |

核心原则：**降级只能降低召回质量，不能降低事实标准**。任何降级路径都不得让模型在没有引用的情况下输出事实性内容（`00` §10）。

### 11.2 用户可见文案

| 场景 | 文案 |
|---|---|
| D1 无依据 | 「暂未找到可引用的官方依据，已转人工确认」 |
| D2/D3 低置信 | 「检索服务降级中，结果可能不完整，建议人工核对」 |
| D4 索引陈旧 | 「知识库正在更新，部分资料暂不可用」 |

### 12.3 实现（SQL 强制，不靠应用层 if）

```sql
-- 统一检索 CTE：权限与生效期在 SQL 内过滤，任何人不得绕过
WITH allowed AS (
  SELECT c.* FROM kb_chunk c
  WHERE c.status = 'active' AND c.archived_at IS NULL
    AND c.acl_roles && ARRAY[$role]::text[]                 -- 角色 ∩ 文档 ACL
    AND c.effective_from <= $as_of
    AND (c.effective_to IS NULL OR $as_of < c.effective_to)
    AND c.metadata->>'domain' = ANY($domains)               -- 用途白名单
)
SELECT id, document_id, version_no, content, metadata,
       embedding <=> $qvec AS distance
FROM allowed
WHERE embedding IS NOT NULL
ORDER BY embedding <=> $qvec
LIMIT 40;
```

防护要点：

| 风险 | 防护 |
|---|---|
| 越权读 `copy` 域 | `$domains` 由服务端按角色计算，不接受前端传入 |
| 通过 `metadata` 注入过滤条件 | 过滤条件只允许白名单键（`domain/platform/sku_code/color_id/size_code`），值参数化 |
| 用旧版本引用绕过 | 检索只返回 `status='active'` 且当前 `version_no` 的切片 |
| 日志泄漏隐私 | `kb_query_log.query` 截断 500 字；不含会话原文 |
| viewer 通过 API 直查 | 权限矩阵在路由层 + SQL 层双重校验（`14` 的 role×resource） |

## 13. 更新与过期告警

### 13.1 更新触发

| 触发 | 来源 | 处理 |
|---|---|---|
| 主数据变更（价格/成分/尺码） | `product.fact_version` 变更事件 | 对应文档 `index_status='stale'` → 重建队列 |
| 人工上传新版本 | `POST /kb/documents` | 新建 `version_no`，旧版 `superseded`，原子切换 |
| 政策调整 | 客服主管提交 + admin 发布 | 新版本立即生效；旧版保留 180 天 |
| 平台规则公告 | 平台运营摘录 | 新版本 + `metadata.source_url` + `announcement_date` |
| 复审到期 | `review_due_at` | 生成待办 + 告警；逾期文档降权（排序乘 0.8）而非直接下线 |

### 13.2 版本切换（原子）

```sql
BEGIN;
UPDATE kb_document SET status = 'superseded', index_status = 'indexed'
 WHERE source_type = $st AND source_id = $sid AND status = 'active';
UPDATE kb_chunk SET status = 'superseded'
 WHERE document_id = $old_doc_id AND version_no = $old_ver;
INSERT INTO kb_document (...) VALUES (...) RETURNING id;          -- 新版本
INSERT INTO kb_chunk (...) SELECT ...;                           -- 新切片（已嵌入）
UPDATE kb_document SET status = 'active', index_status = 'indexed' WHERE id = $new_doc_id;
COMMIT;
```

切换期间检索不阻塞（旧版在新版提交前仍 `active`）；切换后旧切片立即不可见（`status='superseded'`）。

### 13.3 过期与告警

| 文档类型 | 复核周期（`review_due_at = published_at + N`） | 逾期动作 |
|---|---|---|
| `policy` | 90 天（硬到期：`effective_to` 必填） | P1 告警；逾期后检索排除 |
| `platform_rule` | 30 天 | P1；逾期降权并提示 |
| `size_chart` / `fabric` | 随主数据版本（版本变更即重建） | P2 |
| `product` | 90 天 | P2 |
| `faq` / `care` | 90 / 180 天 | P3 |
| `copy_sample` / `manual` | 180 天 | P3 |

告警规则：

| 告警 | 条件 | 级别 | 责任人 |
|---|---|---|---|
| 文档临期 | `review_due_at - now() <= 7d` | P2 | `owner_user_id` |
| 文档逾期 | `now() > review_due_at` | P1（policy/platform_rule）/ P2（其他） | owner + admin |
| 索引陈旧 | `index_status='stale'` 持续 > 24h | P1 | 知识库 admin |
| 索引失败 | `index_status='failed'` | P1 | 知识库 admin |
| 过期命中 | 检索结果含过期切片（应为 0） | P0 | 后端值班 |
| 尺码表版本不一致 | `kb_document.version_no ≠ size_chart` 生效版本号，或 checksum 不等 | P0 | 后端 + 商品 |
| 无引用率突增 | 日无引用率 > 10% | P2 | 知识库 admin |

`scripts/kb-health.sql` 每日跑一致性检查（示例）：

```sql
-- 尺码表同源同版本（期望 0 行）
SELECT d.id, d.version_no AS kb_ver, s.version_no AS src_ver
FROM kb_document d
JOIN size_chart s ON s.product_id = d.source_id AND s.status = 'effective'
WHERE d.source_type = 'size_chart' AND d.status = 'active'
  AND d.version_no <> s.version_no;
```

## 14. 检索测试集与评估指标

### 14.1 测试集构造

| 项 | 要求 |
|---|---|
| 规模 | ≥ 120 条查询（中文），覆盖 §3 全部 9 个源 |
| 分层 | 尺码/成分/政策/平台规则/客服口径/文案参考，各 ≥ 15 条 |
| 来源 | **真实会话与工单**（脱敏），禁止用模型生成查询（会自证） |
| 标注 | 每条查询标 `gold_chunk_ids`（≥1，允许 2–3 条可接受集）+ `answerable` 布尔 + `expected_source_type` |
| 难例 | 同义表述（"缩水吗"→洗护）、跨 SKU（同款不同色）、政策条款编号查询、"能不能退"（需政策+尺码无关）、过期条款干扰项 |
| 维护 | 每月从 `kb_query_log.feedback='unhelpful'` 抽样 10 条补充；版本化 `eval-set@x.y` |
| 反例集 | 20 条**不该命中**的查询（如问竞品、问平台外规则），期望"无引用" |

### 14.2 指标定义

| 指标 | 定义 | 门禁阈值 |
|---|---|---|
| `Recall@8` | 命中 gold 的查询数 / 可回答查询数 | ≥ 0.90 |
| `MRR@10` | 首个 gold 命中名次倒数的均值 | ≥ 0.75 |
| `nDCG@10` | 按相关度分级（gold=2，可接受=1）计算 | ≥ 0.80 |
| `CitationPrecision` | 引用片段确实支撑断言的条数 / 总引用条数（人工抽检 50 条） | ≥ 0.95 |
| `QuoteResolvableRate` | `quote` 能在 `content` 中定位的比例 | ≥ 0.98 |
| `NoCitationRate` | 可回答查询中无引用比例 | ≤ 5% |
| `StaleHitRate` | 命中过期/被替代切片的比例 | **0** |
| `PermissionLeak` | 越权返回（viewer 拿到 `copy` 域）次数 | **0** |
| `DegradedRate` | 降级请求占比 | ≤ 2% |
| `P95Latency` | 混合召回（无重排）P95 | ≤ 600ms |
| `P95LatencyRerank` | 含重排 P95 | ≤ 3s |
| `RerankGain` | 重排前后 nDCG@10 差值 | ≥ +2pp（否则默认关闭） |

### 14.3 评估流程与门禁

```bash
# 1) 起评估（读测试集，逐条调 search()，产出逐条明细）
pnpm --filter @dssaas/knowledge eval -- --set eval-set@1.2 --mode hybrid

# 2) 报告：指标汇总 + 失败样本（未命中/低分/无引用）
# 3) 与基线 diff，任一门禁指标下降即 CI 失败
```

| 变更类型 | 必须跑 | 门禁 |
|---|---|---|
| 切片参数（大小/重叠/策略） | 全量 | 所有指标不低于基线 |
| 嵌入模型/维度 | 全量 + 重建 | Recall@8 ≥ 0.90 且 ≥ 基线 −1pp |
| 融合权重 / `ef_search` | 全量 | nDCG@10 不低于基线 |
| 词典/分词 | 全量 | 关键词路指标不低于基线 |
| 提示词（若重排用 LLM） | 含重排子集 | RerankGain ≥ +2pp |
| 解析器版本 | 全量 + 抽检 20 篇原文 | QuoteResolvableRate ≥ 0.98 |

### 14.4 与生产监控的关系

离线测试集指标 → 上线门禁；线上 `kb_query_log` → 真实分布监控（无引用率、降级率、反馈率）。两者偏差 > 10pp 说明测试集漂移，必须补样本。每月输出《检索质量月报》：指标趋势、Top 未命中查询、Top 过期告警、改进项。
