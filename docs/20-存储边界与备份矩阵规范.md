## 0. 不变量（违反即缺陷，不做例外）

| # | 不变量 | 检查手段 | 违反后果 |
|---|---|---|---|
| I1 | 业务读路径只允许 Postgres + MinIO | §8 静态规则 + SEC-19 运行时探针 | 双写漂移，页面与平台不一致 |
| I2 | 每个状态目录只有一个写者容器 | §3.3 卷矩阵 + compose 断言 | 丢更新、文件撕裂 |
| I3 | DSH 目录必须是持久卷，不是容器层 | `docker inspect` 断言（§3.3 C4） | 重启即丢黑匣子与凭据 |
| I4 | 凭据明文不进普通备份介质 | §5 排除项 + 备份清单断言 | 介质泄露即凭据泄露（ADR-0009） |
| I5 | 审计追加写、不可更新（`audit_log`） | `REVOKE UPDATE, DELETE` + `trg_audit_no_update` | 追责链失效（`docs/14` §6） |
| I6 | 恢复是变更，不是日常操作 | `CHANGE_ID` 校验（§6.0） | 误恢复覆盖生产 |
| I7 | 备份不可验证即视为不存在 | 每次备份附 manifest + 校验和 + 试恢复 | 灾备当天才发现备份是空壳 |
| I8 | RTO/RPO 用演练值，不用设计值 | §5.4 演练记录 | 事故时才发现超时 |

RTO/RPO 目标（演练按此对齐）：**Postgres** RPO ≤ 5 分钟、RTO ≤ 60 分钟；**MinIO** RPO ≤ 24 小时（版本化对对象级误删另有兜底）、RTO ≤ 120 分钟；**DSH 目录** RPO ≤ 24 小时、RTO ≤ 30 分钟（空目录也能启动，只丢调试上下文与凭据，凭据走 §4.3 分支）。

## 1. 存储边界矩阵

### 1.1 三类存储的职责与边界

| 维 | Postgres 16 + pgvector | MinIO | DSH 工作目录（卷 `dsh-data`） |
|---|---|---|---|
| 定位 | 业务唯一事实源 | 素材、视频、导出包、报文留档 | agent 黑匣子 + 凭据 + DSH 原生存储根 |
| 写者 | 仅 `apps/api`/`apps/worker`，只经 `packages/db` | 仅 api/worker 经 `packages/media`；`edge-proxy` 只写 `edge-archive` | 仅 `dsh-host` 进程与一次性 `dsh-headless` 任务 |
| 业务代码可读 | **可**（唯一允许的读源） | 可（只经服务端流或 10 分钟签名 URL） | **不可**；仅 `scripts/debug` 与管理员调试工具 |
| 事务 | ACID、跨表事务、PITR 可回 | 对象级原子，无跨对象事务 | 无事务（文件级读-改-写） |
| 版本与回滚 | 迁移 + 软删 + 乐观锁 `version` | 桶版本化（`dssaas-*` 开） | 无版本，只能靠备份 |
| 查询能力 | SQL、索引、HNSW、分区 | 前缀列举 + 按 `media_asset` 反查 | grep/jq，仅供排障 |
| 生命周期 | 在线永久；`audit_log` 在线 12 月 + 归档 3 年 | 90 天–永久（见表 1.3） | 会话 `.jsonl` 30 天；`storage` 7 天 |
| 备份方式 | 全备 + WAL 归档（§5） | 版本化 + 对象镜像（§5） | 卷 tar，排除凭据（§5） |
| 故障域 | `pg-data` 卷 | `minio-data` 卷 | `dsh-data` 卷 |
| 丢失影响 | 灾难：业务数据全失 | 素材需重生成或重拍 | 低：丢调试上下文；凭据可重建 |

**不可下沉到文件存储的事实**（每一条都能在 `docs/06` 找到字段依据）：

| 事实 | 表 | 为什么必须在 PG |
|---|---|---|
| 价格/库存 | `product_sku` | 分精度 `%10000=0`、乐观锁、写前快照（ADR-0005） |
| 尺码/成分 | `size_chart`、`fabric_composition` | 版本 + 生效日期 + 合计 100 约束（ADR-0008） |
| 审批与写入门 | `approval`、`audit_log` | `target_hash` 失效、append-only、链式审计 |
| 会话与未读 | `conversation`、`message` | 原子 `unread_count+1`（`docs/18` §1.4） |
| 队列事实 | `workflow_run`、`outbox_event` | 状态机 + 幂等键 + 死信可重放（ADR-0002） |
| 止损与熔断 | `compensating_ticket`、`kill_switch` | 不可逆登记与一键停写 |

### 1.2 MinIO 桶边界（对齐 `docs/10` §6.1）

| 桶 | 写入方 | 版本化 | 备份角色 | 保留 |
|---|---|---|---|---|
| `dssaas-raw` | worker | 开 | 对象镜像备份 | 永久（`concept` 90 天） |

| `edge-archive` | `edge-proxy` | 关 | 备份（报文留档，`docs/03`） | 90 天 |
| `audit-anchor` | worker | 关 | **Object Lock 合规模式 365 天**，不覆盖 | 365 天 |

### 1.3 DSH 目录内部边界

| 容器内路径 | 内容 | 写者 | 业务可读 | 纳入备份 |
|---|---|---|---|---|

| `/dsh/workspaces/` | agent 工作区（临时产物） | `dsh-host`/`dsh-headless` | 否 | 否 |

## 2. 为什么业务数据不进 DSH 原生存储

### 2.1 配置要求与官方定位（已核实，非推测）

| 事实 | 出处 | 直接后果 |
|---|---|---|
| `dsh-storage-json` 的 `root` **必填**，无默认值 | 包 README，`docs/00` 附录 A | 必须显式给目录 → 必须落在持久卷，否则容器重建即丢 |
| 目录以 **`0o700`** 创建 | 同上 | 属主唯读；跨 UID 容器直接读不到（§2.2 故障 2） |
| README 明示「**更大的数据或高并发场景请选择 SQLite**」 | 同上 | 官方自己把它定位在轻量低频，不是业务库 |
| 存储后端为 **JSON 文件**，无事务/索引/并发控制 | 同上 | 读-改-写丢失更新；无 PITR |
| `dsh-workflow` 是 **agent 扇出编排**，执行引擎由调用方提供 | 同上 | 业务流程状态机只能自建（ADR-0002） |
| `dsh-credentials` **未声明静态加密** | 同上 | 凭据必须单独处理（§4、§7） |

### 2.2 硬要放进去会出的三条具体故障

**故障 1 · 并发读改写丢更新（必然发生，不是概率）**
`docs/18` §1.4 要求「`message` 插入 + `unread_count+1` + `outbox` 写」在同一事务里原子完成。JSON 文件存储没有事务与行锁：`api` 两个并发请求、或 `api` 与 `worker` 同时读同一文件再整文件写回，后者覆盖前者。表现是**消息进库但未读不增加、工作台不弹窗**，直接打穿「提醒送达 P95 ≤ 800ms」并触发平台回复时效扣分；更严重的是审批行或幂等键被覆盖 → 同一笔写执行两次（`docs/00` §9.2 的幂等键形同虚设）。验证方式：并发 3 重放同一回调 1000 次，比对 `message` 行数与 `unread_count`，漂移率不为 0 即否决该方案。

**故障 2 · `0o700` × 多容器 = 启动即挂，修好即破安全**
目录由第一个打开的容器以 `0o700` 创建，属主是该容器 UID。`api`、`worker`、`dsh-host` 的镜像 UID 不同，其余容器 `EACCES` → 启动崩溃循环；为了「先跑起来」而 `chmod 0777`，等于拆掉「状态与凭据只有属主可读」这条 DSH 安全假设，并把凭据暴露给所有挂载该卷的进程（`docs/14` §5.3：agent 工具进程与 Host 同 OS 用户，文件权限无法对 agent 隐藏）。

**故障 3 · 没有 PITR，审计也无法作证**
文件存储没有 WAL、没有时间点恢复：误删或写坏只能退回上一次文件快照（最坏丢一整天）。同时 `docs/14` §6 要求审计追加写、不可更新、可按日锚定复算；JSON 可被任何有写权限的进程改写 → `audit-anchor` 日锚定立刻对不上，事故复盘会陷入「日志说发了、文件说没发、用户说没收到」的三方僵局。

> 规模补充：JSON 后端每次读都整文件反序列化，商品/会话量上来后读放大 O(N)，会被塞进 5 秒草稿预算里，挤掉真正该花时间的模型调用。

### 2.3 结论

DSH 原生存储只承载 **agent 自身的轻量状态**（本方案里业务用途为零）。业务状态一律 Postgres，字节一律 MinIO。这条结论由 ADR-0002、ADR-0010 与本文 I1 三重锁定，任何「先用文件存一下，以后再迁」的提议直接按违规处理。

## 3. Compose 卷设计

### 3.1 卷矩阵（唯一合法状态目录清单）

| 卷（compose 名 / 物理名） | 容器内挂载点 | 属主 UID:GID | 权限 | 唯一写者 | 备份挂载 |
|---|---|---|---|---|---|
| `dsh-data` / `dssaas_dsh-data` | `/dsh` | `10001:10001` | `0750`；`.credentials.yaml` `0600` | `dsh-host` | 备份任务容器 `:ro`（§3.3） |
| `pg-data` / `dssaas_pg-data` | `/var/lib/postgresql/data` | `999:999` | `0700`（initdb 设定） | `postgres` | 热备不挂卷；冷备/快照窗口 `:ro` |
| `minio-data` / `dssaas_minio-data` | `/data` | `1000:1000` | `0750` | `minio` | 不挂卷，用 `mc mirror` 拉取 |
| `backup` / `dssaas_backup` | `/backup` | `10002:10002` | `0750` | 仅备份任务容器 | 自身再镜像到离线介质（§5.2） |
| `pg-wal` / `dssaas_pg-wal` | `/wal` | `999:999` | `0700` | 仅 `postgres`（`archive_command`） | 备份任务容器 `:ro` 后转存 `backup` |

> `pg-wal` 是为「单写者」原则拆出来的子卷：WAL 只能由 postgres 写，不能与备份产物的写者共用 `backup` 卷。物理路径用 `docker volume inspect -f '{{.Mountpoint}}' dssaas_pg-data` 查询，**业务代码与宿主脚本不得直读这些路径**。

### 3.2 compose 关键片段（非全文，仅落约束）

```yaml
volumes:
  dsh-data:   { name: dssaas_dsh-data }
  pg-data:    { name: dssaas_pg-data }
  pg-wal:     { name: dssaas_pg-wal }
  minio-data: { name: dssaas_minio-data }
  backup:     { name: dssaas_backup }

services:
  postgres:
    image: pgvector/pgvector:pg16
    user: "999:999"
    volumes: ["pg-data:/var/lib/postgresql/data", "pg-wal:/wal"]
    environment: { PGDATA: /var/lib/postgresql/data/pgdata }
    command: >
      postgres -c wal_level=replica -c archive_mode=on
               -c archive_command='test ! -f /wal/%f && cp %p /wal/%f'
               -c archive_timeout=60s -c max_wal_senders=3
  minio:
    image: minio/minio
    user: "1000:1000"
    volumes: ["minio-data:/data"]
    command: server /data --console-address ":9001"
  dsh-host:
    user: "10001:10001"
    read_only: true
    tmpfs: ["/tmp"]
    volumes: ["dsh-data:/dsh"]
    environment: { DSH_HOME: /dsh/home }
  api:      { read_only: true, tmpfs: ["/tmp"] }   # 不挂任何状态卷
  worker:   { read_only: true, tmpfs: ["/tmp", "/scratch"] }
  backup:
    user: "10002:10002"
    volumes:
      - "backup:/backup"
      - "dsh-data:/src/dsh:ro"
      - "pg-wal:/src/wal:ro"
```

### 3.3 「禁止多容器各写本地文件」的四条硬约束与校验

| # | 约束 | 落地方式 | 校验命令（CI 与上线前必跑） |
|---|---|---|---|
| C1 | 状态目录只允许出现在 3.1 白名单 | `api`/`web`/`worker`/`edge` 一律 `read_only: true` + `tmpfs`，不得有 `volumes:` | `yq '.services \| to_entries[] \| select(.key \| test("^(api\|web\|worker\|edge)")) \| .value.volumes' infra/docker-compose.prod.yml` → 输出 `null`/`[]` |
| C2 | 同一卷只有一个 rw 写者 | 卷矩阵「唯一写者」列；备份/恢复/排障容器一律 `:ro` | `docker inspect -f '{{json .Mounts}}' <c> \| jq '[.[] \| select(.RW)] \| length'`，对 `pg-data`/`pg-wal`/`dsh-data` 必须为 1 |
| C3 | 属主与权限固定 | 初始化任务 `chown -R 10001:10001 /dsh/home && chmod 0750 …`；容器 `user:` 显式固定 | `docker compose run --rm --entrypoint sh dsh-host -c 'stat -c "%a %u:%g" /dsh/home'` → `750 10001 10001` |
| C4 | DSH 目录必须是卷，不是容器层 | 断言挂载来源为命名卷 | `docker inspect -f '{{range .Mounts}}{{.Type}} {{.Name}} {{.Destination}}{{"\n"}}{{end}}' $(docker compose ps -q dsh-host) \| grep 'volume dssaas_dsh-data /dsh'` |

**为什么这样做而不是写进文档让人遵守**：`read_only: true` 让误写立刻 `EROFS`（快速失败）；`:ro` 让第二写者拿不到写句柄；`user:` 固定让 `0o700` 不会因镜像 UID 变化而随机失效。约定的失效模式是「半年后有人加了一行 volumes」，结构不会。

### 3.4 每日卷健康探针（纳入备份报告，非独立脚本）

```bash
docker compose exec -T postgres psql -U dssaas -Atc "select setting from pg_settings where name='archive_mode'"   # 期望 on
docker compose exec -T postgres psql -U dssaas -Atc "select count(*) from pg_ls_archive_statusdir() where name like '%.ready'" # 期望 0
docker run --rm -v dssaas_dsh-data:/dsh:ro alpine:3 sh -c 'test -f /dsh/home/.credentials.yaml && echo creds-present || echo creds-missing'
df -h /var/lib/docker/volumes | tail -n +2   # pg-data < 80%，dsh-data < 70%，backup < 85%
```

判定：`archive_mode≠on`、`.ready` 积压 > 10、任一卷使用率超阈 → 备份任务仍执行但报告 `status=warning` 并触发 §9.3 告警。

## 4. DSH 凭据落盘形态确认（M1 必做，先出结论再定策略）

### 4.1 执行步骤（首次起 Host 后做一次，结果留证）

```bash
# 1) 定位文件（不同版本的 harness home 可能不同，两处都看）
docker compose exec -T dsh-host sh -lc 'printf "%s\n" "$DSH_HOME"; ls -la "$DSH_HOME" 2>/dev/null'
docker compose exec -T dsh-host sh -lc 'find / -maxdepth 6 -name ".credentials.yaml" 2>/dev/null'

# 2) 权限与属主（验 0750 / 0600 是否成立）
docker compose exec -T dsh-host sh -lc 'stat -c "%a %u:%g %s %n" "$DSH_HOME" "$DSH_HOME/.credentials.yaml"'

# 3) 形态指纹：只看前缀与结构，不把值打到终端
docker compose exec -T dsh-host sh -lc 'grep -o "^[a-zA-Z0-9_-]*:" "$DSH_HOME/.credentials.yaml" | head -5'
docker compose exec -T dsh-host sh -lc 'grep -Ec "^(enc|sops|age|vault):|BEGIN (AGE|PGP)" "$DSH_HOME/.credentials.yaml" || true'
docker compose exec -T dsh-host sh -lc 'LC_ALL=C grep -c "sk-[A-Za-z0-9]\{16,\}" "$DSH_HOME/.credentials.yaml" || true'
docker compose exec -T dsh-host sh -lc 'head -c 8 "$DSH_HOME/.credentials.yaml" | xxd | head -1'
docker run --rm -v dssaas_dsh-data:/dsh:ro zricethezav/gitleaks:latest detect --no-git -s /dsh/home --redact -f json || true
```

### 4.2 判断标准

| 观察到的现象 | 判定 | 依据 |
|---|---|---|
| YAML/JSON 文本，值形如 `sk-…`、`Bearer …`、长可打印串；`grep -c "sk-…"` > 0 | **未加密**（当前预期结论） | `docs/00` 附录 A：`dsh-credentials` **未声明静态加密**（ADR-0009） |
| 值为 `enc:v1:` / `sops:` / `age1…` / `BEGIN AGE ENCRYPTED FILE`；或二进制且 `sk-` 计数为 0 | 已加密（依赖 DSH 内置主密钥） | 前缀指纹 + 命中计数 |
| `gitleaks` 命中该文件 | 一律按**未加密**处理 | `docs/14` §5.5 泄露规则 |
| 文件不存在但 Host 能调通模型 | 值来自启动环境（`apiKeyEnv`） | `docs/14` §5.3：保存值优先于环境 |

留证：输出（**剔除任何可能截到的值行**）写入 `backup/reports/credential-at-rest-<YYYYMMDD>.json`，字段 `home / path / mode / uid_gid / encrypted(bool) / evidence_cmds / decided_at / decided_by`；并在 `docs/14` M1 验收单勾选「凭据落盘形态已确认」。

### 4.3 两种分支处理

| 分支 | 普通备份 | 恢复策略 | 额外动作 |
|---|---|---|---|
| **A 已加密**（主密钥不在同卷） | 允许随 `dsh-data` 备份，但备份件仍用 age 加密；主密钥离线保管 | 解卷 → 主密钥解密 → `POST /providers/:id/test` 验证 | 主密钥保管人与更替周期登记（§7.4） |
| **B 未加密**（当前预期） | **排除**：`tar --exclude='home/.credentials.yaml'`；清单断言该路径不存在，命中即备份失败 | **不恢复凭据**：按 §7 重建/重签（模型 Key 在控制台 5 分钟可重建） | 卷 0750 + 文件 0600 + 专用 OS 用户；`gitleaks` 日扫；泄露即轮换 |

分支 B 是**首选路径**：把「不可恢复」换成「可重建」，长期保管明文的收益远小于风险。凭据值因此不进普通备份、不进 Git、不进镜像（I4，ADR-0009）。

### 5.2 3-2-1 与离线要求

- **3 份**：生产卷 + `backup` 卷 + 离线介质（或异地对象存储）；**2 种介质**：块卷/文件系统 + 对象存储；**1 份离线**：加密移动盘，物理隔离，离线期间不挂载。

## 6. 恢复步骤

### 6.0 前置（所有恢复共用）

```bash
export CHANGE_ID=CHG-20261020-01
[ -n "$CHANGE_ID" ] || { echo "missing CHANGE_ID"; exit 2; }          # I6：恢复是变更
docker compose stop api worker dsh-host                                # 停写，避免边恢复边写
docker volume create dssaas_pg-data-restore                           # 永远恢复到新卷，不动原卷（取证）
docker volume inspect -f '{{.Mountpoint}}' dssaas_pg-data > /tmp/orig-pg-path.txt
```

### 6.1 恢复方式决策表

| 现象 | 用哪条路 | 代价 |
|---|---|---|
| 整库损坏 / 误 DROP DATABASE / 需回到某时刻 | §6.2 PITR | 60 分钟级，需停写 |
| 单表误删 / 误 UPDATE 少量行 | §6.3 逻辑恢复到影子库后导回 | 10 分钟级，可不停写 |
| 单个素材/视频被覆盖或误删 | §6.4 版本恢复 | 秒级 |
| 整桶丢失（卷损坏） | §6.4 整桶 `mc mirror` | 小时级（按容量） |
| DSH 会话黑匣子丢失 | §6.5 | 30 分钟级（可空目录启动） |
| 凭据失效/泄露 | §7 轮换（不是"恢复"） | 30 分钟级 |

### 6.2 Postgres PITR（命令级）

```bash
# 1) 选最近一个早于目标时间的全备
ls -1dt /var/lib/docker/volumes/dssaas_backup/_data/pg/base/*/ | head -5
BASE=/var/lib/docker/volumes/dssaas_backup/_data/pg/base/20261019T020000Z

# 2) 把全备铺到新卷，并清掉崩溃残留
docker run --rm -u 999:999 -v dssaas_pg-data-restore:/target -v dssaas_backup:/backup:ro \
  pgvector/pgvector:pg16 sh -c "cp -a /backup/pg/base/20261019T020000Z/. /target/ && rm -f /target/postmaster.pid /target/postmaster.opts"

# 3) 写恢复参数（容器内 PGDATA=/var/lib/postgresql/data/pgdata）
docker run --rm -u 999:999 -v dssaas_pg-data-restore:/target alpine:3 sh -c 'cat >> /target/pgdata/postgresql.auto.conf <<EOF
restore_command = '"'"'cp /wal/%f %p'"'"'
recovery_target_time = '"'"'2026-10-20 14:00:00+08'"'"'
recovery_target_inclusive = on
recovery_target_action = '"'"'promote'"'"'
EOF
touch /target/pgdata/recovery.signal'

# 4) 用 override 把 pg-data 指向恢复卷后启动（只起 postgres）
docker compose -f infra/docker-compose.prod.yml -f infra/docker-compose.restore.yml up -d postgres
docker compose logs -f postgres | grep -E "redo done|recovery stopping|database system is ready"

# 5) 验证：已退出恢复、时间线推进、关键表在
docker compose exec -T postgres psql -U dssaas -d dssaas -Atc \
  "select pg_is_in_recovery(), pg_current_wal_lsn(); select count(*) from audit_log; select max(occurred_at) from audit_log;"
docker compose exec -T postgres prisma migrate status || pnpm --filter @dssaas/db exec prisma migrate status
```

要点：`restore_target_time` 用**事故时刻之前**并留 1 分钟余量；恢复失败可改时间重来（新卷幂等）；**通过后先把旧卷改名保留 7 天**（`docker volume create dssaas_pg-data-bad-<date>` 并把旧卷数据 cp 过去）再切换，禁止删除原卷。

### 6.3 Postgres 单表/误删恢复

```bash
# 恢复到影子库，避免整库回退
docker compose exec -T postgres createdb -U dssaas dssaas_restore_$(date +%m%d)
docker compose exec -T postgres pg_restore -U dssaas -d dssaas_restore_1020 \
  -t approval --data-only /backup/pg/dump/dssaas-20261020.dump
# 校验后按主键回填（只允许 INSERT ... ON CONFLICT DO NOTHING，禁止整表 TRUNCATE 覆盖）
docker compose exec -T postgres psql -U dssaas -d dssaas -c \
  "INSERT INTO approval SELECT * FROM dblink('dbname=dssaas_restore_1020','SELECT * FROM approval') AS t(...) ON CONFLICT (id) DO NOTHING;"
```

回填必须写 `audit_log(action='ops.restore_table', detail=<CHANGE_ID>)`；**禁止**用备份整表覆盖生产表（会抹掉恢复窗口内的合法写入）。

### 6.4 MinIO 单对象与整桶恢复

```bash
# 单对象：先看版本，再按 version-id 复制回当前
mc ls --versions local/dssaas-derived/main_shot/1/2026/10/018f.../main_1200.webp
mc cp --version-id "3f2a...=" local/dssaas-derived/<key> local/dssaas-derived/<key>
# 校验（与 media_asset.sha256 比对）
mc cat local/dssaas-derived/<key> | sha256sum

# 整桶：从镜像源反向 mirror 到空桶（先建桶并开版本化）
mc mb --with-versioning local/dssaas-derived-restore
mc mirror --preserve backup/dssaas-derived local/dssaas-derived-restore
mc mirror --preserve --overwrite local/dssaas-derived-restore local/dssaas-derived   # 校验通过后回灌
```

校验口径：抽 30 个对象（含最大视频、最老素材）比对 `sha256`；`dssaas-export` 不恢复（可重生成）；`audit-anchor` 若被破坏只能从离线介质恢复，且必须核对 Object Lock 状态。

### 6.5 DSH 目录恢复

```bash
docker compose stop dsh-host
docker run --rm -v dssaas_dsh-data:/dst -v dssaas_backup:/backup:ro alpine:3 sh -c '
  cd /dst && tar xzf /backup/dsh/dsh-data-20261019.tar.gz --numeric-owner &&
  chown -R 10001:10001 /dst/home /dst/storage && chmod 0750 /dst/home'
sha256sum -c /backup/dsh/dsh-data-20261019.sha256    # 逐文件校验，失败即停
docker compose start dsh-host
docker compose exec -T dsh-host sh -lc 'ls -la "$DSH_HOME"; ls /dsh/home/sessions | tail -3'
```

凭据文件**不在**该备份中（§4.3）：恢复后 Host 会以「未配置」启动，管理页显示需重新设置，这是预期行为，不是恢复失败。

### 6.6 恢复后验证清单

| 检查 | 命令/位置 | 通过判据 |
|---|---|---|
| 数据库连得上、迁移状态一致 | `prisma migrate status`；`select count(*) from _prisma_migrations` | 无 pending/failed |
| 审计链连续 | `select count(*), max(seq) from audit_log`；抽查 3 条 `chain_hash` | 无缺口、可复算 |
| 写入门可用 | `POST /api/listings/publish` 用 dry-run 目标 | 校验通过但不产生写入 |
| 对象可读 | 抽 3 个 `media_asset` 生成签名 URL | HTTP 200 且字节一致 |
| 凭据状态 | 管理页徽标 + `POST /providers/:id/test` | 已配置且探活通过（或明确显示未配置） |
| 队列自愈 | 观察 reconciler 日志 | 无重复执行、无丢单 |

## 7. 凭据轮换预案

### 7.1 触发条件

| 触发 | 时限 | 说明 |
|---|---|---|
| 泄露/疑似泄露（日志、截图、介质外泄） | 15 分钟内止血 | 先撤销后排查（`docs/14` §5.5） |
| 定期轮换到期 | 到期当周 | P1 90 天、P2 180 天、KEK 365 天、age 接收方 365 天 |
| 人员变动（管理员/运维离职） | 交接后 24 小时内 | 桥接令牌随 Host 重启自动换 |
| 平台强制重置（政策/风控） | 平台要求内 | 注意双 secret 窗口 |
| 恢复演练后（用了导出件） | 立即 | 导出件视为已泄露 |

### 7.2 步骤（以 P1 模型 Key 为例，P2 见 `docs/14` §5.4）

```bash
# 1) 供应商控制台新建 Key（不撤销旧 Key，保留双活窗口）
# 2) 写入 DSH 凭据（只按名引用；不落配置文件、不回显）
docker compose exec -T dsh-host sh -lc 'cat >/dev/null'   # 由管理页或 credentials set 写入，禁止 shell 传值留存历史
# 3) 探活：单个 provider 全链路
curl -sS -X POST localhost:3001/api/providers/<id>/test -H "Authorization: Bearer $ADMIN_TOKEN" | jq
# 4) 观察 24h：错误率、401 计数、成本异常
# 5) 撤销旧 Key；确认 model_call_log 无 401/403
# 6) 导出一次新凭据加密件，销毁上一个导出件（§5.1）
```

### 7.3 验证

- `POST /providers/:id/test` 返回 `ok=true` 且 `latency_ms` 正常；
- `model_call_log` 中该 provider 近 24h 无 `401/403`，`status=failed` 比例未上升；
- DSH 管理页只显示「已配置」徽标，不显示值；
- 旧 Key 撤销后主动探活一次应得到 `401`（证明撤销生效）。

### 7.4 审计与留证

| 事件 | `audit_log.action` | 必填字段 |
|---|---|---|
| 写入新凭据 | `credential.set` | `actor`、`credential_ref`/名称、`key_version`、`request_id` |
| 导出加密件 | `credential.export` | `recipient_fingerprint`、`artifact_sha256`、`actor` |
| 轮换完成 | `credential.rotate` | 旧/新 `fingerprint`（SHA-256 前 16 位）、时间 |
| 撤销 | `credential.revoke` | 原因、关联工单/事故号 |

留证：轮换记录 + 探活输出 + 导出件 manifest 一并归档；**任何日志、报告、审计字段都不得出现明文**，只能出现 `fingerprint`。

## 8. 「双写漂移」防护

### 8.1 定义与可检测形态

双写漂移 = 同一业务事实在 Postgres 之外还存在第二份可读副本，且两者出现分歧。本方案允许存在的「第二份」只有两种，且都不承载业务事实：MinIO 的字节（由 `media_asset.sha256` 反向校验）、DSH 的 `.jsonl`（仅供调试，不参与业务判断）。任何让页面/接口从后两者取数的实现都算漂移（`docs/00` §16：业务读路径来自非 Postgres 的次数 **0 容忍**）。

### 8.2 静态检查规则（CI 必过）

```bash
# R1 业务代码禁止直读黑匣子/凭据/DSH 存储根；白名单只有 packages/db 与 packages/debug-tools
rg -n --hidden -g '!**/node_modules/**' -g '!**/dist/**' \
   -g '!packages/db/**' -g '!packages/debug-tools/**' -g '!scripts/debug/**' \
   -e '\.jsonl' -e '\.credentials\.yaml' -e 'dsh-data' -e 'storage-json' -e 'DSH_HOME' \
   apps packages infra scripts && exit 1 || echo "R1 ok"

# R2 除 allowlist 外禁止直接 import fs（读业务数据的通道只能是 packages/db / packages/media）
rg -n "from ['\"](node:)?fs['\"/]" apps packages | grep -vE '^packages/(db|media|debug-tools)/' && exit 1 || echo "R2 ok"
```

配套：`dependency-cruiser` 规则禁止 `apps/web` → `packages/db`（web 只调 `/api`）；ESLint `no-restricted-imports` 在 `apps/web` 禁用 `node:fs`。CI 门禁把 R1/R2 与 `pnpm lint/typecheck/test` 并列，失败即阻断合并（`docs/00` §17）。

### 8.3 代码评审清单（涉及数据读取的 PR 逐条打勾）

1. 新增读路径是否只从 `packages/db`（Prisma/raw SQL）或 `packages/media`（MinIO）取数？
2. 是否出现 `.jsonl`、`DSH_HOME`、`storage-json`、`sessions/` 字面量？（应全部为 0）
3. 新增表/列是否已在 `docs/06` 有定义？（禁止「先建表后补文档」）
4. 是否有把 Postgres 数据「导出到文件/本地缓存后再读」的实现？（禁止，缓存只能是进程内且以 `version/fact_version` 失效）
5. 写路径是否经写入门并带 `approval_id` + 幂等键？（ADR-0005）
6. 恢复/迁移脚本是否带 `CHANGE_ID` 与审计写入？
7. 是否有新的「事实来源」枚举值？（`ck_source_kind` 不允许出现模型/自定义取值）
8. 采样对账（§8.4）是否覆盖到本次新增的数据类型？

### 8.4 抽样对账方法

| 对账 | 频率 | 方法 | 判定 |
|---|---|---|---|
| 未读漂移 | 每 5 分钟 | `unread_count` vs `count(message where direction='in' and read_at is null)`（`docs/18` §1.4） | 不等 → 修计数 + 写 `drift_log` |
| 审批/流程一致 | 每日 02:00 | `approval.status='pending'` 数 vs 对应 `workflow_run.state='waiting_approval'` 数 | 差 > 0 → 告警（说明状态转移漏写） |
| 素材完整性 | 每周 | 随机 30 个 `media_asset`：`mc cat` + `sha256sum` 对比库内 `sha256` | 不一致 → 该对象标 `quarantined` + 重取 |
| 模型记账 | 每周 | 随机 20 条 `model_call_log` 与对应 session `.jsonl` 的 tool_calls 计数比对 | 差 > 5% → 成本漏记，修网关埋点 |
| 读路径探针（SEC-19） | 每次发布 | 用空目录 `:ro` 覆盖 `/dsh` 启动 api，跑商品详情、会话列表、审批列表 | 全部 200 且无 5xx → 无 `.jsonl` 依赖 |

### 8.5 违规处置

静态检查违规 = 阻断合并，无例外；运行时探针失败 = 回滚发布；对账漂移 = 开 `compensating_ticket` 并写 `drift_log`，24 小时内给出根因。漂移事件的根因分析必须回答一个问题：**这个读路径为什么不走 `packages/db`**。

## 9. 备份脚本规格（`scripts/ops/backup.sh`）

### 9.1 输入参数与前置

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `--target` | `all\|pg\|minio\|dsh\|creds` | `all` | 可单独跑某一类 |
| `--mode` | `full\|incr` | 按日历（周日 full） | `incr` 仅对 MinIO/DSH 有效 |
| `--out` | 目录 | `/backup` | 产物根；`--dry-run` 时只打印计划 |
| `--retention-days` | 整数 | 按 §5.1 | 覆盖保留期（演练/清理用） |
| `--encrypt-recipient` | age 公钥文件 | `age.pub` | 缺省即失败（不允许明文备份） |
| `--verify-only` | 开关 | 关 | 只做 manifest 校验与试恢复检查 |
| `--dry-run` | 开关 | 关 | 打印将执行的命令，不写产物 |

前置检查（失败即退出，不产出半成品）：磁盘剩余 > 20%（`--out` 与 `pg-wal` 卷）、`age.pub` 可读、`archive_mode=on`、`docker compose ps` 中 postgres/minio 为 `running`、`CHANGE_ID` 仅在恢复模式必需。

### 9.2 输出报告字段（`/backup/reports/<target>-<ts>.json`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `run_id` / `started_at` / `finished_at` / `duration_s` | uuid / ISO8601 / number | 一次运行的身份与耗时 |
| `target` / `mode` / `host` / `dsh_version` / `pg_timeline` | string | 可追溯性；`dsh_version` 取镜像内版本 |
| `artifacts[]` | `{path, bytes, sha256, kind}` | 每个产物一行，`sha256` 必填 |
| `manifest_path` / `manifest_sha256` | string | 清单文件位置与其校验和 |
| `postgres` | `{basebackup_dir, wal_last_segment, wal_lag_bytes, dump_path, tables}` | WAL 滞后 > 1GB 视为 warning |
| `minio` | `{buckets[], objects, bytes, skipped, version_count}` | 按桶统计；`skipped` 记录跳过的桶（`dssaas-export`） |
| `dsh` | `{files, bytes, excluded[], sessions_oldest}` | `excluded` 必须含 `home/.credentials.yaml`（I4） |
| `creds` | `{exported(bool), recipient_fingerprint, artifact}` | 未导出的运行也要写 `exported=false` 并说明原因 |
| `verify` | `{manifest_ok, trial_restore: pass\|skip, checked_rows, checked_objects}` | `trial_restore=skip` 必须在 `warnings` 说明 |
| `encryption` | `{alg, key_id, recipient}` | 不允许 `alg=none` |
| `retention` | `{pruned[], kept}` | 清理动作要可审计 |
| `status` / `warnings[]` / `error_code` / `exit_code` | enum / array / string / int | `status ∈ {ok, warning, failed}` |

### 9.3 失败告警与退出码

| 退出码 | 含义 | 告警等级 | 处置 |
|---|---|---|---|
| 0 | 成功（可含 warning） | 日报 | — |
| 2 | 参数/前置检查失败（磁盘不足、缺 `age.pub`） | P3 | 修配置后重跑 |
| 3 | Postgres 备份失败（`pg_basebackup`/`pg_dump` 非 0） | P2 | 检查复制槽、`archive_command`、磁盘 |
| 4 | MinIO 备份失败（`mc mirror` 非 0） | P2 | 检查后端、网络、桶策略 |
| 5 | DSH 目录备份失败（tar 非 0 或清单校验失败） | P3 | 检查卷挂载与权限 |
| 6 | 加密失败 | P1 | **立即停止**：已产出的明文半成品必须删除 |
| 7 | 校验失败（`sha256`/manifest 不一致） | P1 | 备份视为无效，重跑并排查介质 |
| 8 | 报告写入失败 | P2 | 修 `/backup` 权限 |

告警方式：退出码 + 报告 `status` 同时推 `ALERT_WEBHOOK`；指标 `backup_last_success_timestamp{target}`、`backup_failed_total{target,error_code}`、`backup_duration_seconds`。**连续 2 次失败或 `backup_last_success_timestamp` 超过 26 小时 → 升级为 P1 并通知负责人**。失败告警必须包含：`run_id`、`target`、`error_code`、报告路径、`CHANGE_ID`（若为恢复相关）。

### 9.4 调度与并发

| 项 | 规定 |
|---|---|
| 调度 | 宿主 cron / systemd timer；`flock -n /var/lock/dssaas-backup.lock` 防重入 |
| 顺序 | `pg`（02:00）→ `minio`（03:00）→ `dsh`（03:30）→ `creds`（04:00，轮换后另触发） |
| 重试 | 失败不自动重试超过 1 次（避免半成品叠加），重试也失败即告警等人 |
| 校验 | 每次运行结束跑 `--verify-only`；周日 full 后追加一次 `trial_restore` 到临时卷 |
| 报告归档 | 报告与 manifest 同时推离线介质；保留 400 天 |
