## 0. 结论先行

1. **1688 公开 API 文档尚未取得可核实来源**：本轮只确认了平台存在开放平台与开发者入口，未获得可公开引用的接口文档页面（对比拼多多有 412 条公开公告可抓）。**因此本报告不含任何接口名、字段名、限流数字**；一切结论待开发者账号登录后核验。这是 M0 的已知缺口，不是遗漏。
2. **B2B 的复杂度不在接口数量，而在价格与批量的数据结构**：一件商品可能同时有「起批价 + 规格阶梯价 + 区间价 + 代发价」，且不同起批量对应不同单价。若主数据只存一个 `price`，M4 上架必错。**前置动作：在 `product_sku` 之上增加「价格档位表」（见 §2.7 与 §6.1）**，再谈 adapter。
3. **询盘与报价是 1688 的主交互**（总纲 §2.2）：旺旺询盘 → 报价 → 成交，链路里「报价」是 B 级不可逆（发后不可撤回）、「起批条件」是 C 级敏感（改错直接影响成交与纠纷）。**报价功能默认人工确认，不做自动报价**。
4. **代发（一件代发）是双平台差异的最大来源**：库存、发货时效、面单、退货地址在代发场景下与自营不同，必须在订单与库存接口的字段层面区分「代发订单」与「批发订单」。
5. 部署与网络约束未知，按 `docs/03` 逐接口核验；未核实前按「公网直连 + IP 白名单 + 固定出口 IP」设计，不预置 edge-proxy。

**判定规则 H2（价格结构化）**：任何商品的 `price_tier` 未通过「档位连续、上下限不重叠、最高档无上限、与起批价一致」四项校验，禁止生成上架草稿；校验在 L1 规则层实现（规则 ID `PRICE_TIER_*`）。
**判定规则 H3（代发）**：订单若含代发标记，发货动作必须校验「代发库存 ≥ 需求量」且「退货地址 = 代发地址」，否则拦截并转人工。
**判定规则 H4（报价）**：报价单一律 B 级：发送前展示「报价明细 + 有效期 + 是否含税运费」，发送后不可撤回；超时未成交自动失效并记录。

**核验命令（bash / WSL / Git Bash）**

```bash
# 出口 IP（白名单登记）
curl -s https://ifconfig.me; echo

# 调用域名可达性与证书
curl -sS -o /dev/null -w 'code=%{http_code} tls=%{time_appconnect} total=%{time_total}\n' https://<api-host>/
openssl s_client -connect <api-host>:443 -servername <api-host> -showcerts </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates

# 时间偏差（签名/防重放依赖）
curl -sI https://<api-host>/ | grep -i '^date'; date -u

# 判断是否内网限定（公网应超时或 403）
curl -sS -m 5 -o /dev/null -w '%{http_code}\n' https://<api-host>/<doc-path>
```

**判定规则 H5（网络）**：与 01 的 G6 同构——公网直连无白名单→中心直连；需白名单→固定出口；仅内网/指定机房→edge-proxy；无法满足→未自动化清单 + 人工/导入包。
