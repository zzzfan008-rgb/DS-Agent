## 0. 结论先行

1. **三个页面全部围绕真实接口设计，不造假数据**：商品列表/详情、文案生成/判定、模型配置都直接消费 t7/t8/t9 端点；后端未提供的字段在页面上显式降级并登记缺口，**宁可显示“待聚合/未返回”，也不做前端猜测**（队长硬要求）。
2. **商品库**：列表支持搜索 + 类目 + 状态 + 游标分页；平台态/缺失字段直接渲染后端聚合结果（t28 已在实现期间落地），未返回时显示**“待服务端聚合”占位**（灰条 + tooltip），**不**用 `/listings?limit=100` 客户端拼装；详情按"概览/SKU、尺码表（按版本分组）、面料成分、平台属性、素材摘要"分区；新建（含尺码表必填）与 CSV 导入（先 dry_run 预览、再确认写入）各自独立路由。
3. **文案工作台**：三栏（输入/结果编辑/判定与审批）；生成是同步请求（201，非 SSE），显示耗时与取消；L1 命中按 `span` 高亮、L2 引用可点击查看原文；`escalate` 用独立紫色警示，不与 pass 混淆；编辑后重判 + 提交审批 + target_hash 变化提示。**本次不做前台模型选用器**，输入区显示“由路由策略自动选择”。
4. **模型管理**：后台四区（Provider / Model / Route / 用量与成本），覆盖新建、连通性测试、发布守卫未满足项、路由 scope/purpose/优先级/降级链、配额；前台仅保留**只读**可用模型与价格展示（无选用开关），写操作只在后台。
5. **明确的契约缺口 23 条**（§7）：其中影响最大的是详情尺码表无 `status`、文案草稿无 PATCH、审批无内容级失效校验、模型列表无 provider 名称、`model_id` 传了但不生效、内容判定无 KB 证据可挂载（L2 对商品草稿不可达）；实现期间新发现 Provider/Model 列表缺 `version`、`POST /products` 带 0.5 测量值触发 500（两条均已由后端 t41 修复）。每条都给出 UI 降级方式。

- 工作区最大宽 1600，桌面内容区左右 24px；列表行高 44px，表头 36px 粘性；详情两栏（主内容 + 右辅栏 360）在 ≥1280 生效。

- 金额一律 `formatCents()`（整数分 → ¥），输入用元、提交转分；比例/测量不显示多余小数（测量允许 0.5）。

### 2.4 权限与写操作约定

| 页面/动作 | 权限键（`GET /me.permissions[]`） | 无权限表现 |
|---|---|---|
| 商品列表/详情 | `product.read` | 整页 `ForbiddenState` |
| 新建/导入 | `product.write` / `product.import` | 按钮不渲染（不是 disabled） |
| 文案读取 | `content.read` | 整页无权限态 |
| 生成/重判/提交审批 | `content.write`（operator+） | 输入区只读、按钮不渲染；viewer 可看历史判定 |
| 模型前台视图 | 登录即可（viewer 可看已发布模型名称与价格，但用途矩阵为空时列表为空） | 空态解释"当前角色无可用用途" |
| 模型后台视图 | `model.write`（admin） | tab 不渲染；直达显示无权限态 |
| Provider/Route 写 | `provider.write` / `route.write`（admin） | 写按钮不渲染 |
| 用量与成本 | `metrics.read`（admin） | 区块级无权限态 |

写请求统一：`X-CSRF-Token`（读 `dssaas_csrf` Cookie）+ `Idempotency-Key`（每次用户动作一个 UUID；payload 变化即换新键；重试复用同键）+ PATCH 必须 `If-Match: <version>`。409 冲突统一"数据已被他人修改，已刷新，请重试"。

- 行点击进入详情；SPU 用等宽字体；名称最多 1 行省略。
- 平台态（队长裁决）：**不**调用 `/api/listings` 做客户端聚合（商品数增长会破坏分页语义）。后端未返回 `platform_states{pdd,1688}` 时，两列统一显示**灰条 + “待服务端聚合”**，tooltip 写明“字段由后端聚合任务补齐，当前不展示推断值”。缺失字段同理：无 `missing_fields[]` 时显示“待服务端聚合”，**不**用 `size_chart_version/sku_count` 猜缺失项（避免把“没数据”伪装成“已校验”）。
- **实现状态（2026-10-20）**：t28 已在实现期间落地，`GET /products` 实际返回 `platform_states` 与 `missing_fields`；M3 直接渲染（`未上架` / `缺资质` / `缺平台类目`），数据源切换未改布局，截图见 `docs/assets/M2-web/m3-products-list.png`。
- `platform`/`missing_fields` 查询参数仍未在 UI 启用（G1 剩余项），因此 M3 不渲染这两个筛选控件。
- 类目过滤：无类目字典端点（G2），M3 用"可输入 combobox + 当前页出现过的类目快捷项"；输入按 `^[A-Z][0-9]{4}(\.[0-9]{1,3})?$` 本地校验后作为 `category_code` 精确查询。
- 状态过滤：`draft/active/inactive/archived`。
- 分页：游标为 `GET /products` 返回的 `meta.next_cursor`（实际是 `spu_code`）；前端维护 cursor 栈以支持"上一页"；筛选变化清空栈。

```json
{ "product_id": "uuid", "platform": "pdd",
  "content_type": "title|selling_points|detail|faq|reply|quote",
  "tone": "专业|亲和|简洁|促销|批发",
  "constraints": { "length": 60, "keywords": ["防风"], "forbidden": ["最"] },
  "fact_refs": [], "model_id": "uuid?" }
```
响应：`{draft_id, content, fact_refs, status:"drafted", judgment_pending:true, facts_hash, model_call_id}`。

> `fact_refs` 与 `model_id` 当前服务端**未使用**（G16/G19）：M3 不提供任意 fact_refs 编辑器；**不做模型选用器**，输入区固定显示“模型：由路由策略自动选择（copy 用途）”。

**判定 `POST /api/judgments`（operator+）**

```json
{ "subject_type": "content_draft", "subject_id": "draft_id",
  "platform": "pdd", "content_type": "title",
  "text": "可选：编辑后的正文", "run": "L1|L2|L1+L2" }
```
响应关键字段：`verdict, severity, reason, repair_hint, evidence_refs[], rule_hits[], l1{blocked,hits[],errors[],duration_ms}, l2|null, versions{}, cost_cents, latency_ms, escalated, short_circuit?, facts_hash`。

- L1 hit：`rule_id, severity, field:'text', span:[start,end], matched, suggestion`；span 对应**提交的 text 原文**。
- L2：`verdict/severity/reason/repair_hint/evidence_refs/claims/confidence`。
- 编辑后重判必须带 `text=编辑后正文`；不带则服务端用 DB 草稿正文（未编辑版）。
- `invalid_fact`（主数据变更）→ 不能强行判；提示重新生成。

**提交审批 `POST /api/approvals`（operator+；M4 扩展端点）**

```json
{ "subject_type": "content_draft", "subject_id": "draft_id",
  "action": "publish", "platform": "pdd",
  "target_payload": { "draft_id": "...", "content_type": "title",
                      "content": "当前编辑正文", "facts_hash": "...",
                      "judgment_id": "...", "verdict": "...", "severity": "..." },
  "fact_snapshot": { "facts_hash": "...", "product_version": 14,
                     "size_chart_version": 3, "price_cents": 39900,
                     "composition": "棉80/聚酯20" },
  "risk_meta": { "risk_notes": ["L1-LEX-001 blocker", "L2 high"],
                 "content_type": "title", "judgment": { "verdict": "...", "severity": "..." } },
  "diff": { "content": { "before": "AI 原文", "after": "当前编辑正文" } } }
```
响应：`{id, status, level, target_hash, sla_due_at, expires_at, level_reasons[]}`。

- 级别由服务端算；当前 `action=publish` 映射 `listing.create` → **B 级**（G13）。页面只展示服务端 level，不自行推断。
- 同内容同 hash 已有 pending → 409 `conflict` + `detail.approval_id`；页面跳转已有审批。
- `target_hash` 变化提示：保存提交成功后返回的 hash 与提交时正文快照；再次编辑正文 → 显示"target_hash 将变化，原审批不对应当前内容"；重新提交会得到新 hash。后端**没有**审批失效/重算逻辑（G3），文案不承诺"自动失效"。

## 6. 权限、错误与可访问性

### 6.1 错误码 → UI 动作（本任务相关）

| code | HTTP | UI |
|---|---|---|
| `validation_failed` | 422 | 字段级 issue 列表 / 顶部汇总；聚焦第一个错误 |
| `invalid_fact` | 422 | 黄条"主数据已变更"；跳商品详情或重新生成；禁止忽略继续 |
| `conflict` | 409 | 刷新数据 + "已被他人修改"；同 hash 审批 → 跳已有审批 |
| `publish_blocked` | 409 | 发布守卫 checklist（`detail.missing[]`） |
| `no_route` | 503 | "该用途没有可用路由" + 去模型管理（admin）/ 联系管理员 |
| `provider_unavailable` | 503 | "供应商凭据或连通性不可用" + 测试连接（admin） |
| `model_not_published` | 422 | "模型未发布或参数不合法" + 跳模型管理 |
| `role_forbidden` | 403 | "当前角色无权使用该用途"；不显示模型 |
| `quota_exceeded` | 429 | 配额用量/重置时间 + 申请入口（文案"联系管理员"） |
| `upstream_5xx` / `timeout` | 502/504 | "结果未知/上游失败" + 重试 + request_id |
| `unauthorized` | 401 | 跳登录并保留 return_url |
| `forbidden` | 403 | 无权限态；不泄露对象是否存在 |

### 6.2 可访问性与键盘

- 表格：`<caption>`（视觉隐藏）、`th scope="col/row"`；排序/筛选 `aria-sort`/`aria-pressed`。
- 状态不是仅颜色：平台/verdict/severity/发布状态都带文字；色盲模拟下可区分。
- tabs：`role=tablist`、方向键切换；窄屏链接 tabs 用 `aria-current`。
- L1 高亮：`<mark>` + 右侧命中列表互为锚点；屏幕阅读器在命中列表内读 rule_id/matched/suggestion，不依赖高亮。
- 表单：错误 `aria-describedby` 指向字段错误；提交失败聚焦错误汇总；金额输入 `inputMode="decimal"`。
- 键盘：`/` 聚焦搜索；`j/k` 列表上下（复用 M1 偏好开关）；`Esc` 关闭抽屉；`Cmd/Ctrl+Enter` 生成/提交（在输入区外）。
- 动效：骨架 shimmer 尊重 `prefers-reduced-motion`；无自动轮播。
