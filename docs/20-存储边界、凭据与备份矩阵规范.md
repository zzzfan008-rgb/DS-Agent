## 0. 不变量（违反即缺陷，不做例外）

| # | 不变量 | 检查手段 | 违反后果 |
|---|---|---|---|
| I1 | 业务读路径只允许 Postgres + MinIO | §8 静态规则 + SEC-19 运行时探针 | 双写漂移，页面与平台不一致 |
| I2 | 每个状态目录只有一个写者容器 | §3.1 卷矩阵 + §3.3 断言 | 丢更新、文件撕裂 |
| I3 | DSH 目录必须是持久卷，不是容器层 | `docker inspect` 断言（§3.3 C4） | 重启即丢黑匣子与凭据 |
| I4 | 凭据明文不进普通备份介质 | §5 排除项 + 备份清单断言 | 介质泄露即凭据泄露（ADR-0009） |
| I5 | 审计追加写、不可更新（`audit_log`） | `REVOKE UPDATE, DELETE` + `trg_audit_no_update` | 追责链失效（`docs/14` §6） |
| I6 | 恢复是变更，不是日常操作 | `CHANGE_ID` 校验（§6.0） | 误恢复覆盖生产 |
| I7 | 备份不可验证即视为不存在 | 每次备份附 manifest + 校验和 + 试恢复 | 灾备当天才发现备份是空壳 |
| I8 | RTO/RPO 用演练值，不用设计值 | §5.2 演练记录 | 事故时才发现超时 |

RTO/RPO 目标（演练按此对齐）：**Postgres** RPO ≤ 5 分钟、RTO ≤ 60 分钟；**MinIO** RPO ≤ 24 小时（版本化对对象级误删另有兜底）、RTO ≤ 120 分钟；**DSH 目录** RPO ≤ 24 小时、RTO ≤ 30 分钟（空目录也能启动，只丢调试上下文与凭据，凭据走 §4.3 分支）。

## 1. 存储边界矩阵

### 1.1 三类存储的职责与边界

| 维 | Postgres 16 + pgvector | MinIO | DSH 工作目录（卷 `dsh-data`） |
|---|---|---|---|
| 定位 | 业务唯一事实源 | 素材、视频、导出包、报文留档 | agent 黑匣子 + 凭据 + DSH 原生存储根 |
| 写者 | 仅 `apps/api`/`apps/worker`，只经 `packages/db` | 仅 api/worker 经 `packages/media`；`edge-proxy` 只写 `edge-archive` | 仅 `dsh-host` 进程与一次性 `dsh-headless` 任务 |
| 业务代码可读 | **可**（唯一允许的读源） | 可（只经服务端流或 10 分钟签名 URL） | **不可**；仅 `scripts/debug` 与管理员调试工具 |
| 事务 | ACID、跨表事务、PITR 可回 | 对象级原子，无跨对象事务 | 无事务（文件级读-改-写） |
| 版本与回滚 | 迁移 + 软删 + 乐观锁 `version` | 桶版本化（`dssaas-*` 开） | 无版本，只能靠备份 |
| 查询能力 | SQL、索引、HNSW、分区 | 前缀列举 + 按 `media_asset` 反查 | grep/jq，仅供排障 |
| 生命周期 | 在线永久；`audit_log` 在线 12 月 + 归档 3 年 | 90 天–永久（见表 1.3） | 会话 `.jsonl` 30 天；`storage` 7 天 |
| 备份方式 | 全备 + WAL 归档（§5） | 版本化 + 对象镜像（§5） | 卷 tar，排除凭据（§5） |
| 故障域 | `pg-data` 卷 | `minio-data` 卷 | `dsh-data` 卷 |
| 丢失影响 | 灾难：业务数据全失 | 素材需重生成或重拍 | 低：丢调试上下文；凭据可重建 |

**不可下沉到文件存储的事实**（每一条都能在 `docs/06` 找到字段依据）：

| 事实 | 表 | 为什么必须在 PG |
|---|---|---|
| 价格/库存 | `product_sku` | 分精度 `%10000=0`、乐观锁、写前快照（ADR-0005） |
| 尺码/成分 | `size_chart`、`fabric_composition` | 版本 + 生效日期 + 合计 100 约束（ADR-0008） |
| 审批与写入门 | `approval`、`audit_log` | `target_hash` 失效、append-only、链式审计 |
| 会话与未读 | `conversation`、`message` | 原子 `unread_count+1`（`docs/18` §1.4） |
| 队列事实 | `workflow_run`、`outbox_event` | 状态机 + 幂等键 + 死信可重放（ADR-0002） |
| 止损与熔断 | `compensating_ticket`、`kill_switch` | 不可逆登记与一键停写 |

## 2. 为什么业务数据不进 DSH 原生存储

### 2.1 配置要求与官方定位（已核实，非推测）

| 事实 | 出处 | 直接后果 |
|---|---|---|
| `dsh-storage-json` 的 `root` **必填**，无默认值 | 包 README，`docs/00` 附录 A | 必须显式给目录 → 必须落在持久卷，否则容器重建即丢 |
| 目录以 **`0o700`** 创建 | 同上 | 属主唯读；跨 UID 容器直接读不到（§2.2 故障 2） |
| README 明示「**更大的数据或高并发场景请选择 SQLite**」 | 同上 | 官方自己把它定位在轻量低频，不是业务库 |
| 存储后端为 **JSON 文件**，无事务/索引/并发控制 | 同上 | 读-改-写丢失更新；无 PITR |
| `dsh-workflow` 是 **agent 扇出编排**，执行引擎由调用方提供 | 同上 | 业务流程状态机只能自建（ADR-0002） |
| `dsh-credentials` **未声明静态加密** | 同上 | 凭据必须单独处理（§4、§7） |

### 2.2 硬要放进去会出的三条具体故障

**故障 1 · 并发读改写丢更新（必然发生，不是概率）**
`docs/18` §1.4 要求「`message` 插入 + `unread_count+1` + `outbox` 写」在同一事务里原子完成。JSON 文件存储没有事务与行锁：`api` 两个并发请求、或 `api` 与 `worker` 同时读同一文件再整文件写回，后者覆盖前者。表现是**消息进库但未读不增加、工作台不弹窗**，直接打穿「提醒送达 P95 ≤ 800ms」并触发平台回复时效扣分；更严重的是审批行或幂等键被覆盖 → 同一笔写执行两次（`docs/00` §9.2 的幂等键形同虚设）。验证方式：并发 3 重放同一回调 1000 次，比对 `message` 行数与 `unread_count`，漂移率不为 0 即否决该方案。

**故障 2 · `0o700` × 多容器 = 启动即挂，修好即破安全**
目录由第一个打开的容器以 `0o700` 创建，属主是该容器 UID。`api`、`worker`、`dsh-host` 的镜像 UID 不同，其余容器 `EACCES` → 启动崩溃循环；为了「先跑起来」而 `chmod 0777`，等于拆掉「状态与凭据只有属主可读」这条 DSH 安全假设，并把凭据暴露给所有挂载该卷的进程（`docs/14` §5.3：agent 工具进程与 Host 同 OS 用户，文件权限无法对 agent 隐藏）。

**故障 3 · 没有 PITR，审计也无法作证**
文件存储没有 WAL、没有时间点恢复：误删或写坏只能退回上一次文件快照（最坏丢一整天）。同时 `docs/14` §6 要求审计追加写、不可更新、可按日锚定复算；JSON 可被任何有写权限的进程改写 → `audit-anchor` 日锚定立刻对不上，事故复盘会陷入「日志说发了、文件说没发、用户说没收到」的三方僵局。

> 规模补充：JSON 后端每次读都整文件反序列化，商品/会话量上来后读放大 O(N)，会被塞进 5 秒草稿预算里，挤掉真正该花时间的模型调用。

### 2.3 结论

DSH 原生存储只承载 **agent 自身的轻量状态**（本方案里业务用途为零）。业务状态一律 Postgres，字节一律 MinIO。这条结论由 ADR-0002、ADR-0010 与本文 I1 三重锁定，任何「先用文件存一下，以后再迁」的提议直接按违规处理。

## 3. Compose 卷设计

### 3.1 卷矩阵（唯一合法的状态目录清单）

| 卷（compose / 物理名） | 挂载点 | 属主 UID:GID | 权限 | 唯一写者 | 备份挂载 |
|---|---|---|---|---|---|
| `dsh-data` / `dssaas_dsh-data` | `/dsh` | `10001:10001` | `0750`；凭据文件 `0600` | `dsh-host` | 备份容器 `:ro` |
| `pg-data` / `dssaas_pg-data` | `/var/lib/postgresql/data` | `999:999` | `0700`（initdb） | `postgres` | 热备不挂卷；冷备窗口 `:ro` |
| `pg-wal` / `dssaas_pg-wal` | `/wal` | `999:999` | `0700` | 仅 `postgres`（`archive_command`） | `:ro` 后转存 `backup` |
| `minio-data` / `dssaas_minio-data` | `/data` | `1000:1000` | `0750` | `minio` | 不挂卷，`mc mirror` 拉取 |
| `backup` / `dssaas_backup` | `/backup` | `10002:10002` | `0750` | 仅备份任务容器 | 再镜像到离线介质 |

> `pg-wal` 是为「单写者」拆出的子卷：WAL 只能由 postgres 写，不能与备份产物共用写者。物理路径用 `docker volume inspect -f '{{.Mountpoint}}' dssaas_pg-data` 查，业务代码与宿主脚本不得直读。

### 3.2 compose 关键片段（只落约束，非全文）

```yaml
volumes: {dsh-data: {name: dssaas_dsh-data}, pg-data: {name: dssaas_pg-data}, pg-wal: {name: dssaas_pg-wal}, minio-data: {name: dssaas_minio-data}, backup: {name: dssaas_backup}}
services:
  postgres: {image: pgvector/pgvector:pg16, user: "999:999", environment: {PGDATA: /var/lib/postgresql/data/pgdata}, volumes: ["pg-data:/var/lib/postgresql/data", "pg-wal:/wal"], command: "postgres -c wal_level=replica -c archive_mode=on -c archive_timeout=60s -c max_wal_senders=3 -c archive_command='test ! -f /wal/%f && cp %p /wal/%f'"}
  minio: {image: minio/minio, user: "1000:1000", volumes: ["minio-data:/data"], command: "server /data"}
  dsh-host: {user: "10001:10001", read_only: true, tmpfs: ["/tmp"], volumes: ["dsh-data:/dsh"], environment: {DSH_HOME: /dsh/home}}
  api: {read_only: true, tmpfs: ["/tmp"]}      # 不挂任何状态卷；worker 同（另加 /scratch）
  backup: {user: "10002:10002", volumes: ["backup:/backup", "dsh-data:/src/dsh:ro", "pg-wal:/src/wal:ro"]}
```

### 3.3 「禁止多容器各写本地文件」的四条硬约束与每日探针

| # | 约束 | 落地 | 校验（CI 与上线前必跑） |
|---|---|---|---|
| C1 | 状态目录只允许 §3.1 白名单 | `api`/`web`/`worker`/`edge` 一律 `read_only` + `tmpfs`，无 `volumes:` | `yq '.services\|to_entries[]\|select(.key\|test("^(api\|web\|worker\|edge)"))\|.value.volumes' infra/docker-compose.prod.yml` → `null`/`[]` |
| C2 | 同卷只有一个 rw 写者 | 备份/恢复/排障容器一律 `:ro` | `docker inspect -f '{{json .Mounts}}' <c> \| jq '[.[]\|select(.RW)]\|length'`，`pg-data`/`pg-wal`/`dsh-data` 恒为 1 |
| C3 | 属主与权限固定 | 初始化任务 `chown -R 10001:10001 /dsh/home && chmod 0750`；容器 `user:` 显式 | `docker compose run --rm --entrypoint sh dsh-host -c 'stat -c "%a %u:%g" /dsh/home'` → `750 10001 10001` |
| C4 | DSH 目录必须是命名卷 | `docker inspect` 断言 `Type=volume` | `docker inspect -f '{{range .Mounts}}{{.Type}} {{.Name}} {{.Destination}}{{"\n"}}{{end}}' $(docker compose ps -q dsh-host) \| grep 'volume dssaas_dsh-data /dsh'` |

`read_only: true` 让误写立即 `EROFS`；`:ro` 让第二写者拿不到写句柄；固定 `user:` 让 `0o700` 不因镜像 UID 变化而失效。**约定会失效（半年后有人加一行 volumes），结构不会。** 每日探针（并入备份报告）：

```bash
docker compose exec -T postgres psql -U dssaas -Atc "select setting from pg_settings where name='archive_mode'; select count(*) from pg_ls_archive_statusdir() where name like '%.ready'"  # 期望 on / 0
df -h /var/lib/docker/volumes | tail -n +2     # pg-data<80%，dsh-data<70%，backup<85%
```

任一超阈（`.ready` > 10、`archive_mode≠on`、卷使用率越界）→ 报告 `status=warning` 并触发 §9.3 告警，备份仍继续执行。

## 4. DSH 凭据落盘形态确认（M1 必做）

### 4.1 执行步骤（首次起 Host 后做一次，结果留证）

```bash
docker compose exec -T dsh-host sh -lc 'printf "%s\n" "$DSH_HOME"; find / -maxdepth 6 -name ".credentials.yaml" 2>/dev/null; stat -c "%a %u:%g %n" "$DSH_HOME" "$DSH_HOME/.credentials.yaml"'
docker compose exec -T dsh-host sh -lc 'grep -Ec "^(enc|sops|age|vault):|BEGIN (AGE|PGP)" "$DSH_HOME/.credentials.yaml"; LC_ALL=C grep -c "sk-[A-Za-z0-9]\{16,\}" "$DSH_HOME/.credentials.yaml"; head -c 8 "$DSH_HOME/.credentials.yaml" | xxd | head -1'
docker run --rm -v dssaas_dsh-data:/dsh:ro zricethezav/gitleaks:latest detect --no-git -s /dsh/home --redact -f json || true
```

### 4.2 判断标准

| 现象 | 判定 | 依据 |
|---|---|---|
| YAML/JSON 文本，值形如 `sk-…`／`Bearer …`，`grep -c` > 0 | **未加密**（当前预期） | `docs/00` 附录 A：`dsh-credentials` **未声明静态加密**（ADR-0009） |
| 值前缀 `enc:v1:`／`sops:`／`age1…`／`BEGIN AGE ENCRYPTED FILE`，或二进制且 `sk-` 计数 0 | 已加密（依赖内置主密钥） | 前缀指纹 + 命中计数 |
| `gitleaks` 命中该文件 / 文件不存在但能调通模型 | 一律按未加密处理 / 值来自启动环境 `apiKeyEnv` 且保存值优先 | `docs/14` §5.5、§5.3 |

留证：输出（剔除任何值行）写 `backup/reports/credential-at-rest-<YYYYMMDD>.json`，字段 `home / path / mode / uid_gid / encrypted / evidence_cmds / decided_at / decided_by`，并在 `docs/14` M1 验收单勾选。

### 4.3 两种分支处理

| 分支 | 普通备份 | 恢复策略 | 额外动作 |
|---|---|---|---|
| **A 已加密**（主密钥不同卷） | 允许随 `dsh-data` 备份，备份件仍 age 加密；主密钥离线 | 解卷 → 主密钥解密 → `POST /providers/:id/test` | 主密钥保管人与更换周期登记（§7.3） |
| **B 未加密**（当前预期） | **排除**：`tar --exclude='home/.credentials.yaml'`；清单断言不存在，命中即备份失败 | **不恢复凭据**：按 §7 重建/重签（模型 Key 控制台 5 分钟可重建） | 卷 0750 + 文件 0600 + 专用 OS 用户；`gitleaks` 日扫；泄露即轮换 |

分支 B 是首选路径：把「不可恢复」换成「可重建」，凭据值因此不进普通备份、不进 Git、不进镜像（I4、ADR-0009）。

## 5. 备份矩阵

### 5.1 主矩阵（对象 / 方式 / 频率 / 保留 / 演练 / 责任人）

| 对象 | 方式 | 频率 | 保留 | 演练 | 责任人 |
|---|---|---|---|---|---|
| Postgres 全备 + WAL | `pg_basebackup -Fp -X stream -c fast` + `archive_command` 连续归档 | 全备每周日 02:00；WAL 连续 | 全备 8 周；WAL 同周期 + 7 天 | 季度 PITR | DBA |
| Postgres 逻辑 | `pg_dump -Fc -Z6` 全库 + 关键表单独导出 | 每日 02:10 | 14 天 + 月度 12 份 | 季度单表恢复 | DBA |
| MinIO 版本化 + 镜像 + 配置 | 全桶 versioning（`dssaas-export` 除外）+ `mc mirror --overwrite --preserve` + `mc admin config export`（桶策略/生命周期） | 版本常开；镜像每日 03:00；配置变更后 + 每周 | 版本 30 天；镜像 14 天 + 月度 6 份；配置 10 版 | 半年整桶恢复 | 运维 |
| DSH 目录 | `tar czf` 卷快照，排除 `.credentials.yaml`、`workspaces/` | 每日 03:30 | 14 天 | 季度抽查解包 | 运维 |
| DSH 凭据 | **不随普通备份**；`age` 加密导出（仅分支 A 可随卷） | 轮换后必导 + 每周 | 3 个版本 + 季度归档 | 季度轮换/恢复演练 | 安全负责人 |
| `backup` 卷 + 备份密钥 | 离线加密移动盘 + 异地对象存储；age/KEK 离线保管 | 每周日；密钥 365 天轮换 | 12 周；密钥 2 代 | 随季度演练 | 运维 + 安全负责人 |

### 5.2 3-2-1 与演练

- **3 份 / 2 种介质 / 1 份离线**：生产卷 + `backup` 卷 + 离线加密移动盘（物理隔离，离线时不挂载）；备份件一律加密，密钥与备份件分离；离线介质每月 `tar -tzf` 抽检。演练日历：PITR 每季度、单表恢复每季度、整桶恢复每半年、DSH 目录每季度、凭据轮换每季度、全链路灾备每年。结论写 `backup/reports/drill-<date>.md`（场景、耗时、失败点、修复项、责任人、复核日）。**未演练的备份策略视为未生效**（I8）。

## 6. 恢复步骤

### 6.0 前置（所有恢复共用）

```bash
export CHANGE_ID=CHG-20261020-01; [ -n "$CHANGE_ID" ] || { echo "missing CHANGE_ID"; exit 2; }   # I6：恢复是变更
docker compose stop api worker dsh-host && docker volume create dssaas_pg-data-restore   # 停写；永远恢复到新卷，原卷留证
```

### 6.1 恢复方式决策

| 现象 | 路径 | 代价 |
|---|---|---|
| 整库损坏 / 误 DROP / 需回到某时刻 | §6.2 PITR | 60 分钟级，需停写 |
| 单表误删 / 误 UPDATE 少量行 | §6.3 影子库导回 | 10 分钟级，可不停写 |
| 单素材/视频被覆盖（整桶丢失）/ 黑匣子丢失 / 凭据失效 | §6.4 版本恢复（整桶 mirror）/ §6.5 / §7 轮换 | 秒级（小时级）/ 30 分钟级 |

### 6.2 Postgres PITR（命令级）

```bash
BASE=/backup/pg/base/20261019T020000Z    # 容器内路径（= <backup 卷>/pg/base/<ts>），取目标时间之前最近的全备
cat > /tmp/pg-recovery.conf <<'EOF'
restore_command = 'cp /wal/%f %p'
recovery_target_time = '2026-10-20 14:00:00+08'
recovery_target_inclusive = on
recovery_target_action = 'promote'
EOF
docker run --rm -u 999:999 -v dssaas_pg-data-restore:/t -v dssaas_backup:/backup:ro -v /tmp:/mnt:ro pgvector/pgvector:pg16 \
  sh -c "cp -a $BASE/. /t/ && rm -f /t/postmaster.pid /t/postmaster.opts && cat /mnt/pg-recovery.conf >> /t/pgdata/postgresql.auto.conf && touch /t/pgdata/recovery.signal"
docker compose -f infra/docker-compose.prod.yml -f infra/docker-compose.restore.yml up -d postgres
docker compose exec -T postgres psql -U dssaas -d dssaas -Atc "select pg_is_in_recovery(), pg_current_wal_lsn(); select count(*), max(occurred_at) from audit_log;"
```

日志出现 `redo done` 与 `recovery stopping` 即 promote 完成。`recovery_target_time` 取事故时刻**之前**并留 1 分钟余量；失败可改时间重来（新卷幂等）；通过后 `prisma migrate status` 必须无 pending/failed，**旧卷改名保留 7 天**再清理，禁止删除原卷。

### 6.3 Postgres 单表/误删

```bash
docker compose exec -T postgres createdb -U dssaas dssaas_restore_1020 && docker compose exec -T postgres pg_restore -U dssaas -d dssaas_restore_1020 -t approval --data-only /backup/pg/dump/dssaas-20261020.dump
```

校验后按主键回填：只允许 `INSERT ... ON CONFLICT DO NOTHING`，禁止 `TRUNCATE`/整表覆盖（会抹掉恢复窗口内的合法写入）；回填必须写 `audit_log(action='ops.restore_table', detail=<CHANGE_ID>)`。

### 6.4 MinIO 单对象与整桶

```bash
mc cp --version-id "3f2a...=" local/dssaas-derived/<key> local/dssaas-derived/<key>      # 先 mc ls --versions 找 version-id
mc cat local/dssaas-derived/<key> | sha256sum                                            # 与 media_asset.sha256 比对
mc mb --with-versioning local/dssaas-derived-restore && mc mirror --preserve backup/dssaas-derived local/dssaas-derived-restore
mc mirror --preserve --overwrite local/dssaas-derived-restore local/dssaas-derived      # 校验通过后回灌
```

抽 30 个对象（含最大视频、最老素材）比对 `sha256`；`dssaas-export` 不恢复（可重生成）；`audit-anchor` 只能从离线介质恢复且必须核对 Object Lock 状态。

### 6.5 DSH 目录（凭据文件不在本备份中，恢复后 Host 以「未配置」启动属**预期**，不是恢复失败）

```bash
docker compose stop dsh-host && docker run --rm -v dssaas_dsh-data:/dst -v dssaas_backup:/backup:ro alpine:3 sh -c \
  'cd /dst && tar xzf /backup/dsh/dsh-data-20261019.tar.gz --numeric-owner && chown -R 10001:10001 home storage && chmod 0750 home'
sha256sum -c /backup/dsh/dsh-data-20261019.sha256 && docker compose start dsh-host   # 校验失败不得启动
```

### 6.6 恢复后验证清单

| 检查 | 判据 |
|---|---|
| 迁移状态 / 审计链 / 对象可读 | `prisma migrate status` 无 pending/failed；`audit_log` 无缺口，抽 3 条 `chain_hash` 可复算；抽 3 个 `media_asset` 签名 URL HTTP 200 且字节一致 |
| 写入门 / 凭据 / 队列 | dry-run 发布校验通过且不写入；管理页徽标 + `POST /providers/:id/test`；reconciler 日志无重复执行、无丢单 |

## 7. 凭据轮换预案

### 7.1 触发条件

| 触发 | 时限 | 说明 |
|---|---|---|
| 泄露/疑似泄露 | 15 分钟内止血 | 先撤销后排查（`docs/14` §5.5） |
| 定期到期 | 到期当周 | P1 90 天、P2 180 天、KEK/age 接收方 365 天 |
| 人员变动（管理员/运维离职）/ 平台强制重置 / 演练用过导出件 | 交接后 24h / 平台要求内 / 立即 | 桥接令牌随 Host 重启自动换；注意双 secret 窗口；导出件视为已泄露 |

### 7.2 步骤与验证

```bash
# 1) 控制台新建 Key（保留旧 Key 双活窗口）  2) 经管理页或 credentials set 写入，禁止 shell 传值留史  3) 探活：
curl -sS -X POST localhost:3001/api/providers/<id>/test -H "Authorization: Bearer $ADMIN_TOKEN" | jq
# 4) 观察 24h 错误率/401/成本   5) 撤销旧 Key   6) 导出新加密件并销毁上一导出件（§5.1）
```

验证：`test` 返回 `ok=true`；`model_call_log` 近 24h 无 401/403 且失败率未升；管理页只显示「已配置」徽标；旧 Key 撤销后主动探活应得 `401`（证明撤销生效）。

### 7.3 审计与留证

| 事件 | `audit_log.action` | 必填 |
|---|---|---|
| 写入新凭据 / 导出加密件 | `credential.set` / `credential.export` | `actor`、凭据名、`key_version`、`request_id`；导出加 `recipient_fingerprint`、`artifact_sha256` |
| 轮换完成 / 撤销 | `credential.rotate` / `credential.revoke` | 旧/新 `fingerprint`（SHA-256 前 16 位）、原因或工单号 |

日志、报告、审计字段都不得出现明文，只能出现 `fingerprint`。

## 8. 「双写漂移」防护

### 8.1 定义与静态检查规则（CI 必过）

同一业务事实在 Postgres 之外存在第二份**可读**副本且两者分歧，即为漂移。本方案只允许两种「第二份」，且都不承载事实：MinIO 的字节（由 `media_asset.sha256` 反向校验）、DSH 的 `.jsonl`（仅调试）。任何让页面/接口从后两者取数的实现即漂移（`docs/00` §16：业务读路径来自非 Postgres 的次数 **0 容忍**）。

```bash
# R1 禁止直读黑匣子/凭据/DSH 存储根；白名单仅 packages/db 与 packages/debug-tools
rg -n --hidden -g '!**/node_modules/**' -g '!**/dist/**' -g '!packages/db/**' -g '!packages/debug-tools/**' \
   -e '\.jsonl' -e '\.credentials\.yaml' -e 'dsh-data' -e 'storage-json' -e 'DSH_HOME' apps packages && exit 1 || echo R1-ok
# R2 除 allowlist 外禁止直接 import fs（业务取数只能经 packages/db 或 packages/media）
rg -n "from ['\"](node:)?fs['\"/]" apps packages | grep -vE '^packages/(db|media|debug-tools)/' && exit 1 || echo R2-ok
```

配套：`dependency-cruiser` 禁止 `apps/web → packages/db`（web 只调 `/api`）；ESLint `no-restricted-imports` 在 `apps/web` 禁用 `node:fs`。R1/R2 与 lint/typecheck/test 并列进 CI 门禁，失败即阻断合并（`docs/00` §17）。

### 8.2 代码评审清单（涉及数据读取的 PR 逐条打勾）

1. 新增读路径是否只来自 `packages/db` 或 `packages/media`？
2. 是否出现 `.jsonl` / `DSH_HOME` / `storage-json` / `sessions/` 字面量？（应为 0）
3. 新增表/列是否已在 `docs/06` 定义？是否存在「导出到文件/本地缓存后再读」？缓存只能进程内且按 `version/fact_version` 失效。
4. 写路径是否经写入门并带 `approval_id` + 幂等键（ADR-0005）？恢复脚本是否带 `CHANGE_ID` 与审计？是否新增事实来源枚举（`ck_source_kind` 不允许模型取值，ADR-0010）？

### 8.3 抽样对账与处置

| 对账 | 频率 | 方法 | 判定 |
|---|---|---|---|
| 未读漂移 | 每 5 分钟 | `unread_count` vs `count(message direction='in' and read_at is null)` | 不等即修计数 + `drift_log` |
| 审批与素材 | 每日 02:00 / 每周 | `approval pending` 数 vs `workflow_run waiting_approval` 数；随机 30 个 `media_asset` 用 `mc cat \| sha256sum` 对比库内 `sha256` | 差 > 0 告警；不一致标 `quarantined` + 重取 |
| 读路径探针（SEC-19） | 每次发布 | 用空目录 `:ro` 覆盖 `/dsh` 启动 api，跑商品详情/会话/审批列表 | 全部 200 且无 5xx 才通过 |

静态违规 = 阻断合并，无例外；探针失败 = 回滚发布；对账漂移 = 开 `compensating_ticket` + 写 `drift_log`，24 小时内给根因。根因必须回答：**这个读路径为什么不走 `packages/db`**。

## 9. 备份脚本规格（`scripts/ops/backup.sh`）

### 9.1 输入与前置

| 参数 | 取值 / 默认 | 说明 |
|---|---|---|
| `--target` / `--mode` / `--out` / `--retention-days` | `all\|pg\|minio\|dsh\|creds`；`full\|incr`；`/backup`；按 §5.1 | 可只跑一类；默认按日历（周日 full），`incr` 仅对 MinIO/DSH；保留期覆盖供演练 |
| `--encrypt-recipient` / `--verify-only` / `--dry-run` | age 公钥文件（缺省即失败）；后两者默认关 | 不允许明文备份；只校验 或 只打印计划 |

前置检查（失败即退出，不产半成品）：`--out` 与 `pg-wal` 卷剩余 > 20%；`age.pub` 可读；`archive_mode=on`；postgres/minio 容器 `running`；`CHANGE_ID` 仅恢复模式需要。

### 9.2 报告字段（`/backup/reports/<target>-<ts>.json`）

| 字段 | 说明 |
|---|---|
| `run_id` / `target` / `mode` / `host` / `dsh_version` / `pg_timeline` | 运行身份与可追溯性（`started_at`/`finished_at`/`duration_s` 同组） |
| `artifacts[]` = `{path, bytes, sha256, kind}`，另 `manifest_path` / `manifest_sha256` | 产物与清单 |
| `postgres` = `{basebackup_dir, wal_last_segment, wal_lag_bytes, dump_path, tables}` | WAL 滞后 > 1GB → warning |
| `minio` = `{buckets[], objects, bytes, skipped, version_count}` | `skipped` 记录 `dssaas-export` |
| `dsh` = `{files, bytes, excluded[], sessions_oldest}`；`creds` = `{exported, recipient_fingerprint, artifact}` | `excluded` 必须含 `home/.credentials.yaml`（I4）；未导出写 `exported=false` 与原因 |
| `verify` = `{manifest_ok, trial_restore: pass\|skip, checked_rows, checked_objects}` | `skip` 必须在 `warnings` 说明 |
| `encryption` = `{alg, key_id, recipient}`；`retention` = `{pruned[], kept}` | 不允许 `alg=none`；清理可审计 |
| `status` / `warnings[]` / `error_code` / `exit_code` | `ok\|warning\|failed` |

### 9.3 失败告警与退出码

| 码 | 含义 | 等级 | 处置 |
|---|---|---|---|
| 3 / 4 / 5 | Postgres / MinIO / DSH 目录备份失败 | P2 / P3 | 查复制槽、`archive_command`、后端与桶策略、卷挂载与权限 |
| 6 | 加密失败 | **P1** | 立即停止，删除已产出的明文半成品 |
| 7 / 8 | 校验失败（`sha256`/manifest 不一致）/ 报告写入失败 | **P1** / P2 | 备份视为无效，重跑并排查介质；修 `/backup` 权限 |

退出码 `0` = 成功（可含 warning），记日报。告警：退出码 + 报告 `status` 同时推 `ALERT_WEBHOOK`；指标 `backup_last_success_timestamp{target}`、`backup_failed_total{target,error_code}`、`backup_duration_seconds`。**连续 2 次失败或 26 小时无成功 → 升级 P1 并通知负责人**；告警必须含 `run_id`、`target`、`error_code`、报告路径、`CHANGE_ID`（恢复相关时）。

调度：宿主 cron/systemd timer + `flock -n /var/lock/dssaas-backup.lock` 防重入；顺序 `pg` 02:00 → `minio` 03:00 → `dsh` 03:30 → `creds` 04:00（轮换后另触发）；最多自动重试 1 次，再失败即告警等人；每次结束跑 `--verify-only`，周日 full 后追加 `trial_restore` 到临时卷；报告与 manifest 同步推离线介质，保留 400 天。
