## 5. 状态机 / 幂等 / 成本 / 租约

- **状态**（06 的 9 值）：`queued` → `submitted` → `polling` → `retrieved` → `succeeded`；失败 `failed`（`error_class`），超时 `expired`，取消 `cancelled`；`stored` 是内部阶段。
- **退避**：`delay(n)=min(base·2ⁿ,cap)·(1+jitter)`；测试断言 2s→4s→8s（注入时钟，无真实 sleep）。
- **幂等三层**：provider `idempotencyKey` → 同 external id；`media_asset.mediaJobId` → 只建一次；`cost_ledger(ref_type=media_job, ref_id=job_id)` → 只记一次。
- **成本**：图片 `amount_cents=usage.costCents`；渲染 `0 分/0.5s`；视频预留 `seconds=duration_seconds`；`tokens=0`。
- **配额**：`media_quota` 按 org + sku + 时间窗；超限 → failed/error_code=quota + 可读错误。
- **多实例租约（t34）**：
  - 抢占：`FOR UPDATE SKIP LOCKED` 选中 → `locked_by=$worker, locked_until=now()+90s`；`poll_after` 仍只表示下次轮询时间。
  - 心跳：处理中每 30s 续租；续租返回 0 行 → `leaseLost`，`persist`/`saveAsset`/`addCostLedger` 前都会 `ensureLease`，失租立即抛 `LeaseLostError` **停止写库**。
  - 完成后清空租约；进程崩溃则 90s 后自动可被接手。

## 6. 已知限制

1. **mock provider**：真实厂商（model id/凭据/限流）尚未接入。
2. **MinIO 未实机联调**：本机 `docker pull minio/minio` 被拒（registry 权限），因此样例用 `FsStorage`，S3 路径用本地假 S3 验证 SigV4/path-style。**上线/CI 必须先跑 `infra/minio-init/init.sh`**（compose `--profile init up minio-init`）。
3. **取消清理时序**：API 只置 `cancelled`；临时对象由 worker 下一 tick 清理（`mock/_tmp/`）。
4. **视频未实现**：无 ffmpeg/转码；`purpose=video` 无真实产物。
5. **字体与 XMP**：尺码表用系统字体（Windows 中文正常），未随镜像打包思源黑体；AIGC 仅可见标识，未写 XMP/sidecar。
6. **配额行需预先存在**：`media_quota` 无自动发放；`/media/generate` 创建任务与配额预检不在本任务。
7. **API 取消路由未做集成测试**：依赖登录态与 DB，仅 typecheck + 逻辑分支。
8. **sharp 原生依赖**：`sharp@0.35.5`（libvips 预编译，约 +30MB 镜像）。

### 7.3 租约语义（真实 DB）

`scripts/lease-check.ts` 输出：

```json
{"claimed_by_a":1,"after_expiry_claimed_by_b":1,"worker_b_lock":"lease-worker-b",
 "renew_old_worker":false,"write_old_worker":false,"write_new_worker":true}
```

即：A 抢占成功；租约过期后 B 接手；A 续租失败、带租约守卫的写入被拒（0 行）；B 写入成功。单测另有「心跳续租失败时旧 worker 停止写库（无 asset / 无 ledger）」一条，覆盖 `LeaseLostError` 分支。

### 7.4 MinIO 初始化脚本（两种用法）

```bash
# A) compose 一次性 service（推荐；profile init）
docker compose -f infra/docker-compose.yml --profile init up minio-init
# 等价直接运行（需本机已装 mc）
MINIO_ENDPOINT=http://127.0.0.1:9000 \
MINIO_ROOT_USER=dssaas MINIO_ROOT_PASSWORD=... \
sh infra/minio-init/init.sh
```

脚本：等待就绪（alias set 重试，120s 超时）→ `mc mb --ignore-existing dssaas-media` → `mc version enable` → 打印桶与版本化信息；幂等可重复执行。**本机因 registry 权限无法拉取 `minio/minio` / `minio/mc` 镜像，脚本未在本机实跑**；`docker compose config` 与 `--profile init config` 均通过（EXIT 0）。上线/CI 必须执行本脚本。

### 7.5 为什么不用 `poll_after` 当租约

媒体任务可能持续数分钟；`poll_after` 只是“下次轮询时间”。若把 `poll_after` 前推 30s 当租约，任务超过租约后会被另一个 worker 重新抢到，造成重复轮询、重复计费、重复落素材。因此 t34 新增 `locked_by/locked_until` 独立租约列 + 30s 心跳续租（90s 有效期），失租即停写；`poll_after` 保持原语义。`docs/10 §5.3` 已同步该口径。
