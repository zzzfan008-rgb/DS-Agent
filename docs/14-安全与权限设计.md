## 0. 结论先行（可执行摘要）

1. **权限判定点只有一个**：`apps/api` 的业务授权中间件 + 写入门硬校验。DSH Host 的 `dsh-api-remote-access` 只负责「机器到机器」这一层，不承担业务 RBAC。
2. **写操作必须四要素齐全**：`approval_id` + 与审批绑定的 payload 哈希 + 角色校验 + 幂等键。缺一即拒，错误码固定。
3. **审批与执行分离**：任何 `operator` 不能审批自己提交的项；A 级需 1 人，B 级需 1 人且必须 admin 或值班主管，C 级需 admin + 二次确认 + 时机检查。
4. **凭据分三平面**：模型供应商密钥进 DSH 凭据（只存引用）；平台 appSecret 进 `credential_ref` 信封加密（DSH 永不接触）；基础设施口令走容器 secret。三者不共用一个存储、不共用一把主密钥。
5. **DSH 凭据文件不承诺静态加密，且 agent 工具进程与 Host 同 OS 用户**——所以「把平台密钥放进 DSH 凭据」是明确禁止项，不是偏好。
6. **网络出站由容器网络 + 白名单代理强制**，因为 `dsh-sandbox-policy` 只管文件操作，词汇里没有网络与进程策略（已核实）。
7. **审计是哈希链 + 每日锚定**，DB 侧对应用账号只授 `INSERT/SELECT`，触发器拒绝 `UPDATE/DELETE`。
8. **所有安全项都要有自动化用例**，清单见第 11 节；没有用例的安全设计视为未交付。

## 1. 信任边界与威胁模型

### 1.1 信任边界

| # | 边界 | 内侧（可信） | 外侧（不可信） | 穿越控制 |
|---|---|---|---|---|
| B1 | 员工浏览器 ↔ `apps/web` | 会话 Cookie、CSRF Token | 公网/办公网请求 | TLS、`__Host-` Cookie、SameSite=Lax、Origin 校验、登录限流 |
| B2 | `apps/web` ↔ `apps/api` | 服务端渲染与 `/api` | 浏览器可篡改的一切参数 | 每次请求重新鉴权，前端隐藏 ≠ 授权 |
| B3 | `apps/api` ↔ 中心 DSH Host | 桥接令牌、业务信封、peer principal | 其它容器、同机其它进程 | loopback/内部网络 + Bearer + 非 owner peer + 方法级 policy |
| B4 | DSH Host ↔ 模型供应商 | 供应商 base_url、API Key 引用 | 模型返回内容、工具调用参数 | 出网白名单、密钥只存引用、工具面裁剪 |
| B5 | `apps/api`/`worker` ↔ 平台开放平台 | 已签名请求 | 平台响应、回调报文 | 出网白名单、签名校验、字段白名单解析 |
| B6 | MCP server ↔ Host | serverName 命名空间 | MCP 工具描述、返回内容、资源 URI | 工具 allow-list + 单调 guard + 输出当数据 |
| B7 | 备份介质 ↔ 生产 | 加密备份件 | 介质本身可能外泄 | 信封加密 + 主密钥离线/KMS |
| B8 | 管理员 ↔ DSH 原生界面 | 本机回环 + 启动 token | 办公网其它机器 | 仅回环或跳板机、一次性 token、审批档位 |

### 1.2 主要威胁与对应控制（STRIDE 简表）

| 威胁 | 典型场景 | 控制 | 验证 |
|---|---|---|---|
| 越权（E） | viewer 调写接口；operator 伪造 `approval_id` | 服务端角色矩阵 + 审批对象哈希绑定 + 测试用例 SEC-01~SEC-12 | 第 11 节 |
| 提权（E） | 改自己的 `role`；TOTP 重放 | 角色变更双人复核；`totp_last_step` 单调递增 | SEC-13/14 |
| 注入（T） | 商品描述里夹带「忽略以上指令」；客服消息注入 | 事实与指令分离、模型只做语义、工具面只读、输出当数据 | SEC-15~17 |
| 信息泄露（I） | 密钥进日志/异常栈；`.jsonl` 被业务读取 | 日志脱敏、错误码不透传上游 body、存储边界静态检查 | SEC-18/19 |
| 抵赖（R） | 否认点过「批准」 | 审批快照 + 审计哈希链 + 审批时 TOTP 再确认（C 级） | SEC-20 |
| 拒绝服务（D） | 登录爆破；批量发布打爆平台配额 | 限流、队列、kill switch、配额 | SEC-21 |
| SSRF（I/E） | 素材 URL 指向内网/metadata | URL 校验 + DNS pin + 重定向复核 + 出网代理 | SEC-22~24 |
| 供应链（T） | 恶意 MCP server / 被投毒的依赖 | MCP 白名单 + 只读；锁文件 + 依赖审计 | SEC-25 |

## 2. 角色与权限矩阵

### 2.1 记号

`R` 读 · `C` 新建 · `U` 修改 · `A` 审批/决策 · `X` 执行写平台或不可逆动作 · `D` 删除/归档 · `M` 管理配置 · `—` 无权限。

**默认拒绝**：矩阵未列出的组合一律拒绝；新增接口必须同时提交矩阵变更与对应越权用例。

### 2.2 业务资源 × 角色

| 资源（表/域） | viewer | operator | admin | 说明 |
|---|---|---|---|---|
| `product` / `product_sku` | R | R U | R U D M | 主数据导入仅 admin 触发（`POST /products/import`） |
| `size_chart` / `fabric_composition` | R | R U | R U D | 修改后旧版本保留，写入门按版本引用 |
| `platform_attribute_mapping` / `platform_category` | R | R | R U M | 平台字典只 admin 维护 |
| `content_draft` | R | R C U | R C U D | 草稿删除为软删（`archived_at`） |
| `judgment`（判断层结果） | R | R | R | 只由系统写入，人不可改判；异议走申诉记录 |
| `approval` | R | R C（提交） | R C A | `operator` 只能提交，不能决定；见 2.4 |
| `listing` 发布/上下架/改价/批量 | R | — | R X | 提交动作由 `operator` 产生草稿，执行仅 admin/写入门服务账号 |
| `listing` 止损（stop-loss） | R | — | R X | 高危：需二次确认 + 补偿工单 |
| `conversation` / `message` | R | R | R | 只读同步结果 |
| `reply`（客服回复） | R | R C（草稿）X（发送已批准） | R C X A | operator 可发「已批准」消息；不得自批自发 |
| 询盘/报价（1688） | R | R C | R C A X | 报价视为 B 级写 |
| `media_asset` / `media_job` | R | R C U | R C U D M | 成本字段只读，改价走模型路由配置 |
| `kb_document` / `kb_chunk` | R | R | R C U D M | 上传与重建索引仅 admin |
| `provider` / `model` / `model_route` | — | — | R C U D M | 供应商与密钥属管理面 |
| `audit_log` | — | — | R | 仅 admin 可查；无任何角色可写/改 |
| `kill_switch` | R | R | R X M | 触发需 admin；解除也需 admin 且留原因 |
| `users` / `roles` / `memberships` | — | — | R C U D M | 见 2.5 双人规则 |
| 备份/恢复 | — | — | R X | 恢复为不可逆操作，需变更单 |
| `POST /agent/run`（Agent 运行） | — | C（受限 intent） | C（全 intent） | intent 白名单见 `docs/12` §8；角色与 intent 的对应见 `docs/17` §6 |
| `GET /audit` / `GET /metrics` / `GET /health` | — | — | R | metrics 另给监控账号（只读） |
| DSH 原生界面 | — | — | R X | 仅管理员调试，见 `docs/17` 第 9 节 |

### 2.3 平台写操作 × 级别 × 角色（与总纲 9.3 对齐）

| 级别 | 操作 | 发起 | 审批 | 执行 | 额外要求 |
|---|---|---|---|---|---|
| A 可逆 | 库存微调、未发布内容改动、内部标签 | operator | operator 之外任一有权人 | 写入门 | 允许覆盖写回快照；留 `before/after` |
| B 不可逆·低危 | 新增 SKU、发送客服消息、替换非主图 | operator | admin 或值班主管 | operator（发送）或写入门 | 提示「不可撤回」+ `irreversible=true` |
| C 高危·不可逆 | 在售改价、换主图、改类目/关键属性、活动字段 | admin | admin（另一人）+ 二次确认 | 写入门 | 时机检查（活动期→预约/先下架）+ 影响面 + 补偿工单模板 |

### 2.4 职责分离（SoD）硬规则

| 规则 | 落法 | 违反时 |
|---|---|---|
| 提交人 ≠ 审批人 | `approval.submitted_by <> approval.decided_by`，DB `CHECK` + 服务校验 | `409 conflict`，审计 `approval.sod_violation` |
| C 级二次确认 ≠ 审批 | 审批通过后再要一次「确认执行」动作，携带新 `confirm_token`（5 分钟有效，一次性） | `approval_required` |
| 角色变更需双人 | 提权/降权写入 `approval`（类型 `role_change`），由另一 admin 批准后生效 | 拒绝提交 |
| kill switch 解除需双人 | 同上，类型 `kill_switch_release` | 拒绝 |
| 备份恢复需变更单 | `scripts/ops/restore.sh` 校验 `CHANGE_ID` 环境变量与审批记录 | 脚本退出 2 |
| 服务账号不得登录网页 | `users.kind='service'` 禁止 password/TOTP 登录路径 | `403` |

### 2.5 补丁：矩阵变更流程

1. 在 `packages/core/src/authz/matrix.ts` 增加/修改条目；
2. 同 PR 增加一条 `tests/security/authz.spec.ts` 用例（资源 × 角色 × 期望）；
3. PR 描述贴出「新增了谁的什么能力、为什么」；
4. CI 跑 `pnpm test:security` 与 `pnpm check:authz-coverage`（扫描路由装饰器，未在矩阵登记的路由直接失败）。

## 3. 认证：口令 + TOTP，预留 LDAP / 企业微信 / 钉钉

### 3.1 口令

| 项 | 取值 | 依据/说明 |
|---|---|---|
| 哈希算法 | Argon2id，`m=64MiB, t=3, p=1` | 单机可承受；参数写入 `users.password_algo`，便于渐进升级 |
| 最小长度 | 12 字符 | 管理员 16 字符 |
| 复杂度 | 不强制大小写符号组合，改为弱口令库校验（本地 10 万条 + HIBP k-anonymity 可选） | 降低「Password1!」式伪复杂度 |
| 失败锁定 | 单账号 5 次锁 15 分钟（`users.failed_attempts` / `locked_until`）；单 IP 10 次/5 分钟（Redis） | 锁定事件写 `audit_log` |
| 改密后 | `session_epoch += 1`，撤销该用户全部会话 | 强制重新登录 |
| 重置 | 仅 admin 发起，生成一次性链接（15 分钟），重置后强制改密 + 重新绑定 TOTP | 不走邮件明文临时密码 |

### 3.2 TOTP

| 项 | 取值 |
|---|---|
| 算法 | RFC 6238，HMAC-SHA1，6 位，30 秒步长 |
| 密钥 | 160 bit 随机；存于 `credential_ref`（`backend=vault`），`users.totp_secret_ref` 只存名称；表内无明文 |
| 校验窗口 | 当前步 ±1 步；成功步写 Redis `auth:totp:last:<user_id>` 并强制递增（`users` 无 last_step 列），防重放 |
| 绑定 | 首次登录强制绑定；展示 `otpauth://` 二维码 + 手动密钥；绑定成功才发放会话 |
| 恢复码 | 10 个，每个 10 字节随机，Base32 展示；仅存 Argon2id 哈希于 `credential_ref`（`backend=vault`，name=`user_<id>_recovery`，`notes` 记剩余数）；用一删一；剩余 ≤3 个时登录页提示 |
| 管理员 | 强制 TOTP；禁用 TOTP 需另一 admin 批准（`approval` 类型 `totp_disable`） |
| 失败 | 与口令共用限流桶；连续 10 次失败锁定并告警 |

### 3.3 登录流程（带状态机）

```text
POST /auth/login {username, password}
  → 校验口令（恒定时间比较）→ 若需 TOTP：返回 {stage:"totp", challenge_id}
POST /auth/login/totp {challenge_id, code}
  → 校验 TOTP + last_step → 建会话 → Set-Cookie __Host-dssaas_sid
  → 302 /；审计 auth.login
失败路径统一返回 {code:"auth_failed"}，不区分「用户不存在/口令错/TOTP 错」
```

约束：
- `challenge_id` 为 5 分钟一次性票据，存 Redis，绑定 IP 与 UA 哈希；
- 登录成功/失败都写审计（失败只记用户名哈希，避免明文枚举）；
- 禁止在 URL、日志、埋点中出现口令、TOTP、恢复码；
- 管理员登录可配置 IP 段白名单（`AUTH_ADMIN_CIDRS`），为空则不限制但记录来源。

### 3.4 身份源适配口（预留，不阻塞 M1）

统一接口放在 `packages/core/src/identity/provider.ts`：

```ts
export interface IdentityProvider {
  readonly id: 'local' | 'ldap' | 'wecom' | 'dingtalk';
  /** 返回跳转地址，或直接完成本地校验 */
  begin(input: BeginInput): Promise<{ redirectUrl: string } | { challengeId: string }>;
  /** 回调换取外部身份；externalId 稳定且不可由用户伪造 */
  authenticate(input: CallbackInput): Promise<ExternalIdentity>;
  /** 可选：全量/增量同步组织与人员 */
  syncUsers?(): Promise<SyncResult>;
  health(): Promise<{ ok: boolean; detail?: string }>;
}

export interface ExternalIdentity {
  externalId: string;          // LDAP dn / wecom userid / dingtalk unionid
  displayName: string;
  groups: string[];            // 用于映射角色
  email?: string;
}
```

| 适配器 | 协议要点 | 角色映射 | 默认状态 |
|---|---|---|---|
| `ldap` | 服务账号 bind + 用户 bind；只读；TLS 必需（`ldaps://` 或 StartTLS） | `groups` 命中 `AUTHZ_LDAP_GROUP_MAP`（如 `cn=dssaas-admin,...→admin`） | 关闭，配置齐全后启用 |
| `wecom` | OAuth2 网页授权 `snsapi_base` 取 `userid`；通讯录只读接口需企业 secret | 部门 ID → 角色；未映射部门 → `viewer` 待审 | 关闭 |
| `dingtalk` | 扫码登录 `code` 换 `unionid`；部门列表接口 | 同上 | 关闭 |
| `local` | 本文 3.1–3.3 | 直接按 `memberships` | 始终启用 |

适配规则：
1. **外部身份不自动成为 admin**：首次登录若组未映射，落 `viewer` 并生成 `pending_role` 待 admin 确认；
2. 同一 `externalId` 只绑定一个本地用户；换绑需 admin + 审计；
3. 外部源不可用时**不回退本地口令**（除 `break-glass` 账号），返回 `auth_provider_unavailable`；
4. `break-glass` 本地管理员账号：1 个，口令 + TOTP 离线保管，登录即触发高优先级告警；
5. 预留口只在 M1 定义接口与 `local` 实现，LDAP/企微/钉钉放 M8 之后按需实现，接口不返工。

## 4. 会话与令牌策略

### 4.1 令牌总表

| 令牌 | 载体 | 形态 | 有效期 | 存储 | 撤销方式 |
|---|---|---|---|---|---|
| Web 会话 | `__Host-dssaas_sid` Cookie | 32 字节随机，Base64URL，不透明 | 空闲 8h / 绝对 12h（admin 空闲 30min） | Redis（AOF）+ 每用户 sid 集合 `sess:user:<uid>` | 登出删键；删集合全撤 |
| CSRF | `dssaas_csrf` Cookie + `X-CSRF-Token` 头 | 双提交，32 字节 | 随会话 | 前端可读 Cookie（非 HttpOnly） | 随会话 |
| 登录票据 | `challenge_id` | 随机 UUID | 5 分钟，一次性 | Redis | 用后即删 |
| C 级确认 | `confirm_token` | 随机 32 字节 | 5 分钟，一次性 | Redis，绑定 `approval_id` | 用后即删 |
| 服务令牌 | `Authorization: Bearer dsa_...` | `dsa_` + 32 字节 Base62 | 90 天 | `credential_ref`（`backend=vault`）存令牌，`notes` 记 scopes/到期 | admin 撤销/到期 |
| 桥接令牌 | `Authorization: Bearer`（api→Host） | 32 字节随机 | Host 进程生命周期 | 文件 `<dsh-data>/secrets/bridge-token`（0600） | 重启即换；泄漏立即重启 Host |
| 平台 access_token | 内存/缓存 | 平台颁发 | 依平台 | 不明文落库；仅存过期时间 | 重新换取 |
| 幂等键 | `Idempotency-Key` 头 | 客户端 UUIDv7 | 24h 去重窗口 | Redis + `workflow_run` 唯一索引 | 自然过期 |

### 4.2 Web 会话细则

| 项 | 规则 |
|---|---|
| Cookie 属性 | `HttpOnly; Secure; SameSite=Lax; Path=/; __Host-` 前缀（生产 TLS）；开发环境允许 `Secure=false` 但启动横幅告警 |
| 会话 ID | 不透明随机，不含用户信息；服务端 Redis 存 `sid → {user_id, role, ip_hash, ua_hash, created_at, last_seen}` |
| 滑动续期 | 每次请求若剩余 <20% 有效期则续期，写回 Redis；绝对上限不续 |
| 绑定 | 首次绑定 `ip_hash` 与 `ua_hash`；变化时**不直接踢**，但 admin 会话变化即失效；普通会话记审计 |
| 并发 | 同账号最多 5 个会话，超出淘汰最旧；admin 最多 2 个 |
| 登出 | 删除 Redis 键 + 清 Cookie + 审计；提供「登出所有设备」 |
| 批量撤销 | 改密/禁用/角色变更时，删除 `sess:user:<uid>` 集合与其中每个 sid；Redis 丢失时全部会话失效（fail closed，重新登录） |
| 记住我 | 不提供。需要长会话走重新登录 |
| Origin/Referer | 所有状态变更请求校验 `Origin` 与 `Host` 同源；缺失 `Origin` 的非 GET 请求拒绝 |
| CSRF | 双提交 + SameSite 双保险；`/api/*` 的 POST/PUT/PATCH/DELETE 必须带 `X-CSRF-Token` |

### 4.3 服务令牌与桥接令牌

- 服务令牌用于 worker、脚本、监控只读账号；按 `scopes[]` 授权（如 `sync:read`、`metrics:read`），**不得**含 `listing:write`；
- 服务令牌以 `credential_ref`（`backend=vault`）存放，`notes` 记 scopes 与到期；签发时只展示一次明文，验签用恒定时间比较；
- 桥接令牌只在 `apps/api` 与 Host 之间使用；Host 启动时生成，写文件 0600，`apps/api` 启动读取并缓存；读取失败则拒绝启动（fail closed），不降级为无鉴权；
- 桥接请求必须同时满足：来源为内部网络地址、`Authorization` 匹配、`Content-Type: application/json`、方法为 `POST`、路径精确匹配；四项任一不满足返回 404（不暴露存在性）。

### 4.4 会话与 DSH 的边界

- 员工**永远不持有** DSH 会话 Cookie 或启动 token；
- DSH 原生界面的启动 token 一次性、只在本机回环可用，管理员用完即关；
- `apps/api` 到 Host 的每个业务调用都携带 `request_id` 与业务信封（用户、角色、用途），Host 侧独立再校验一次角色-用途白名单（纵深防御）。

## 5. 密钥与凭据管理

### 5.1 三平面（强制分离）

| 平面 | 内容 | 存放 | 业务代码接触方式 | 为什么不能合并 |
|---|---|---|---|---|
| P1 模型供应商 | 文本/图片/视频供应商 API Key | DSH 凭据（`dsh-credentials-local` 的 `$DSH_HOME/.credentials.yaml`，按名引用） | 只存 `provider.auth_ref` 名称；`dsh-llm-pi-ai` 按 `apiKeyEnv` 解析 | DSH 需要按请求热解析；业务不得持有明文 |
| P2 平台与业务密钥 | 拼多多/1688 appKey/appSecret、证书、webhook secret、服务令牌 | `credential_ref` 只存指针；密文在 Vault/加密凭据文件（`backend=vault`），KEK 来自 `DSSAAS_KEK` 或 KMS | adapter 每次调用从 Vault 解析，用后即弃；不缓存明文超过单次调用 | DSH 永不接触平台写权限 |
| P3 基础设施 | Postgres/Redis/MinIO 口令、备份加密密钥 | Docker secret / `.env.prod`（0600）/ KMS；备份主密钥离线 | 进程启动注入环境变量 | 与业务密钥轮换节奏不同 |

### 5.2 `credential_ref` 表（复用总纲表，补全字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | 主键 |
| `owner_type` | enum | `provider` / `platform` / `service` / `edge` |
| `owner_id` | uuid/text | 关联对象 |
| `purpose` | text | `provider_api_key` / `platform_app_secret` / `platform_cert` / `service_token` / `webhook_secret` |
| `ciphertext` | bytea | AES-256-GCM 密文 |
| `nonce` | bytea | 12 字节随机 |
| `aad` | text | 绑定 `owner_type:owner_id:purpose`，防密文搬移 |
| `key_version` | int | 支持双密钥窗口轮换 |
| `fingerprint` | text | `SHA-256(plaintext)` 前 16 位，用于比对而不泄露 |
| `status` | enum | `active` / `rotating` / `revoked` |
| `rotated_at` | timestamptz | 最近轮换时间 |
| `created_by` / `created_at` | | 公共字段 |

约束：
- 明文只存在于进程内存与一次调用栈；禁止进日志、异常、trace、`model_call_log`；
- 解密函数 `decryptCredential(id)` 只在 `packages/adapters-*` 与 `packages/core/credentials` 内可见（ESLint `no-restricted-imports` 限制）；
- KEK 轮换：新 `key_version` 加密新写入，旧版本仍可解；后台任务逐条重加密；完成后旧 KEK 下线。

### 5.3 DSH 凭据的使用与限制（已核实）

| 事实 | 影响 | 我们的做法 |
|---|---|---|
| `dsh-credentials` 只报「是否已配置/来源/能否写入」，绝不返回值 | 界面安全 | 管理页只显示徽标 |
| 保存值优先于启动环境；轮换下次请求生效，无需重启 | 可热轮换 | 平台密钥轮换 SOP 不重启 |
| `dsh-credentials-local` 文件默认 `<harness home>/.credentials.yaml`，仅属主可读；Windows 无 mode 检查 | 文件级隔离有限 | Host 以专用 OS 用户运行；文件所在卷 0700 |
| **agent 工具进程以同一 OS 用户运行**，文件权限无法对 agent 隐藏 | 密钥可被有 shell/fs 工具的 agent 读取 | 业务 preset **不挂** bash/fs/pwsh 工具；平台密钥根本不进 DSH |
| **未声明静态加密** | 备份介质泄露即泄露 | DSH 凭据文件不进普通备份；改为加密导出 + 轮换预案 |

> 结论：**P2（平台凭据）永不写入 DSH 凭据**。DSH 凭据只放 P1，且只放「模型供应商」这一类。

### 5.4 轮换

| 对象 | 周期 | 步骤 | 验证 |
|---|---|---|---|
| 模型供应商 Key | 90 天或泄露即换 | ① 供应商控制台建新 Key；② `credentials.set(ref, new)`；③ 发一次探活请求；④ 观察 24h 错误率；⑤ 撤销旧 Key | `POST /providers/:id/test` 通过 + `model_call_log` 无 401 |
| 平台 appSecret | 180 天或平台要求 | ① 平台后台重置（注意双 secret 窗口）；② Vault 写新版本，`credential_ref.status=rotating` 且 `external_key` 指向新路径；③ adapter 灰度 1 个同步任务；④ 全量切换；⑤ 旧版 `revoked` | 同步任务成功 + 平台签名校验通过 |
| 桥接令牌 | Host 每次重启 | 自动生成写文件；`apps/api` 监听文件变化 | 启动自检 + `/ready` |
| 服务令牌 | 90 天 | 新建 → 替换调用方 → 撤销旧 | 监控 401 计数 |
| KEK | 365 天 | 新版本写入 → 后台重加密 → 旧版下线 | 抽样解密校验 |
| TOTP 密钥 | 不轮换（丢失走重置） | 重置流程 | 下次登录 |
| 备份密钥 | 365 天 | 新备份用新钥；旧备份保留旧钥 1 个周期 | 季度恢复演练 |

### 5.5 泄露预案（按场景）

| 场景 | T+0 止血（≤15 分钟） | T+1h | T+24h | 责任人 |
|---|---|---|---|---|
| 模型 Key 泄露 | `credentials.unset(ref)` + 供应商侧撤销 + 观察异常计费 | 新 Key 上线、错误率观察 | 审计哪些调用使用了旧 Key、成本影响评估 | 运维 |
| 平台 appSecret 泄露 | 平台侧重置 + `status=revoked` + 触发对应平台 kill switch | 重新授权、灰度同步 | 全量审计平台侧操作日志、比对是否出现非本系统写入 | 运维 + 负责人 |
| 桥接令牌泄露 | 立即重启 Host（令牌即时失效）+ 检查 Host 访问日志 | 复核 `businessAgent/run` 调用来源 | 评估是否产生越权草稿/写操作 | 运维 |
| 员工账号泄露 | 禁用账号 + `session_epoch+1` + 撤销服务令牌 | 审计其近 30 天操作 | 强制改密 + 重绑 TOTP | admin |
| 备份介质外泄 | 确认加密范围；轮换 KEK 与备份密钥 | 评估可解密数据 | 通报与整改 | 负责人 |
| 代码库泄露密钥 | `gitleaks` 告警即轮换，不论是否已推送 | 清理历史（`git filter-repo`）+ 强制推送评审 | 复盘 | 全员 |

**通用原则**：先止血（撤销/断网/停写），再轮换，再取证，最后复盘；任何「先观察一下」都不允许超过 15 分钟。

## 7. SSRF 与出网白名单

### 7.1 出网架构（强制，不靠代码自觉）

```text
apps/api / worker / dsh-host  ──►  egress-proxy (squid 或 envoy)  ──►  平台 / 模型供应商
        │                                   │
        └── 仅加入 compose 网络 `internal`    └── 唯一带默认路由的容器；按 SNI/Host 白名单放行
```

| 规则 | 落法 |
|---|---|
| 业务容器无默认路由 | compose 网络 `internal: true`；只有 `egress-proxy` 接 `edge` 网络 |
| 白名单唯一来源 | `infra/egress/allowlist.yaml`，由 `scripts/egress/render.ts` 生成代理配置；变更走 PR + 审批 |
| DSH Host 也走代理 | 环境变量 `HTTPS_PROXY=http://egress-proxy:3128`；`NO_PROXY` 只含内部服务名 |
| 直连例外 | 仅 MinIO/Postgres/Redis 内部地址；不允许任何公网直连 |
| 审计 | 代理日志按目标域聚合，异常域名告警 |

### 7.2 白名单（初始，域名以侦察报告为准）

| 目标 | Host | 端口 | 用途 | 来源 |
|---|---|---|---|---|
| 拼多多开放平台 | `docs/01` 登记的 API 域名 | 443 | 商品/订单/消息/素材 | 侦察报告，M0 填实 |
| 1688 开放平台 | `docs/02` 登记的 API 域名 | 443 | 商品/订单/询盘 | 侦察报告，M0 填实 |
| 模型供应商 | `provider.base_url` 的 host 集合 | 443 | 文本/图片/视频 | 管理面发布时同步到白名单，需 admin 批准 |
| 对象存储 | `minio:9000`（内部） | 9000 | 素材 | 固定 |
| 包仓库/镜像 | 构建期使用，运行期不放行 | — | CI | 只在构建网络 |

规则：
1. 禁止 `*` 通配；子域必须显式列出；
2. IP 直连一律拒绝（平台若只给 IP，需在报告里单列并加备注）；
3. 非 443 端口默认拒绝，新增需说明；
4. 白名单变更写审计 `egress.allowlist.update`；
5. 每季度复核一次，删掉不再使用的域名。

### 7.3 代码层 SSRF 防护（所有抓取 URL 的地方）

```ts
// packages/core/src/net/safe-fetch.ts（唯一允许发外部请求的出口）
async function safeFetch(raw: string, init: SafeFetchInit): Promise<Response> {
  const url = parseAndValidate(raw);       // 1. 只允许 http/https；拒绝 userinfo、非默认端口
  const ip = await resolveAndPin(url.host); // 2. DNS 解析后固定 IP，防 rebinding
  assertPublicIp(ip);                       // 3. 拒绝回环/私网/链路本地/ULA/组播/保留/169.254.169.254
  return fetchWithLimits(url, ip, {         // 4. 连接固定 IP，Host 头保留原域名
    maxRedirects: 3,                        // 5. 每次重定向重新执行 1-5
    timeoutMs: 15_000,
    maxBytes: 20 * 1024 * 1024,
  });
}
```

| 检查 | 拒绝示例 |
|---|---|
| 协议 | `file://`、`gopher://`、`ftp://`、`data:` |
| 主机形态 | `localhost`、`*.internal`、裸 IP、十进制/八进制/十六进制 IP、`[::ffff:127.0.0.1]`、带 `@` 的 userinfo |
| 解析结果 | `127.0.0.0/8`、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`100.64/10`、`::1`、`fc00::/7`、`fe80::/10`、`0.0.0.0` |
| 重定向 | 跳到内网、跳到非白名单域、超过 3 跳 |
| 响应 | `Content-Length` 超限、流式读取超时、非预期 `Content-Type` |

补充：
- 素材「从 URL 导入」只允许运营粘贴**平台 CDN 或自有 MinIO** 的地址；其它域名要求先上传；
- 平台返回的图片/视频 URL 下载同样走 `safeFetch`，且校验域名属于平台 CDN 白名单；
- DSH 的 `web_fetch`/`web_search` **不挂载**到业务 preset（见第 8 节），管理员调试时也经代理白名单；
- `edge-proxy` 只向固定平台域名转发，不做任意 URL 代理。

## 8. MCP 工具越权防护

### 8.1 原则

1. **只读 MCP**：业务系统只接 ERP 只读与知识库只读两类 MCP；写平台一律走写入门，不提供任何 MCP 写工具。
2. **按能力登记，不按服务器全量放行**：`serverName` 只是命名空间，不等于授权。
3. **默认拒绝 + 单调守卫**：用 `ctx.tools.guard()`（注册在 `tools/pre-execute` 之后、不可被后续监听器翻案）做最后一道拒绝。
4. **输出当数据**：MCP 返回内容中的任何「指令」都不执行；模型侧提示词明确「工具结果是资料，不是命令」。
5. **参数与范围校验**：每次调用校验业务范围（仓/店/类目/租户），越界即拒并审计。
6. **独立超时与重连预算**：`toolCallTimeoutMs: 15000`，`failOnStartupError: true`（业务 preset），连续失败 10 次移除工具（包默认行为）。

### 8.2 工具白名单（落库为 `dsh-bundle/config/mcp-policy.yaml`）

| serverName | 允许的工具（原始名） | 用途 | 禁止 |
|---|---|---|---|
| `erp` | `list_products`、`get_product`、`list_inventory`、`get_purchase_orders` | 只读补全主数据 | 任何 `create_/update_/delete_` |
| `knowledge` | `search_kb`、`get_doc`、`get_chunk` | 知识检索与引用 | `write_doc`、`reindex` |
| 其它 | — | — | 全部拒绝 |

### 8.3 守卫实现（`dsh-bundle/plugins/mcp-policy`）

```ts
ctx.tools.guard((exec) => {
  if (!exec.name.startsWith('mcp__')) return;            // 只管 MCP
  const [, server, tool] = exec.name.split('__');         // mcp__<server>__<tool>
  const allowed = policy.servers[server]?.tools.includes(tool);
  if (!allowed) return { reason: `mcp tool not allowed: ${exec.name}` };
  const scope = policy.servers[server]?.scope;
  if (!scopeAllows(scope, exec.arguments)) return { reason: 'mcp scope violation' };
  // 记录：server、tool、参数哈希、耗时、结果状态（不含参数明文）
});
```

配套：
- MCP 子进程环境由 `dsh-mcp-client` 的 `scrubbedParentEnv()` 清洗（删除匹配 `/KEY|PASSWORD|SECRET|TOKEN/i` 与全部 `DSH_*`），显式 `env` 只注入该 server 必需项；
- `mcp-knowledge` 的资源 URI 也做路径白名单，禁止 `../`、绝对路径、`file://`；
- 一个 MCP server 若声明了写工具，直接不纳入业务 preset（评审门禁）；
- 变更 MCP 配置需 admin + 审计，且重启后回归一次工具清单。

### 8.4 MCP 风险 → 机制 → 用例

| 风险 | 机制 | 用例 |
|---|---|---|
| 调未登记工具 | guard 拒绝 + 审计 | SEC-25 |
| 同名工具覆盖/冲突 | 命名空间 `mcp__<server>__<tool>`；同 scope 重名直接加载失败 | SEC-26 |
| 恶意 server 返回指令 | 提示词声明数据；判断层不采信；输出截断 | SEC-27 |

| server 进程读到密钥 | 环境清洗 + 不共享 .env | SEC-29 |
| 资源 URI 穿越 | 路径规范化 + 白名单 | SEC-30 |
| 慢 server 拖死会话 | 15s 超时 + 取消 | SEC-31 |

## 9. 沙箱与审批档位（`dsh-permission-presets` + `dsh-user-approval`）

### 9.1 已核实的行为（决定我们怎么配）

| 事实 | 含义 |
|---|---|
| 预设 = 沙箱模式 + 审批策略的捆绑；保留名 `custom` / `auto` 不能自建 | 我们只能定义具名预设，不能自造 `custom` |
| 沙箱模式只有 `read-only` / `workspace-write` / `danger-full-access` | 三档正好对应三档角色 |
| 审批策略只有 `ask` / `never`；**`never` 是确定性拒绝，不是放行** | 绝不能把 `never` 当「全权」用 |
| 沙箱**只管文件操作**，网络与进程不在其词汇中 | 出网必须靠第 7 节的网络层 |
| 会话切换写 `permission/preset` 事件，跨重启保留 | 切换可审计、可回放 |
| `ask` 无应答者时解析为 `unavailable` 并拒绝 | 无人值守场景必须显式配置 |

### 9.2 预设表（`dsh-bundle/config/cordis.patch.yml`）

```yaml
- name: '@deepseek-ai/dsh-permission-presets'
  config:
    presets:
      viewer:   { sandbox: read-only,           approval: ask }
      operator: { sandbox: workspace-write,     approval: ask }
      admin:    { sandbox: danger-full-access,  approval: ask }
      ci:       { sandbox: workspace-write,     approval: never }
    defaultPreset: viewer
```

| 预设 | 沙箱 | 审批 | 适用 | 挂载工具 | 说明 |
|---|---|---|---|---|---|
| `viewer` | read-only | ask | 文案/问答/判断等只读用途 | `skill`、只读 MCP | 默认；写文件即被沙箱拒 |
| `operator` | workspace-write | ask | 批量素材暂存、导出包生成 | 上述 + 受控 workspace 写 | 工作区限定 `dsh-data/workspaces/<session>` |
| `admin` | danger-full-access | ask | 管理员调 preset/skill/MCP | 全量（含 bash/fs/web） | 仅本机回环，用完切回 |
| `ci` | workspace-write | never | `dsh-headless` 批处理/CI | 无交互工具 | `never` = 需要审批的操作一律拒绝，适合无人值守 |

**选档规则**：按**用途**选，不按用户角色选。用户角色只决定「能否发起该用途」；例如 operator 角色发起的文案生成仍是 `viewer` 预设（因为不需要写文件）。

### 9.3 审批语义

| 项 | 规则 |
|---|---|
| 一次性 | 每个 `approval/request` 独立决定，无 `allow-always`、无记忆规则（包能力边界） |
| 失败关闭 | 无应答者 / 应答者抛错 / 超时 → `unavailable` → 拒绝 |
| 留痕 | `approval/asked` 与 `approval/decided` 只写会话日志；同时在 `apps/api` `audit_log` 记一条 `agent.approval` |
| 业务审批 ≠ DSH 审批 | 业务 L3 审批在 `apps/web` 审批中心；DSH 审批只管 Host 工具。两者不混用、不互相替代 |
| 业务会话的审批路径 | 业务 preset 不含需要审批的工具（写文件/执行命令），因此 `ask` 实际不会触发；若触发说明配置漂移，按事故处理 |

### 9.4 权限档位与角色的关系

| 业务角色 | 可发起用途 | 实际使用预设 | 不能做什么 |
|---|---|---|---|
| viewer | 查询、报表、看板 | `viewer` | 不能生成草稿、不能调用会写文件的用途 |
| operator | 文案、客服草稿、素材暂存、提交审批 | `viewer` / `operator` | 不能改模型配置、不能执行平台写 |
| admin | 全部 + 管理面 + DSH 调试 | `viewer` / `operator` / `admin` | 不能在无审批下执行 C 级写 |

## 10. 「最小权限」在写入门上的落法

### 10.1 写入门七道硬校验（顺序固定，任一失败即拒并审计）

| # | 校验 | 失败错误码 | 可否绕过 | 审计字段 |
|---|---|---|---|---|
| 1 | 调用者身份与角色（仅 `admin` 或写入门服务账号） | `authz_denied` | 否 | `actor_role` |
| 2 | `approval_id` 存在且 `status=approved`、未过期、未使用 | `approval_required` | 否 | `approval_id` |
| 3 | 审批对象哈希 = 当前 payload 哈希（内容变更即失效） | `approval_stale` | 否 | 两个哈希 |
| 4 | 提交人 ≠ 审批人；C 级审批人 ≠ 二次确认人 | `conflict` | 否 | 双方 id |
| 5 | 幂等键 `hash(platform+action+payload)` 未被成功使用 | 幂等命中返回首次结果 | 否 | `idempotency_key` |
| 6 | 平台/类目/任务类型未被 kill switch 停用 | `kill_switch_active` | 否（除紧急放行流程，需 admin 双人） | `kill_switch_id` |
| 7 | 写前快照已落库（`listing.published_snapshot`） | `snapshot_missing` | 否 | `snapshot_id` |

执行后追加：结果分类（成功/平台驳回/可重试/永久失败）、平台请求 id、耗时、`irreversible` 标记、补偿工单 id（B/C 级）。

### 10.2 服务账号与网络最小化

| 主体 | 能做什么 | 不能做什么 |
|---|---|---|
| `apps/api` 写入门（服务账号 `writer`） | 调平台写接口、读平台只读接口 | 不能读 DSH 凭据、不能登录网页、不能改模型配置 |
| `apps/worker`（服务账号 `syncer`） | 只读同步、媒体轮询、对账 | 不能调平台写接口 |
| 平台凭据 | 写凭据与读凭据分离：`platform_app_secret` 用途区分 `read` / `write` 两个 owner，能写的不用于同步 | 同一凭据不得同时具备读写 |
| 网络 | 只有 `apps/api` 容器可出网到平台写域名；`worker` 只出网到只读域名与模型供应商 | `web`/`dsh-host` 不可直达平台写域名 |
| DB | `app_rw`（业务）、`app_ro`（报表）、`migrator`（迁移）、`audit_writer`（只插审计） | 应用不得用超级用户；`app_rw` 对 `audit_log` 只有 INSERT |

### 10.3 批量与高危的额外约束

| 操作 | 约束 |
|---|---|
| 批量改价/下架 | 单批 ≤50；超过必须 admin 二次确认并分批；执行前 dry-run 输出 diff；执行中可一键暂停 |
| 跨类目批量 | 默认禁止；需要 admin 逐类目批准 |
| 首次上线新平台 adapter | 金丝雀：1 个 SKU → 1 个类目 → 10 个 SKU → 全量；每档观察 30 分钟 |
| 夜间/活动期 | C 级操作默认转入「预约窗口」；活动期禁止改价/换主图（除非先下架） |
