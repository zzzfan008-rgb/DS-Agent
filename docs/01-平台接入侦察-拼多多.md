> **本文件的写法约定**
> 1. 凡未经现场核验的事实，一律写「待填：<具体要问平台什么>」，**不写接口名、不写数字**。凭记忆或第三方博客填的接口名会导致 M4 写入门返工，代价远高于留空。
> 2. 「结论」列只能是三选一：**自动化**（走写入门 + adapter）/ **降级**（导入包或只读同步）/ **人工**（工作台内处理 + 剪贴板助手）。含条件的结论必须写清条件，例如「审核通过→自动化；未获批→降级」。
> 3. 每个「待填」都必须在附录 A 的核验执行单里有对应动作，否则视为未登记的空缺。

## 0. 结论先行

1. **接口文档需登录开发者账号**（已知线索 L5），本报告因此不含任何未经核对的 method 名、限流数字与字段名。**拿到账号前，写路径按总纲 §8.1 的「导入包 + 人工」先落地**；adapter 只定义接口形状（`PlatformPort` 方法签名 + 幂等键 + 快照字段），参数与枚举等核验后填。
2. **10 月可见变更集中在订单、资质、消息、视频、云存储**（线索 L1–L4）。这类变更会直接击穿「录制回放」型契约测试，因此 §六 的公告订阅 → 变更工单 → adapter 回归 → 灰度 是 M0 交付物，不是 M4 的优化项。
3. **服装类目资质是上架硬门槛**（线索 L2）：成分、安全类别、质检报告、商标/授权链路必须进主数据（总纲 §13.2 的 `fabric_composition`、`platform_attribute_mapping`），并在 L1 规则层做「资质必填」确定性校验，否则 M4 批量驳回，且驳回可恢复率上不去。
4. **部署与网络约束在公开页面不可证实**：是否强制指定机房、是否 IP 白名单、回调是否要求备案域名与公网 HTTPS、access_token 是否与出口 IP 绑定——全部进入 `docs/03` 的逐接口核验表。未核实前默认按「公网直连 + IP 白名单 + 固定出口 IP」设计，中心不预置 edge-proxy。
5. **考核口径必须以平台原文为准**：回复时效类指标（如「3 分钟人工回复率」一类的口径）直接决定 §五 的采集点；口径抄错会导致 M5 客服台「提醒秒级、但仍被判超时」。本报告只固定采集口径与计算公式，阈值留待回填。

> 本节只记录**拼多多侧**的约束信号与判定；逐接口填表在 `docs/03`。此处不重复表格，避免两处口径不一致。

| # | 约束项 | 平台规则（待核验） | 判定影响 | 核验方式 |
|---|---|---|---|---|
| 1 | 是否强制指定机房 / 云内网 | 待填：是否存在仅限特定云厂商内网调用的接口（如素材、视频、云存储类） | 命中 → 必须 `edge-proxy`，否则该接口进未自动化清单 | 在文档页搜索「内网 / 指定 / 域名 / 机房」关键词；逐个接口看调用域名 |

| 3 | IP 白名单 | 待填：是否强制、粒度、变更审核时长 | 中心出口 IP 必须固定（NAT/EIP）；否则需 edge 固定出口 | 后台白名单页面截图 + 变更日志 |

| 5 | 敏感数据出口 | 待填：收件人信息是否需要单独申请、是否脱敏返回 | 影响订单详情可读字段与合规 | 订单详情文档字段表 |
| 6 | 时间与时区 | 待填：时间戳字段时区、签名是否含时间戳与允许偏差 | 影响签名与防重放 | 文档签名章节；`curl -sI` 比对平台 Date 头与本机时间 |

**核验命令（bash / WSL / Git Bash）**

```bash
# 1) 记录出口 IP（用于白名单登记，需固定）
curl -s https://ifconfig.me; echo
curl -s https://api.ipify.org; echo

# 2) 探测调用域名可达性与 TLS 证书链（替换 <api-host>）
curl -sS -o /dev/null -w 'code=%{http_code} dns=%{time_namelookup} tls=%{time_appconnect} total=%{time_total}\n' \
  https://<api-host>/
openssl s_client -connect <api-host>:443 -servername <api-host> -showcerts </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates

# 3) 记录平台时间与本机偏差（签名时间窗与防重放依赖它）
curl -sI https://<api-host>/ | grep -i '^date'
date -u

# 4) 路径可达性（判断是否内网限定：公网应超时或被拒）
curl -sS -m 5 -o /dev/null -w '%{http_code}\n' https://<api-host>/<doc-path>
```

**判定规则 G6（网络）**：接口在公网可直接建连且无白名单要求 → 中心直连；需白名单 → 中心固定出口 IP；仅内网可达或明确要求指定机房 → 必须 edge-proxy（见 `docs/03` 决策树）；无法满足且不采购云主机 → 进「未自动化接口清单」，走导入包/人工。

### 6.3 变更工单（分级与判定规则）

| 级别 | 判定条件 | 例子 | 处理要求 |
|---|---|---|---|
| P0 | 签名/鉴权变化、必填字段新增、接口下线、错误码语义变化、写操作语义变化 | 线索 L1/L2/L3 类变更 | 24h 内 hotfix，冻结当批发布，必要时 kill switch |
| P1 | 新增可选字段、新增接口、限流调整、沙箱行为变化 | 线索 L4 类新增 | 3 工作日内适配，排入下个发布窗口 |
| P2 | 文档措辞、示例、规则说明澄清，无接口影响 | 公告文案修订 | 记录 + 季度复盘，不改代码 |

工单必填字段：`ticket_id, announcement_id, level, affected_interfaces[], affected_fields[], breaking(yes/no), detected_at, due_at, owner, regression_run_id, release_id, closed_at`。

**判定规则 G9（分级）**：无法判断是否 breaking 时一律按 P0 处理；连续两次误判为 P0 的类别，在下季度评审中下调并记录依据。

### 6.4 adapter 回归

| 项 | 要求 |
|---|---|
| 基线 | 每个在用接口至少 1 条「真实请求/响应」录制（脱敏后入 `tests/contract/fixtures/pdd/`），沙箱可用时每夜回放 |
| 字段级 diff | 响应 JSON 逐字段比对「新增/删除/类型变化/枚举新增」；**新增字段不算失败**（记录并告警），**删除或类型变化算 P0** |
| 必跑用例 | 发布成功、发布被驳回（资质缺失）、改价成功、改价被拒（活动中）、上下架幂等、库存覆盖、订单增量拉取、消息发送去重、视频分片断点续传 |
| 失败处置 | 回归失败 → 工单回到 P0 → 冻结该接口的自动写，转人工/导入包 |
| 产出 | `regression_run_id` 关联到工单；报告含 diff 摘要与通过率 |

### 6.5 灰度发布（判定规则与回滚）

| 档位 | 范围 | 观察窗口 | 进入下一档的判据 | 回滚动作 |
|---|---|---|---|---|
| 0 dry-run | 只调用校验类/只读接口，不产生写 | — | 0 参数错误 | 修参数 |
| 1 金丝雀 | 1 个 SKU / 1 个会话 | ≥ 1 个批次 | 发布成功率 100%、驳回 0、人工介入 0 | kill switch 停该 action |
| 2 小批量 | ≤ 10% 新品 | ≥ 1 天 | 成功率 ≥ 95%、驳回可恢复率 100% | 降回金丝雀 |
| 3 全量 | 全部 | 持续 | 连续 3 天无 P0 | 按 A/B/C 级止损（总纲 §9.3） |

**判定规则 G10（灰度）**：任何一档出现「不可逆误操作」或「未审批写」，立即回滚到上一档并触发复盘；回滚不等于伪回滚——已发生的 C 级操作必须登记并生成补偿工单。
