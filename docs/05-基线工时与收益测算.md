> **三条铁律**
> 1. **不编数字**。本文件不写任何「行业平均」「经验值」。凡是数，必须有采样记录或供应商报价支撑；没测到就写「待填」。
> 2. **单位统一为分钟**（保留 1 位小数），金额统一为人民币元；所有汇总必须能由明细重算（给出 CSV + 脚本）。
> 3. **目标分钟数必须包含审批工时**：系统让人少写字，但增加了审批动作。若只算「写字省下的时间」，净收益会被高估——这是这类项目最常见的自欺。

## 0. 结论先行与口径总则

1. **M0 只需要一张能跑通的采集表 + 一套能复算的公式**，不需要精确的收益结论。收益结论的价值取决于样本量，而样本量要等真实操作被测。
2. **基线分三段**：`当前`（人工全流程）、`目标`（系统 + 人审批）、`差额`（可节省）。三段必须同口径：同一环节、同一起止点、同一剔除规则，否则差额是假的。
3. **收益公式**（总纲要求的形态）：

   ```
   月净收益 = 单 SKU 节省(分钟) × 月上新量(个) + 客服节省(分钟) × 月会话量(次) − 模型与媒体成本(元)
   ```

   其中「节省」是分钟数，必须再乘「每分钟人工成本」才能与成本同单位相减。完整版见 §4。
4. **成本不只有模型和媒体**：还有审批人工、运维、存储、失败重试。测算表把它们列全，避免「看起来省钱、实际更贵」。
5. **每个数字都要接到验收指标**（§六）：`单 SKU 上架人工工时`、`首次响应时长`、`草稿降级率`、`单件媒体成本` 等，否则这份测算只是纸面文章。

### 0.1 口径总则（违反则数据作废）

| 编号 | 规则 |
|---|---|
| C1 | **起止点显式**：每个环节必须写「从什么动作开始，到什么动作结束」，例如「从打开商品编辑页到点击提交成功」。 |
| C2 | **中断剔除**：单次采样中被打断 > 60 秒（接电话、处理别的单）需记录中断时长并在分析时剔除；中断次数 > 3 次的样本作废。 |
| C3 | **不含等待平台审核的时间**：审核是异步外部等待，不计入人工工时，单独统计「审核时长」。 |
| C4 | **含找资料的时间**：找图、找尺码、问供应商都属于真实成本，必须计入（这正是系统要省的）。 |
| C5 | **一人一次一记录**：多人协作的环节拆成多条记录，不合并。 |
| C6 | **异常值**：偏离中位数 > 3 倍 MAD 的样本标记复核，确认是真实长尾则保留并在报告中说明。 |
| C7 | **版本标注**：每个数字必须标注「采样日期 + 采样人 + 样本量」，否则不可引用。 |

## 二、采样方法与样本量

### 2.1 采样方式（按可靠性排序）

| # | 方式 | 可靠性 | 适用环节 | 注意 |
|---|---|---|---|---|
| 1 | 系统/平台日志时间戳差 | 高（客观） | 后台操作、会话首响、审批、媒体任务 | 需确认时区与字段含义 |
| 2 | 录屏 + 秒表回放 | 高 | 填单、文案、素材、定价 | 录屏需本人同意；脱敏后存档 |
| 3 | 现场观察（不打断） | 中 | 客服、询盘 | 观察者效应，样本量要大 |
| 4 | 本人自记（开始/结束打卡） | 中低 | 长流程、跨天环节 | 易漏记，需交叉验证 |
| 5 | 访谈估算 | 低（仅用于排期） | 无法观察的环节 | **不得用于验收阈值** |

**判定规则 W1（来源门禁）**：验收指标的目标值只能由方式 1–3 的数据支撑；方式 4–5 的数据仅可用于初步排期，且需标注「低可信」。

### 2.2 样本量（先估标准差，再定样本量）

单个环节均值的样本量：

```
n = (z² · σ²) / E²        z = 1.96（95% 置信）
```

| 步骤 | 做法 |
|---|---|
| 1 | 先采 10 次（预采样），算标准差 σ（Excel `STDEV.S` 或 `awk`） |
| 2 | 设定允许误差 E（分钟）：核心环节建议 1 分钟，次要环节 2 分钟 |
| 3 | 查下表得 n；总体 < 50 时用有限总体校正 `n' = n / (1 + (n-1)/N)` |

**系数表（z = 1.96，向上取整）**

| σ（分钟） \ E（分钟） | 0.5 | 1 | 2 |
|---|---|---|---|
| 2 | 62 | 16 | 4 |
| 3 | 139 | 35 | 9 |
| 5 | 385 | 97 | 25 |
| 8 | 984 | 246 | 62 |

> 说明：σ 越小、要求越精确，样本量越大。上表是纯公式结果，用于快速查表；实际按预采样得到的 σ 计算。

**判定规则 W2（样本充足）**：报告中的每个「当前分钟数」必须附 `n` 与 `σ`；`n` 小于表中值的结果标注「样本不足，仅供参考」，不得写入验收阈值。

## 三、收益测算公式

### 3.1 主公式（总纲指定形态）

```
月净收益 = 单 SKU 节省 × 月上新量 + 客服节省 × 月会话量 − 模型与媒体成本
```

- 前两项是**分钟**，第三项是**元** → 必须用「每分钟人工成本」把前两项换成元（§3.3）。
- 「单 SKU 节省」与「客服节省」均由 §一 的「当前 − 目标」得出。

### 3.2 展开式（唯一允许的计算口径）

```
单 SKU 节省(分钟)     = Σ_{i ∈ 上架链路} (当前_i − 目标_i)
                        （含 P1–P10 或 Q1–Q4、Q7、Q8；含新增的审批环节 P10）

客服节省(分钟/次)     = 当前单次处理分钟 − 目标单次处理分钟
客服月节省(分钟)      = 客服节省 × 月会话量 × 自动化覆盖比例
                        （覆盖比例 = 系统能介入的会话占比，待填）

月人工节省(元)        = [ 单 SKU 节省 × 月上新量 + 客服月节省 ] × 每分钟人工成本

模型与媒体成本(元)    = Σ token 成本 + Σ 图片成本 + Σ 视频成本 + 存储与带宽
token 成本            = Σ ( 输入 token/1e6 × 输入单价 + 输出 token/1e6 × 输出单价 )
图片成本              = 生成张数 × 单价（按模型分别计）
视频成本              = 生成秒数 × 单价（按模型分别计）

月净收益(元)          = 月人工节省 − 模型与媒体成本 − 运维摊销 − 审批人工成本
                        （审批人工成本若已计入「目标分钟数」则**不得**重复扣减，二选一，写明选择）
```

### 3.3 人工成本换算

```
每分钟人工成本(元/分钟) = 月薪(元) / 21.75(月计薪天数) / 8(小时) / 60(分钟)
```

| 项 | 说明 |
|---|---|
| 月薪口径 | 用**全成本**（含社保公积金、管理摊销），不是到手工资；差额可达 30%+ |
| 21.75 | 法定月计薪天数，用于把月薪换成日薪 |
| 不同角色不同价 | 运营、客服、美工、审批人（主管）分别设定，不要用同一个数 |
| 待填列 | 月薪、角色、来源（HR 口径），见 §5.2 |

### 3.4 盈亏平衡与回本

```
盈亏平衡月上新量  N* = (模型与媒体成本 + 运维摊销) / (单 SKU 节省 × 每分钟人工成本)
盈亏平衡月会话量  M* = (模型与媒体成本 + 运维摊销) / (客服节省 × 覆盖比例 × 每分钟人工成本)
回本周期(月)      T  = 一次性投入 / 月净收益
投资回报率        ROI = 月净收益 / 一次性投入
```

**判定规则 Y1（立项门禁）**：`月净收益 > 0` 且 `回本周期 ≤ 待定上限`（上限由决策人给，待填），否则方案需降本或缩范围；不允许「先做再算」。

### 3.5 敏感度（必须做，防止单点假设决定结论）

| 变量 | 低 | 基准 | 高 | 对月净收益的影响 |
|---|---|---|---|---|
| 月上新量 | 待填 | 待填 | 待填 | 线性正相关 |
| 月会话量 | 待填 | 待填 | 待填 | 线性正相关 |
| 单 SKU 节省 | 待填 | 待填 | 待填 | 线性正相关 |
| 自动化覆盖比例 | 待填 | 待填 | 待填 | 线性正相关 |

### 5.1 数字落到指标的三条判定规则

| 编号 | 规则 |

| V1 | **目标值必须由基线推导**：`目标 = 基线 × (1 − 降幅)`，降幅需评审确认并写明实现机制（§一 备注列）。禁止直接写「行业标杆值」。 |

### 5.3 复算脚本（CSV → 汇总，可直接跑）

```bash
# 1) 每环节：样本量、均值、中位数、P90（awk 版，无需依赖）
awk -F, 'NR>1 && $8>0 {
  n[$2]++; s[$2]+=$8; v[$2]=v[$2]" "$8
}
END {
  for (k in n) {
    m=n[k]; split(v[k],a," ");
    asort(a);
    mean=s[k]/m; med=a[int((m+1)/2)];
    idx=int(m*0.9); if (idx<1) idx=1; if (idx>m) idx=m; p90=a[idx];
    printf "%s n=%d mean=%.1f median=%.1f p90=%.1f\n", k, m, mean, med, p90;
  }
}' docs/evidence/time/time_sample.csv | sort
```

```bash
# 2) 收益测算（参数来自 params.csv，缺值直接报错，不静默当 0）
node -e '
const fs = require("fs");
const p = Object.fromEntries(fs.readFileSync("docs/evidence/time/benefit_params.csv","utf8")
  .trim().split(/\r?\n/).slice(1).map(l => { const [k,v] = l.split(","); return [k, Number(v)]; }));
const need = ["monthly_new_sku","monthly_sessions","minute_cost","sku_saving_min","cs_saving_min","auto_coverage","model_cost","media_cost","ops_cost"];
const miss = need.filter(k => !Number.isFinite(p[k]));
if (miss.length) { console.error("缺参数（禁止默认为 0）:", miss.join(", ")); process.exit(1); }
const labor = p.sku_saving_min * p.monthly_new_sku + p.cs_saving_min * p.monthly_sessions * p.auto_coverage;
const laborYuan = labor * p.minute_cost;
const net = laborYuan - p.model_cost - p.media_cost - p.ops_cost;
console.log({ laborMinutes: labor, laborYuan: +laborYuan.toFixed(0), net: +net.toFixed(0),
  breakevenSku: +((p.model_cost + p.media_cost + p.ops_cost) / (p.sku_saving_min * p.minute_cost || 1)).toFixed(1) });
'
```
